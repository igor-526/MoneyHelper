# categories Specification

## Purpose
Справочник категорий доходов и расходов воркспейса: создание, чтение одной/списка с пагинацией и опциональным
фильтром по типу, полная замена (`PUT`) и физическое удаление. Каждая категория принадлежит одному воркспейсу
(`workspaces`), имеет тип (`income`/`expense`), название, уникальное в пределах пары «воркспейс + тип» (список
категорий НЕ общий для пользователя — отдельный в каждом воркспейсе), и иконку из реестра `icons`; данные
изолированы между воркспейсами (и транзитивно — между пользователями) на уровне каждого SQL-запроса — чужая
категория или чужой/несуществующий воркспейс неотличимы снаружи от несуществующей категории (везде 404, не 403).
Все эндпоинты вложены под путь `/api/workspaces/{workspace_id}/categories...`.
## Requirements
### Requirement: Создание категории
`POST /api/workspaces/{workspace_id}/categories` SHALL создавать категорию в указанном воркспейсе, принадлежащем
текущему аутентифицированному пользователю, с типом (`income` или `expense`), названием и иконкой из реестра
допустимых имён. `workspace_id` MUST принадлежать текущему пользователю. Название категории MUST быть уникальным в
пределах пары «воркспейс + тип» (список категорий не общий для пользователя — отдельный в каждом воркспейсе).
Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с ошибкой аутентификации.

#### Scenario: Успешное создание категории дохода
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/categories` с
  `type = "income"`, корректным `name` и допустимым `icon`
- **THEN** ответ 201 содержит созданную категорию с этим `id`, `type`, `name`, `icon`, `created_at` и `updated_at`

#### Scenario: Успешное создание категории расхода
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/categories` с
  `type = "expense"`, корректным `name` и допустимым `icon`
- **THEN** ответ 201 содержит созданную категорию с `type = "expense"`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/workspaces/{workspace_id}/categories` отправлен с `name`, состоящим только из пробелов или
  пустой строкой
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение неизвестной иконки
- **WHEN** `POST /api/workspaces/{workspace_id}/categories` отправлен с `icon`, отсутствующим в реестре допустимых
  имён иконок
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение невалидного типа
- **WHEN** `POST /api/workspaces/{workspace_id}/categories` отправлен с `type`, отличным от `income` и `expense`
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение дубля названия в пределах того же типа и воркспейса
- **WHEN** в воркспейсе уже есть категория с типом `income` и названием «Зарплата», и пользователь отправляет
  `POST /api/workspaces/{workspace_id}/categories` с тем же `type = "income"` и тем же `name = "Зарплата"`
- **THEN** ответ 409, вторая категория не создаётся

#### Scenario: Одинаковое название допустимо для разных типов
- **WHEN** в воркспейсе уже есть категория с типом `income` и названием «Прочее», и пользователь отправляет
  `POST /api/workspaces/{workspace_id}/categories` с `type = "expense"` и тем же `name = "Прочее"`
- **THEN** ответ 201, обе категории существуют одновременно

#### Scenario: Одинаковое название допустимо в разных воркспейсах
- **WHEN** в одном воркспейсе пользователя уже есть категория с типом `income` и названием «Зарплата», и он
  отправляет `POST /api/workspaces/{other_workspace_id}/categories` с тем же `type = "income"` и тем же
  `name = "Зарплата"` для другого своего воркспейса
- **THEN** ответ 201, категории с одинаковым названием существуют одновременно в разных воркспейсах

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/categories` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, категория не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/categories` отправлен без действительного access-cookie
- **THEN** ответ 401, категория не создаётся

### Requirement: Список категорий пользователя с фильтром по типу
`GET /api/workspaces/{workspace_id}/categories` SHALL возвращать постраничный список категорий, принадлежащих
только указанному воркспейсу текущего аутентифицированного пользователя, отсортированный по `created_at` по
возрастанию, затем по `id` как детерминированному tie-breaker. Опциональный query-параметр `type` SHALL
ограничивать список категориями только указанного типа; при отсутствии параметра список SHALL содержать категории
обоих типов. Параметры пагинации — `limit` (1..100, по умолчанию 20) и `offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только категории указанного воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/categories` для одного
  из своих воркспейсов, при этом у него есть категории в других его воркспейсах
- **THEN** ответ 200 содержит только категории указанного воркспейса, `total` равен числу его категорий

#### Scenario: Список без фильтра содержит категории обоих типов
- **WHEN** в воркспейсе есть категории и типа `income`, и типа `expense`, и пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/categories` без параметра `type`
- **THEN** ответ 200 содержит категории обоих типов

#### Scenario: Фильтр по типу возвращает только категории этого типа
- **WHEN** в воркспейсе есть категории обоих типов, и пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/categories?type=income`
- **THEN** ответ 200 содержит только категории с `type = "income"`, `total` равен числу категорий этого типа в
  воркспейсе

#### Scenario: Порядок списка детерминирован
- **WHEN** в воркспейсе есть несколько категорий
- **THEN** ответ 200 возвращает их отсортированными по `created_at` по возрастанию, а при равном `created_at` — по
  `id` по возрастанию

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/workspaces/{workspace_id}/categories` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/workspaces/{workspace_id}/categories` запрошен с `limit` вне диапазона 1..100 или с
  отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/categories` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Чтение одной категории
`GET /api/workspaces/{workspace_id}/categories/{category_id}` SHALL возвращать категорию по `id`, только если и
категория принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю.

#### Scenario: Успешное чтение своей категории
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/categories/{category_id}` для категории своего воркспейса
- **THEN** ответ 200 содержит `id`, `type`, `name`, `icon`, `created_at`, `updated_at`

#### Scenario: Несуществующая категория
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/categories/{category_id}` с `category_id`, которого
  нет в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление категории
`PUT /api/workspaces/{workspace_id}/categories/{category_id}` SHALL полностью заменять `type`, `name` и `icon`
категории, принадлежащей указанному воркспейсу текущего аутентифицированного пользователя. Частичное обновление
(`PATCH`) не поддерживается. Уникальность `name` в пределах пары «воркспейс + тип» MUST соблюдаться и при
обновлении.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/categories/{category_id}` для категории своего воркспейса с новыми корректными
  `type`, `name` и `icon`
- **THEN** ответ 200 содержит категорию с обновлёнными значениями и обновлённым `updated_at`

#### Scenario: Обновление несуществующей категории
- **WHEN** `PUT /api/workspaces/{workspace_id}/categories/{category_id}` отправлен с `category_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}/categories/{category_id}` отправлен с пустым `name`, неизвестным
  `icon` либо невалидным `type`
- **THEN** ответ 400, изменения не применяются

#### Scenario: Конфликт уникальности при переименовании в занятое имя
- **WHEN** в воркспейсе есть категории A и B одного типа, и пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/categories/{category_id}` для категории A с `name`, совпадающим с текущим
  названием категории B того же типа
- **THEN** ответ 409, категория A не изменяется

### Requirement: Удаление категории
`DELETE /api/workspaces/{workspace_id}/categories/{category_id}` SHALL физически удалять категорию, принадлежащую
указанному воркспейсу текущего аутентифицированного пользователя, если у категории нет связанных операций. Если по
категории есть хотя бы одна операция (`transactions.category_id`), запрос SHALL быть отклонён с ошибкой конфликта,
категория не удаляется.

#### Scenario: Успешное удаление категории без операций
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/categories/{category_id}` для категории своего воркспейса, по которой нет ни
  одной операции
- **THEN** ответ 204, категория удалена; последующий `GET
  /api/workspaces/{workspace_id}/categories/{category_id}` для того же `id` возвращает 404

#### Scenario: Удаление несуществующей категории
- **WHEN** `DELETE /api/workspaces/{workspace_id}/categories/{category_id}` отправлен с `category_id`, которого
  нет в указанном воркспейсе
- **THEN** ответ 404

#### Scenario: Отклонение удаления категории с операциями
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/categories/{category_id}` для категории своего воркспейса, по которой есть хотя
  бы одна операция
- **THEN** ответ 409, категория и её операции не удаляются

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретной категорией или списком категорий, SHALL проверять принадлежность
воркспейса текущему аутентифицированному пользователю и принадлежность категории указанному воркспейсу — на
уровне запроса к данным (`GET`, `PUT`, `DELETE /api/workspaces/{workspace_id}/categories/{category_id}`; не
отдельной проверкой после чтения). Категория из чужого воркспейса или чужой воркспейс в пути MUST быть неотличимы
снаружи от несуществующих: во всех случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужая категория недоступна для чтения
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/categories/{category_id}`, где
  `workspace_id` и `category_id` принадлежат воркспейсу пользователя B
- **THEN** ответ 404, а не 403; данные категории B не раскрываются

#### Scenario: Чужая категория недоступна для обновления
- **WHEN** пользователь A отправляет `PUT /api/workspaces/{workspace_id}/categories/{category_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, категория B не изменяется

#### Scenario: Чужая категория недоступна для удаления
- **WHEN** пользователь A отправляет `DELETE /api/workspaces/{workspace_id}/categories/{category_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, категория B не удаляется

#### Scenario: Список одного воркспейса не содержит категорий другого воркспейса
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/categories` для одного из своих
  воркспейсов, при этом в другом его воркспейсе (или воркспейсе пользователя B) есть категории с названиями,
  совпадающими с названиями категорий запрошенного воркспейса
- **THEN** ответ 200 содержит только категории запрошенного воркспейса; создание одноимённой категории в этом
  воркспейсе не конфликтует с одноимённой категорией другого воркспейса
