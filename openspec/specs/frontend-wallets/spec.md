# frontend-wallets Specification

## Purpose
Экран управления кошельками текущего воркспейса (`/wallets`, пункт навигации между «Главная» и «Настройки»):
список карточками (иконка, название, валюты чипами), создание и редактирование единой формой в `Drawer`/`Modal`
поверх списка, удаление с подтверждением. Переиспользует общие компоненты `frontend-shell` (`CurrencyPicker`,
`IconPicker`, `EmptyState`) и текущий воркспейс из `frontend-workspaces` (`useCurrentWorkspaceId`). Все пути
вложены под `/api/workspaces/{workspace_id}/...` (020); 409 при удалении кошелька с операциями обрабатывается
общим правилом обработки ошибок API без специального кода на экране. Для многовалютного кошелька на экране
`/transactions` также отображается средний курс (021, `WalletRateCard`).

## Requirements
### Requirement: Навигация и маршрут раздела «Кошельки»
`navItems` SHALL содержать пункт «Кошельки» (путь `/wallets`, иконка `"wallet"`) между «Главная» и «Настройки» —
«Настройки» SHALL оставаться последним пунктом нижней панели. Маршрут `/wallets` SHALL быть доступен только
авторизованному пользователю с выбранным текущим воркспейсом (под `RequireAuth`, затем `RequireWorkspace`, тем же
поддеревом маршрутов, что и остальные разделы приложения).

#### Scenario: Пункт навигации виден авторизованному пользователю
- **WHEN** авторизованный пользователь с выбранным воркспейсом открывает приложение
- **THEN** в навигации (нижняя панель на телефоне, верхнее меню на широком экране) отображается пункт «Кошельки»,
  ведущий на `/wallets`

#### Scenario: Переход по прямой ссылке без авторизации
- **WHEN** неавторизованный пользователь переходит на `/wallets`
- **THEN** приложение перенаправляет его на `/login`, страница кошельков не отображается

### Requirement: Список кошельков
Экран `/wallets` SHALL загружать список кошельков текущего воркспейса одним запросом
`GET /api/workspaces/{workspace_id}/wallets` (`workspace_id` — из `useCurrentWorkspaceId()`) с максимально
допустимым `limit` (100), без клиентской постраничной подгрузки. Каждый кошелёк SHALL отображаться карточкой:
иконка, название, валюты кошелька — отдельными чипами с кодом валюты (не строкой через запятую), в порядке,
в котором значения `currency_ids` вернул backend. Карточки SHALL отображаться в порядке, в котором backend вернул
список (без клиентской пересортировки).

#### Scenario: Загрузка списка
- **WHEN** экран `/wallets` только что открыт
- **THEN** отображается индикатор загрузки, пока ответ `GET /api/workspaces/{workspace_id}/wallets` не получен

#### Scenario: Список получен и не пуст
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` вернул страницу с одним или несколькими кошельками
- **THEN** каждый кошелёк отображается карточкой с иконкой, названием и чипами валют, в порядке ответа backend

#### Scenario: Пустой список
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` вернул пустую страницу (в текущем воркспейсе ещё нет
  кошельков)
- **THEN** вместо списка карточек отображается пустое состояние с призывом создать первый кошелёк

#### Scenario: Ошибка загрузки списка
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` завершился ошибкой
- **THEN** пользователь получает уведомление об ошибке (toast) по общему правилу обработки ошибок API

### Requirement: Создание кошелька
Экран `/wallets` SHALL позволять создать кошелёк в текущем воркспейсе через форму (название, иконка, одна или
несколько валют), открывающуюся поверх списка в `Drawer` на телефоне и в `Modal` на широком экране — без перехода
на отдельный маршрут. Форма SHALL требовать непустое название, выбранную иконку и хотя бы одну выбранную валюту.
Успешное создание (`POST /api/workspaces/{workspace_id}/wallets`) SHALL добавить новый кошелёк в список без
перезагрузки страницы.

#### Scenario: Успешное создание
- **WHEN** пользователь заполняет форму создания кошелька корректными данными и отправляет её
- **THEN** запрос `POST /api/workspaces/{workspace_id}/wallets` выполняется, форма закрывается, список кошельков
  обновляется и содержит новый кошелёк, пользователь получает уведомление об успехе

#### Scenario: Ошибка валидации по полю при создании
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/wallets` ошибкой 400 с сообщениями по
  конкретным полям (`name`, `icon`, `currency_ids`)
- **THEN** форма остаётся открытой, соответствующие поля показывают полученные сообщения об ошибке, кошелёк не
  добавляется в список

### Requirement: Редактирование кошелька
Экран `/wallets` SHALL позволять отредактировать существующий кошелёк той же формой, что используется для
создания, предзаполненной текущими значениями выбранного кошелька из уже загруженного списка (без дополнительного
запроса). Успешное редактирование (`PUT /api/workspaces/{workspace_id}/wallets/{id}`) SHALL обновить кошелёк в
списке без перезагрузки страницы.

#### Scenario: Открытие формы редактирования
- **WHEN** пользователь нажимает «Редактировать» на карточке кошелька
- **THEN** открывается та же форма, что и для создания, с полями, предзаполненными текущими названием, иконкой и
  валютами этого кошелька

#### Scenario: Успешное редактирование
- **WHEN** пользователь изменяет данные в форме редактирования и отправляет её
- **THEN** запрос `PUT /api/workspaces/{workspace_id}/wallets/{id}` выполняется, форма закрывается, карточка
  кошелька в списке отображает обновлённые данные, пользователь получает уведомление об успехе

### Requirement: Удаление кошелька
Экран `/wallets` SHALL позволять удалить кошелёк с карточки списка через подтверждение (`Popconfirm`), без
перехода на отдельный маршрут или экран подтверждения. Успешное удаление
(`DELETE /api/workspaces/{workspace_id}/wallets/{id}`) SHALL убрать кошелёк из списка без перезагрузки страницы.
Если backend отклоняет удаление (409, у кошелька есть операции), пользователь SHALL увидеть понятное сообщение из
ответа backend по общему правилу обработки ошибок API, без дополнительной специальной обработки на экране.

#### Scenario: Успешное удаление
- **WHEN** пользователь подтверждает удаление кошелька без связанных операций
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/wallets/{id}` выполняется, кошелёк пропадает из списка,
  пользователь получает уведомление об успехе

#### Scenario: Удаление отклонено из-за существующих операций
- **WHEN** пользователь подтверждает удаление кошелька, у которого есть операции, и backend отвечает 409
- **THEN** кошелёк остаётся в списке, пользователь получает уведомление с сообщением из ответа backend (`detail`),
  объясняющим, что удаление невозможно из-за существующих операций

#### Scenario: Отмена удаления
- **WHEN** пользователь открывает подтверждение удаления и отменяет его
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/wallets/{id}` не выполняется, кошелёк остаётся в списке
  без изменений

### Requirement: Курс многовалютного кошелька
Для кошелька с более чем одной валютой SHALL отображаться карточка среднего курса (`WalletRateCard`) на экране
`/transactions`, рядом с карточкой баланса выбранного кошелька, загруженная запросом
`GET /api/workspaces/{workspace_id}/wallets/{wallet_id}/rates?target_currency_id={id}`, где `target_currency_id` —
id первой по коду валюты кошелька (`wallet.currency_ids[0]`, backend уже отдаёт этот список отсортированным по
коду валюты). Для кошелька с одной валютой карточка SHALL не отображаться и запрос SHALL не выполняться. Валюты
из `unrated_currency_ids` ответа SHALL отображаться отдельной строкой с текстом, что для этой валюты нет данных
для курса, а не пропускаться молча и не приводить к ошибке компонента.

#### Scenario: Курс показывается для многовалютного кошелька
- **WHEN** в фильтре «Кошелёк» на экране `/transactions` выбран кошелёк с более чем одной валютой
- **THEN** выполняется запрос `GET .../wallets/{wallet_id}/rates?target_currency_id={id}` с id первой по коду
  валюты кошелька, рядом с балансом отображается карточка курса

#### Scenario: Курс не показывается для однвалютного кошелька
- **WHEN** в фильтре «Кошелёк» выбран кошелёк ровно с одной валютой
- **THEN** карточка курса не отображается, запрос `GET .../wallets/{wallet_id}/rates` не выполняется

#### Scenario: Валюта без данных для курса
- **WHEN** ответ содержит `unrated_currency_ids`, непустой для одной или нескольких валют кошелька
- **THEN** для каждой такой валюты карточка показывает строку с пояснением об отсутствии данных для курса, а не
  ошибку и не пустое место

#### Scenario: Смена выбранного кошелька обновляет курс
- **WHEN** пользователь переключает фильтр «Кошелёк» на другой многовалютный кошелёк
- **THEN** карточка курса перезапрашивает данные для нового кошелька и его первой по коду валюты
