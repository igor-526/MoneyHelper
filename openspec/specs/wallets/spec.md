# wallets Specification

## Purpose
Реестр кошельков воркспейса: создание, чтение одного/списка с пагинацией, полная замена (`PUT`) и физическое
удаление. Каждый кошелёк принадлежит одному воркспейсу (`workspaces`) и привязан к ровно одной валюте из
глобального справочника (`currencies`) и иконке из реестра `icons`; данные изолированы между воркспейсами (и
транзитивно — между пользователями, поскольку воркспейс принадлежит ровно одному пользователю) на уровне каждого
SQL-запроса — чужой кошелёк или чужой/несуществующий воркспейс неотличимы снаружи от несуществующего кошелька
(везде 404, не 403). Все эндпоинты вложены под путь `/api/workspaces/{workspace_id}/wallets...`.
## Requirements
### Requirement: Создание кошелька
`POST /api/workspaces/{workspace_id}/wallets` SHALL создавать кошелёк в указанном воркспейсе, принадлежащем
текущему аутентифицированному пользователю, с названием, иконкой из реестра допустимых имён и ровно одной валютой
(`currency_id` — идентификатор валюты из глобального справочника; может совпадать с валютой воркспейса).
`workspace_id` MUST принадлежать текущему пользователю. Запрос со списком валют (`currency_ids`) или без
`currency_id` MUST быть отклонён. Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с ошибкой
аутентификации.

#### Scenario: Успешное создание кошелька
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/wallets` для своего
  воркспейса с корректным `name`, допустимым `icon` и существующим `currency_id`
- **THEN** ответ 201 содержит созданный кошелёк с этим `id`, `name`, `icon`, `currency_id`, `created_at` и
  `updated_at`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `name`, состоящим только из пробелов или
  пустой строкой
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной иконки
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `icon`, отсутствующим в реестре допустимых
  имён иконок
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение запроса без валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен без `currency_id`
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение списка валют
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен со списком `currency_ids` (в том числе из
  одного элемента)
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `currency_id`, отсутствующим в справочнике
  валют
- **THEN** ответ 400 с сообщением, указывающим неизвестный `currency_id`, кошелёк не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, кошелёк не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен без действительного access-cookie
- **THEN** ответ 401, кошелёк не создаётся

### Requirement: Список кошельков пользователя
`GET /api/workspaces/{workspace_id}/wallets` SHALL возвращать постраничный список кошельков, принадлежащих только
указанному воркспейсу текущего аутентифицированного пользователя, отсортированный по `created_at` по возрастанию,
затем по `id` как детерминированному tie-breaker. Параметры пагинации — `limit` (1..100, по умолчанию 20) и
`offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только кошельки указанного воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/wallets` для одного из
  своих воркспейсов, при этом у него есть кошельки в других его воркспейсах
- **THEN** ответ 200 содержит только кошельки указанного воркспейса, `total` равен числу его кошельков

#### Scenario: Порядок списка детерминирован
- **WHEN** в воркспейсе есть несколько кошельков
- **THEN** ответ 200 возвращает их отсортированными по `created_at` по возрастанию, а при равном `created_at` — по
  `id` по возрастанию

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` запрошен с `limit` вне диапазона 1..100 или с отрицательным
  `offset`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Чтение одного кошелька
`GET /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL возвращать кошелёк по `id`, только если и кошелёк
принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю. Ответы
чтения кошелька (одного и в списке) SHALL содержать `currency_id`.

#### Scenario: Успешное чтение своего кошелька
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`
  для кошелька своего воркспейса
- **THEN** ответ 200 содержит `id`, `name`, `icon`, `currency_id`, `created_at`, `updated_at`

#### Scenario: Несуществующий кошелёк
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}` с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление кошелька
`PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL полностью заменять `name`, `icon` и `currency_id`.
Изменение валюты кошелька SHALL завершаться 409, если на кошелёк ссылается хотя бы одна транзакция; при отсутствии
транзакций валюта MAY быть изменена. Новая валюта SHALL существовать, а `PATCH` SHALL NOT поддерживаться.

#### Scenario: Кошелёк использован транзакцией
- **WHEN** пользователь меняет валюту кошелька, на который ссылается расход или пополнение
- **THEN** ответ 409 и валюта не меняется

#### Scenario: У кошелька нет операций
- **WHEN** пользователь меняет валюту кошелька без транзакций
- **THEN** изменение разрешено независимо от существовавших до миграции переводов, поскольку они удалены

#### Scenario: Переименование при прежней валюте
- **WHEN** пользователь меняет имя или иконку кошелька с операциями, сохраняя `currency_id`
- **THEN** ответ 200 содержит обновлённый кошелёк

#### Scenario: Обновление несуществующего кошелька
- **WHEN** указан неизвестный `wallet_id`
- **THEN** ответ 404

#### Scenario: Некорректные данные
- **WHEN** имя, иконка или валюта не проходят валидацию
- **THEN** ответ 400, изменения не применяются

### Requirement: Удаление кошелька
`DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL физически удалять кошелёк своего воркспейса без
транзакций. Удаление SHALL завершаться 409, если на кошелёк ссылается хотя бы одна транзакция.

#### Scenario: Удаление кошелька с операцией
- **WHEN** пользователь удаляет кошелёк с расходом или пополнением
- **THEN** ответ 409

#### Scenario: Удаление кошелька без операций
- **WHEN** пользователь удаляет кошелёк без транзакций
- **THEN** ответ 204

#### Scenario: Удаление несуществующего кошелька
- **WHEN** указан неизвестный или чужой `wallet_id`
- **THEN** ответ 404

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретным кошельком или списком кошельков, SHALL проверять принадлежность воркспейса
текущему аутентифицированному пользователю и принадлежность кошелька указанному воркспейсу — на уровне запроса к
данным (`GET`, `PUT`, `DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}`; не отдельной проверкой после
чтения). Кошелёк из чужого воркспейса или чужой воркспейс в пути MUST быть неотличимы снаружи от несуществующих:
во всех случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужой кошелёк недоступен для чтения
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где `workspace_id`
  и `wallet_id` принадлежат воркспейсу пользователя B
- **THEN** ответ 404, а не 403; данные кошелька B не раскрываются

#### Scenario: Чужой кошелёк недоступен для обновления
- **WHEN** пользователь A отправляет `PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где `workspace_id`
  принадлежит пользователю B
- **THEN** ответ 404, кошелёк B не изменяется

#### Scenario: Чужой кошелёк недоступен для удаления
- **WHEN** пользователь A отправляет `DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, кошелёк B не удаляется

#### Scenario: Кошелёк недоступен через чужой воркспейс даже с верным wallet_id
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`, подставив `id`
  своего собственного `wallet_id`, но `workspace_id` воркспейса, принадлежащего пользователю B
- **THEN** ответ 404 (кошелёк с таким `wallet_id` не принадлежит указанному воркспейсу)

### Requirement: Средний курс кошелька
`GET /api/workspaces/{workspace_id}/wallets/{wallet_id}/rates` SHALL возвращать средний курс «валюта воркспейса за
единицу валюты кошелька» для кошелька, принадлежащего указанному воркспейсу текущего аутентифицированного
пользователя. Эндпоинт SHALL NOT принимать параметров. Ответ SHALL содержать `workspace_currency_id`,
`wallet_currency_id` и `rate`. `rate` SHALL быть простым средним арифметическим значений `W_leg.amount /
C_leg.amount` по всем пополнениям именно этого кошелька (операции с категорией `income`), у которых есть ноги и в
валюте воркспейса, и в валюте кошелька, за всю историю кошелька. Если валюты воркспейса и кошелька совпадают, `rate`
SHALL быть `1`. Если пополнений с обеими ногами нет, `rate` SHALL быть `null` (ответ 200). Пополнения других
кошельков и других воркспейсов в расчёте участвовать MUST NOT. Запрос без действительной сессии SHALL быть отклонён
с ошибкой аутентификации.

#### Scenario: Курс по пополнениям кошелька
- **WHEN** пользователь запрашивает `GET .../wallets/{wallet_id}/rates` для кошелька в валюте `C` воркспейса с
  валютой `W`, у которого есть пополнения с ногами (100 `W`, 10 `C`) и (300 `W`, 20 `C`)
- **THEN** ответ 200: `workspace_currency_id` = `W`, `wallet_currency_id` = `C`, `rate` = среднее `10` и `15`
  = `12.5`

#### Scenario: Курс не смешивается между кошельками
- **WHEN** в воркспейсе два кошелька в одной валюте, пополнения есть только у второго
- **THEN** для первого кошелька `rate` равен `null`

#### Scenario: Валюты совпадают
- **WHEN** валюта кошелька совпадает с валютой воркспейса
- **THEN** ответ 200 с `rate` = `1`

#### Scenario: Нет пополнений с двумя ногами
- **WHEN** у кошелька в валюте, отличной от валюты воркспейса, нет пополнений
- **THEN** ответ 200 с `rate` = `null`

#### Scenario: Несуществующий или чужой кошелёк
- **WHEN** `wallet_id` не существует в указанном воркспейсе, либо воркспейс не принадлежит текущему пользователю
- **THEN** ответ 404, а не 403 — тот же принцип изоляции, что и у остальных эндпоинтов кошелька

#### Scenario: Отказ без аутентификации
- **WHEN** `GET .../wallets/{wallet_id}/rates` отправлен без действительного access-cookie
- **THEN** ответ 401
