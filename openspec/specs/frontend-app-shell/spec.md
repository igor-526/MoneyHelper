# frontend-app-shell Specification

## Purpose
Каркас frontend: структура app/features/shared, Ant Design и порядок провайдеров, роутинг, обёртка Icon, конфигурация окружения.
## Requirements
### Requirement: Структура проекта
Frontend SHALL находиться в `frontend/` и состоять из Vite + React + TypeScript (строгий режим) и библиотеки Ant Design (antd 6); компоненты интерфейса MUST строиться на antd, собственные обёртки лежат в `shared/ui`. Код SHALL быть разложен по `src/app` (роутинг, провайдеры), `src/features/<feature>` (компоненты, hooks, api фичи) и `src/shared` (api-клиент, ui-kit, утилиты, обёртка над Lucide). Приложение MUST быть полностью CSR.

#### Scenario: Сборка
- **WHEN** выполняется `npm run build` в `frontend/`
- **THEN** сборка завершается успешно и создаёт статические файлы без серверного рендеринга

### Requirement: Композиция провайдеров
Корневой компонент приложения SHALL подключать провайдеры в фиксированном порядке: error boundary, `ThemeProvider` (режим темы, см. `dark-theme`), antd `ConfigProvider` (русская локаль `ru_RU`, алгоритм светлой или тёмной темы, размеры под телефон) с компонентом `App`, `ToastProvider`, провайдер `ApiClient`, провайдер серверного состояния (TanStack Query) с глобальным обработчиком ошибок, роутер. Error boundary MUST не зависеть от antd и остальных провайдеров, чтобы экран ошибки работал при их сбое. Реализация `ApiClient` MUST подставляться только на этом уровне.

#### Scenario: Подмена клиента
- **WHEN** тест рендерит приложение с фейковым `ApiClient`
- **THEN** все запросы приложения идут через фейк

### Requirement: Обёртка Icon над Lucide
`shared` SHALL предоставлять компонент `Icon`, принимающий имя иконки Lucide в том виде, в каком оно хранится в БД (kebab-case, например `credit-card`). Для неизвестного имени `Icon` MUST отображать запасную иконку и не бросать исключение.

#### Scenario: Известная иконка
- **WHEN** рендерится `<Icon name="wallet" />`
- **THEN** отображается иконка Lucide `Wallet`

#### Scenario: Неизвестная иконка
- **WHEN** рендерится `<Icon name="no-such-icon" />`
- **THEN** отображается запасная иконка, ошибки нет

### Requirement: Конфигурация окружения
Адрес backend SHALL задаваться переменной `VITE_API_URL`; в репозитории MUST лежать `frontend/.env.example` с переменной и значением для локальной разработки. Dev-сервер SHALL слушать порт 5173, совпадающий с `CORS_ORIGINS` backend.

#### Scenario: Локальный запуск
- **WHEN** запущены backend и `npm run dev`
- **THEN** страница по адресу `http://localhost:5173` выполняет запросы к API без CORS-ошибок

### Requirement: Корневой маршрут и навигация
Приложение SHALL иметь защищённые маршруты `/wallets`, `/categories`, `/transactions`, `/analytics` и `/settings`;
корневой маршрут `/` SHALL перенаправлять с заменой записи истории на `/transactions`. Навигация SHALL содержать
ровно пункты «Операции», «Кошельки», «Аналитика» и «Настройки» в этом порядке и MUST NOT содержать пункта «Главная».
Приложение MUST NOT показывать статус доступности backend и MUST NOT обращаться к `GET /health`. Неизвестный маршрут,
включая удалённый `/transfers`, SHALL показывать страницу «Страница не найдена».

#### Scenario: Корневой маршрут ведёт на «Операции»
- **WHEN** авторизованный пользователь с выбранным воркспейсом открывает `/`
- **THEN** он оказывается на `/transactions`, отображается раздел «Операции»

#### Scenario: Нет пункта «Главная»
- **WHEN** отображается навигация приложения
- **THEN** в ней четыре пункта «Операции», «Кошельки», «Аналитика», «Настройки», пункта «Главная» нет

#### Scenario: Нет статуса backend
- **WHEN** пользователь открывает любой раздел приложения
- **THEN** статус backend не отображается и запрос `GET /health` не выполняется

#### Scenario: Неизвестный маршрут
- **WHEN** пользователь открывает несуществующий путь
- **THEN** показывается страница «Страница не найдена»

#### Scenario: Старый маршрут переводов
- **WHEN** авторизованный пользователь открывает `/transfers`
- **THEN** приложение показывает стандартную страницу 404 и не выполняет запросов переводов
