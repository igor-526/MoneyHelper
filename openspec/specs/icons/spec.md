# icons Specification

## Purpose
Закрытый курируемый реестр допустимых имён иконок Lucide (kebab-case), единственный источник правды для backend и
frontend: список хранится в `backend/src/core/icons.json`, известен на этапе сборки и не является записью в БД.
Первый потребитель — переиспользуемый тип `IconName` для будущих схем кошельков и категорий (задачи 008, 009);
справочник доступен для чтения через `GET /api/icons` без авторизации.

## Requirements
### Requirement: Реестр допустимых имён иконок
Система SHALL определять единый реестр допустимых имён иконок Lucide в kebab-case как статический список строк,
известный на этапе сборки backend (не таблица БД, не запись, создаваемая через API). Реестр MUST быть единственным
источником правды: любая проверка имени иконки на входе API SHALL сверяться с этим списком, и никакой другой список
допустимых имён не может существовать параллельно в backend.

#### Scenario: Имя из реестра считается допустимым
- **WHEN** проверяется имя иконки, присутствующее в реестре (например `wallet`)
- **THEN** проверка проходит без ошибки

#### Scenario: Имя вне реестра считается недопустимым
- **WHEN** проверяется имя иконки, отсутствующее в реестре (например `no-such-icon` или иконка Lucide, не включённая
  в курируемый набор)
- **THEN** проверка завершается ошибкой валидации

### Requirement: Переиспользуемый тип для валидации имени иконки
Система SHALL предоставлять переиспользуемый Pydantic-тип (аннотацию), проверяющий строковое значение на членство в
реестре допустимых имён иконок, пригодный для использования в любой будущей pydantic-схеме, где поле хранит имя
иконки (в частности, в будущих схемах кошельков и категорий).

#### Scenario: Схема с полем-иконкой принимает известное имя
- **WHEN** pydantic-модель с полем этого типа валидируется со значением из реестра допустимых имён
- **THEN** валидация проходит, и поле содержит переданное значение без изменений

#### Scenario: Схема с полем-иконкой отклоняет неизвестное имя
- **WHEN** pydantic-модель с полем этого типа валидируется со значением, отсутствующим в реестре
- **THEN** валидация завершается ошибкой (`ValidationError`), и модель не создаётся

### Requirement: Чтение списка допустимых иконок
`GET /api/icons` SHALL возвращать отсортированный список всех имён иконок из реестра в формате плоского JSON-массива
строк, без пагинации (`Page`/`PageParams` не применяются — реестр маленький и статический). Эндпоинт SHALL быть
доступен без авторизации: реестр иконок не является данными конкретного пользователя.

#### Scenario: Список иконок по умолчанию
- **WHEN** клиент запрашивает `GET /api/icons`
- **THEN** ответ 200 содержит JSON-массив всех имён иконок реестра, отсортированный по алфавиту

#### Scenario: Доступ без авторизации
- **WHEN** клиент без сессии (без cookies аутентификации) запрашивает `GET /api/icons`
- **THEN** ответ 200 содержит список иконок, запрос не отклоняется как неавторизованный
