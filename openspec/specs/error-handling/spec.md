# error-handling Specification

## Purpose
Обязательная обработка любой ошибки каждого действия на frontend: toast по умолчанию, переопределение сообщения, ошибки по полям форм, error boundary.
## Requirements
### Requirement: Каждая ошибка действия обрабатывается
Любой запрос и любая мутация к API SHALL завершаться видимым для пользователя результатом при ошибке. Ошибки 400, 401, 403, 404, 409, 500, сетевой сбой и таймаут MUST NOT пропадать молча, а действие MUST NOT оставаться в состоянии «загрузка».

#### Scenario: Ошибка мутации
- **WHEN** мутация завершается любым `ApiError`
- **THEN** показывается toast, а состояние мутации становится «ошибка» (не «загрузка»)

#### Scenario: Ошибка запроса данных
- **WHEN** запрос данных завершается любым `ApiError`
- **THEN** показывается toast, а состояние запроса становится «ошибка»

### Requirement: Сообщения по умолчанию
Глобальный обработчик SHALL выбирать текст toast по `ApiError.kind` на русском языке: 400 без полей — `detail` из ответа; 401 — «Сессия истекла, войдите снова»; 403 — «Недостаточно прав для этого действия»; 404 — «Не найдено» (или `detail`, если он есть); 409 — `detail` из ответа; 5xx — «Ошибка сервера, попробуйте позже»; `network` — «Нет соединения с сервером»; `timeout` — «Сервер не отвечает, попробуйте позже»; `unknown` — «Что-то пошло не так». Если `detail` не является строкой, MUST использоваться сообщение по умолчанию для данного вида.

#### Scenario: 500
- **WHEN** запрос завершается `ApiError` с `kind = "server"`
- **THEN** показывается toast типа «ошибка» с текстом «Ошибка сервера, попробуйте позже»

#### Scenario: Сетевой сбой
- **WHEN** запрос завершается `ApiError` с `kind = "network"`
- **THEN** показывается toast «Нет соединения с сервером»

#### Scenario: 404 и 409 с detail
- **WHEN** запрос завершается 404 или 409 с текстовым `detail`
- **THEN** toast содержит этот `detail`

#### Scenario: 403
- **WHEN** запрос завершается 403
- **THEN** показывается toast «Недостаточно прав для этого действия»

#### Scenario: 401
- **WHEN** запрос завершается 401 после неудачной попытки обновить сессию
- **THEN** показывается toast «Сессия истекла, войдите снова»

### Requirement: Переопределение сообщения действием
Конкретное действие SHALL иметь возможность переопределить текст toast для ошибки (по виду ошибки или общим текстом) либо отключить глобальный toast, если оно само показывает ошибку иначе. При отключении действие MUST обработать ошибку явно.

#### Scenario: Свой текст для 409
- **WHEN** мутация задаёт свой текст для `conflict` и завершается 409
- **THEN** показывается заданный текст, а не `detail` по умолчанию

#### Scenario: Отключение глобального toast
- **WHEN** мутация отключает глобальный toast и завершается ошибкой
- **THEN** глобальный toast не показывается, а ошибка доступна вызывающему коду

### Requirement: Ошибки валидации по полям
Для `ApiError` с `kind = "validation"` и непустыми `fieldErrors` frontend SHALL предоставлять помощник, который привязывает сообщения к полям формы по имени поля. Общий toast «Проверьте заполнение формы» MUST показываться всегда; сообщения полей, которых нет в форме, MUST добавляться в текст этого toast, чтобы не теряться.

#### Scenario: Привязка к полям
- **WHEN** форма получает `fieldErrors = {"email": ["некорректный email"]}`
- **THEN** сообщение отображается у поля `email`, а toast содержит «Проверьте заполнение формы»

#### Scenario: Неизвестное поле
- **WHEN** `fieldErrors` содержит поле, которого нет в форме
- **THEN** его сообщение попадает в toast

### Requirement: Error boundary
Приложение SHALL иметь корневой error boundary. Необработанная ошибка рендеринга MUST показывать экран с сообщением об ошибке и кнопкой «Перезагрузить», а не белую страницу; экран корректно выглядит в светлой и тёмной теме.

#### Scenario: Ошибка рендеринга
- **WHEN** компонент бросает исключение при рендеринге
- **THEN** вместо приложения показывается экран ошибки с кнопкой «Перезагрузить»
