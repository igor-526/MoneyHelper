# frontend-transfers Specification

## Purpose
Раздел переводов между собственными кошельками текущего воркспейса (`/transfers`, без отдельного пункта нижней
панели — точка входа только со страницы «Операции»): список с фильтрами (кошелёк, диапазон дат) и реальной
серверной пагинацией, единая форма создания/редактирования с валютой, ограниченной пересечением наборов валют
исходного и целевого кошельков, удаление с подтверждением. Мутации переводов инвалидируют кэш баланса обоих
затронутых кошельков. Переиспользует общие компоненты `frontend-shell`, архитектуру `frontend-wallets`/
`frontend-categories`/`frontend-transactions` и текущий воркспейс из `frontend-workspaces`
(`useCurrentWorkspaceId`). Все пути вложены под `/api/workspaces/{workspace_id}/...` (020).

## Requirements
### Requirement: Маршрут раздела переводов без пункта навигации
Маршрут `/transfers` SHALL быть доступен только авторизованному пользователю с выбранным текущим воркспейсом (под
`RequireAuth`, затем `RequireWorkspace`, тем же поддеревом маршрутов, что и остальные разделы приложения). Раздел
`navItems` SHALL не содержать отдельного пункта, ведущего на `/transfers` — точка входа в раздел переводов
предоставляется только со страницы «Операции» (ссылка «Переводы» и пункт «Перевод» меню «Добавить»).

#### Scenario: Переход по прямой ссылке без авторизации
- **WHEN** неавторизованный пользователь переходит на `/transfers`
- **THEN** приложение перенаправляет его на `/login`, экран переводов не отображается

#### Scenario: Отдельный пункт навигации для переводов отсутствует
- **WHEN** авторизованный пользователь просматривает навигацию приложения (нижнюю панель на телефоне, верхнее
  меню на широком экране)
- **THEN** среди пунктов навигации нет отдельного пункта, ведущего на `/transfers`

### Requirement: Список переводов с фильтрами
Экран `/transfers` SHALL загружать список переводов текущего воркспейса запросом
`GET /api/workspaces/{workspace_id}/transfers` с фильтрами: кошелёк (query-параметр `wallet_id`), диапазон дат
(`date_from`/`date_to`). Над списком SHALL отображаться элементы управления фильтрами: выбор кошелька (со
значением «Все кошельки»), выбор диапазона дат. Каждый перевод SHALL отображаться карточкой: название исходного и
целевого кошелька («откуда → куда»), сумма с кодом валюты, дата перевода. Карточки SHALL отображаться в порядке,
в котором backend вернул список (без клиентской пересортировки).

#### Scenario: Загрузка списка
- **WHEN** экран `/transfers` только что открыт
- **THEN** отображается индикатор загрузки, пока ответ `GET /api/workspaces/{workspace_id}/transfers` не получен

#### Scenario: Список получен и не пуст
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` вернул страницу с одним или несколькими переводами
- **THEN** каждый перевод отображается карточкой с названием исходного и целевого кошелька, суммой с кодом
  валюты и датой, в порядке ответа backend

#### Scenario: Пустой список
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` вернул пустую страницу (в текущем воркспейсе ещё нет
  переводов, соответствующих текущим фильтрам)
- **THEN** вместо списка карточек отображается пустое состояние с призывом создать перевод, элементы управления
  фильтрами остаются видимыми и доступными

#### Scenario: Фильтр по кошельку сужает список
- **WHEN** пользователь выбирает конкретный кошелёк в фильтре «Кошелёк»
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transfers` с query-параметром `wallet_id`,
  равным id выбранного кошелька, список обновляется, отображая только переводы этого кошелька

#### Scenario: Фильтр по диапазону дат сужает список
- **WHEN** пользователь выбирает диапазон дат в фильтре дат
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transfers` с `date_from`, равным началу первого
  выбранного дня, и `date_to`, равным концу последнего выбранного дня, список обновляется, отображая только
  переводы внутри диапазона

#### Scenario: Комбинация фильтров
- **WHEN** пользователь одновременно задаёт фильтр по кошельку и диапазону дат
- **THEN** запрос `GET /api/workspaces/{workspace_id}/transfers` выполняется с обоими query-параметрами
  одновременно, список отображает только переводы, удовлетворяющие всем условиям сразу

#### Scenario: Ошибка загрузки списка
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` завершился ошибкой
- **THEN** пользователь получает уведомление об ошибке (toast) по общему правилу обработки ошибок API

### Requirement: Пагинация списка переводов
Экран `/transfers` SHALL использовать реальную серверную пагинацию с фиксированным размером страницы 20.
Переключение страницы SHALL выполнять новый запрос `GET /api/workspaces/{workspace_id}/transfers` с
соответствующим `offset`. Изменение любого фильтра (кошелёк, диапазон дат) SHALL сбрасывать текущую страницу на
первую.

#### Scenario: Переключение страницы
- **WHEN** список переводов содержит больше одной страницы и пользователь переключается на следующую страницу
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transfers` с `offset`, равным размеру страницы,
  отображается соответствующий набор переводов

#### Scenario: Смена фильтра сбрасывает пагинацию
- **WHEN** пользователь находится не на первой странице списка и меняет любой фильтр
- **THEN** список возвращается к первой странице (`offset: 0`), запрос выполняется с обновлённым фильтром и
  сброшенным смещением

### Requirement: Создание перевода
Экран `/transfers` SHALL позволять создать перевод между двумя кошельками текущего воркспейса через форму,
открывающуюся поверх списка в `Drawer` на телефоне и в `Modal` на широком экране — без перехода на отдельный
маршрут. Форма SHALL содержать выбор исходного кошелька, выбор целевого кошелька (исключающий из своих опций
текущий выбранный исходный кошелёк), выбор валюты, ограниченный пересечением наборов валют исходного и целевого
кошельков, сумму и необязательную дату перевода. Если оба кошелька выбраны, а пересечение их наборов валют пусто,
вместо поля выбора валюты SHALL отображаться предупреждающий текст «У этих кошельков нет общей валюты». Успешное
создание (`POST /api/workspaces/{workspace_id}/transfers`) SHALL добавить новый перевод в список без перезагрузки
страницы.

#### Scenario: Целевой кошелёк исключает исходный из списка
- **WHEN** пользователь выбрал исходный кошелёк в форме создания перевода и открывает выбор целевого кошелька
- **THEN** в списке для выбора недоступен кошелёк, совпадающий с выбранным исходным

#### Scenario: Смена исходного кошелька, совпадающего с целевым, сбрасывает целевой
- **WHEN** пользователь выбрал целевой кошелёк, затем меняет исходный кошелёк на тот же кошелёк, что уже выбран
  как целевой
- **THEN** поле целевого кошелька сбрасывается

#### Scenario: Валюта ограничена пересечением валют двух кошельков
- **WHEN** пользователь выбрал исходный и целевой кошелёк в форме создания перевода, и у них есть хотя бы одна
  общая валюта
- **THEN** в списке доступных для выбора валют показаны только валюты, входящие в набор валют обоих кошельков

#### Scenario: Отсутствие общей валюты между кошельками
- **WHEN** пользователь выбрал исходный и целевой кошелёк, у которых нет ни одной общей валюты
- **THEN** вместо поля выбора валюты отображается предупреждающий текст «У этих кошельков нет общей валюты»,
  форма не может быть отправлена без выбранной валюты

#### Scenario: Смена любого из кошельков сбрасывает выбранную валюту
- **WHEN** пользователь выбрал валюту, затем меняет исходный или целевой кошелёк
- **THEN** поле валюты сбрасывается, пользователю нужно выбрать валюту заново из нового пересечения

#### Scenario: Успешное создание перевода
- **WHEN** пользователь выбирает исходный и целевой кошелёк с общей валютой, выбирает эту валюту, указывает
  положительную сумму и отправляет форму
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transfers` выполняется с данными формы, форма закрывается,
  список переводов обновляется и содержит новый перевод, пользователь получает уведомление об успехе

#### Scenario: Ошибка валидации по полю при создании
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transfers` ошибкой 400 с сообщениями по
  конкретным полям (`from_wallet_id`, `to_wallet_id`, `currency_id`, `amount`, `occurred_at`)
- **THEN** форма остаётся открытой, соответствующие поля показывают полученные сообщения об ошибке, перевод не
  добавляется в список

#### Scenario: Текстовая ошибка бизнес-правила при создании
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transfers` ошибкой 400 с текстовым описанием
  бизнес-правила (например, совпадение исходного и целевого кошелька или отсутствие общей валюты)
- **THEN** форма остаётся открытой, пользователь получает уведомление с этим текстом ошибки, перевод не
  добавляется в список

### Requirement: Редактирование перевода
Экран `/transfers` SHALL позволять отредактировать существующий перевод той же формой, что используется для
создания, предзаполненной текущими значениями выбранного перевода. Успешное редактирование
(`PUT /api/workspaces/{workspace_id}/transfers/{id}`) SHALL обновить перевод в списке без перезагрузки страницы.

#### Scenario: Открытие формы редактирования
- **WHEN** пользователь нажимает «Редактировать» на карточке перевода
- **THEN** открывается та же форма, что и для создания, с полями исходного и целевого кошелька, валюты, суммы и
  даты, предзаполненными текущими значениями этого перевода

#### Scenario: Успешное редактирование
- **WHEN** пользователь изменяет данные в форме редактирования перевода и отправляет её
- **THEN** запрос `PUT /api/workspaces/{workspace_id}/transfers/{id}` выполняется, форма закрывается, карточка
  перевода в списке отображает обновлённые данные, пользователь получает уведомление об успехе

### Requirement: Удаление перевода
Экран `/transfers` SHALL позволять удалить перевод с карточки списка через подтверждение (`Popconfirm`), без
перехода на отдельный маршрут или экран подтверждения. Успешное удаление
(`DELETE /api/workspaces/{workspace_id}/transfers/{id}`) SHALL убрать перевод из списка без перезагрузки страницы.
Успешное создание, редактирование и удаление перевода SHALL инициировать обновление кэша балансов обоих
затронутых кошельков (исходного и целевого).

#### Scenario: Успешное удаление
- **WHEN** пользователь подтверждает удаление перевода
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/transfers/{id}` выполняется, перевод пропадает из
  списка, пользователь получает уведомление об успехе

#### Scenario: Отмена удаления
- **WHEN** пользователь открывает подтверждение удаления и отменяет его
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/transfers/{id}` не выполняется, перевод остаётся в
  списке без изменений

#### Scenario: Мутация перевода обновляет кэш балансов затронутых кошельков
- **WHEN** пользователь успешно создаёт, редактирует или удаляет перевод между двумя своими кошельками
- **THEN** кэш баланса обоих кошельков (исходного и целевого) в текущем воркспейсе инвалидируется; если карточка
  баланса одного из этих кошельков отображается на другом экране приложения (экран «Операции»), она показывает
  актуальные суммы без перезагрузки страницы
