# transactions Specification

## Purpose
Доходы и расходы пользователя по кошелькам: создание, чтение одной/списка с фильтрами (кошелёк, категория, тип,
диапазон дат) и пагинацией, полная замена (`PUT`) и физическое удаление операции, баланс по кошельку и валюте на
лету. Каждая операция принадлежит одному пользователю, ссылается на его кошелёк и категорию (тип операции —
`income`/`expense` — определяется типом категории, отдельного поля нет) и на одну валюту из набора валют кошелька;
данные изолированы между пользователями на уровне каждого SQL-запроса — чужая операция или чужой кошелёк
неотличимы снаружи от несуществующих (везде 404, не 403). Удаление кошелька/категории с операциями отклоняется
(409) — см. `wallets`/`categories`.

## Requirements
### Requirement: Создание операции
`POST /api/transactions` SHALL создавать операцию (доход или расход), принадлежащую текущему аутентифицированному
пользователю, с указанием кошелька, категории, валюты и положительной суммы. Кошелёк и категория MUST принадлежать
текущему пользователю. Валюта операции MUST входить в набор валют указанного кошелька. Число знаков после запятой
суммы MUST NOT превышать `decimal_places` валюты; округление не выполняется. `occurred_at` — опциональное поле;
при отсутствии SHALL использоваться текущее время сервера. Запрос без действительной сессии (без access-cookie)
SHALL быть отклонён с ошибкой аутентификации.

#### Scenario: Успешное создание операции с указанной датой
- **WHEN** аутентифицированный пользователь отправляет `POST /api/transactions` с корректными `wallet_id`
  (своего кошелька), `category_id` (своей категории), `currency_id` из набора валют кошелька, положительным
  `amount` с числом знаков не более `decimal_places` валюты и явным `occurred_at`
- **THEN** ответ 201 содержит созданную операцию с этим `id`, `wallet_id`, `category_id`, `currency_id`, `amount`,
  `occurred_at` (равным переданному), `created_at` и `updated_at`

#### Scenario: Успешное создание операции без даты — используется текущее время
- **WHEN** `POST /api/transactions` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит операцию с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Отклонение валюты, не входящей в набор валют кошелька
- **WHEN** `POST /api/transactions` отправлен с `currency_id`, отсутствующим в `currency_ids` указанного кошелька
- **THEN** ответ 400 с понятным сообщением, операция не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты
- **WHEN** `POST /api/transactions` отправлен с `amount`, число знаков после запятой которого превышает
  `decimal_places` валюты `currency_id`
- **THEN** ответ 400, операция не создаётся, сумма не округляется

#### Scenario: Отклонение неположительной суммы
- **WHEN** `POST /api/transactions` отправлен с `amount`, равным нулю или отрицательным
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого кошелька
- **WHEN** `POST /api/transactions` отправлен с `wallet_id`, которого нет ни у одного пользователя, либо
  принадлежащим другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующей или чужой категории
- **WHEN** `POST /api/transactions` отправлен с `category_id`, которой нет ни у одного пользователя, либо
  принадлежащей другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/transactions` отправлен без действительного access-cookie
- **THEN** ответ 401, операция не создаётся

### Requirement: Список операций пользователя с фильтрами и сортировкой
`GET /api/transactions` SHALL возвращать постраничный список операций, принадлежащих только текущему
аутентифицированному пользователю, отсортированный по `occurred_at` по убыванию, затем по `id` по убыванию как
детерминированному tie-breaker (новые операции первыми). Опциональные query-параметры `wallet_id`, `category_id`,
`type` (`income`/`expense`, через тип связанной категории), `date_from` и `date_to` (включительно, диапазон по
`occurred_at`) SHALL сужать список. Если заданы оба `date_from` и `date_to`, и `date_from` позже `date_to`, запрос
SHALL быть отклонён. Параметры пагинации — `limit` (1..100, по умолчанию 20) и `offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только операции текущего пользователя
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/transactions`, при этом в системе есть операции,
  принадлежащие другим пользователям
- **THEN** ответ 200 содержит только операции текущего пользователя, `total` равен числу его операций

#### Scenario: Порядок списка — новые операции первыми
- **WHEN** у пользователя есть несколько операций с разными `occurred_at`
- **THEN** ответ 200 возвращает их отсортированными по `occurred_at` по убыванию, а при равном `occurred_at` — по
  `id` по убыванию

#### Scenario: Фильтр по кошельку
- **WHEN** пользователь запрашивает `GET /api/transactions?wallet_id=...` для одного из своих кошельков
- **THEN** ответ 200 содержит только операции этого кошелька

#### Scenario: Фильтр по категории
- **WHEN** пользователь запрашивает `GET /api/transactions?category_id=...` для одной из своих категорий
- **THEN** ответ 200 содержит только операции этой категории

#### Scenario: Фильтр по типу операции
- **WHEN** пользователь запрашивает `GET /api/transactions?type=income` (или `type=expense`)
- **THEN** ответ 200 содержит только операции, чья категория имеет соответствующий `type`

#### Scenario: Фильтр по диапазону дат
- **WHEN** пользователь запрашивает `GET /api/transactions?date_from=...&date_to=...`
- **THEN** ответ 200 содержит только операции с `occurred_at` в указанном диапазоне включительно

#### Scenario: Некорректный диапазон дат отклоняется
- **WHEN** `GET /api/transactions?date_from=...&date_to=...` запрошен с `date_from`, позже `date_to`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/transactions` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/transactions` запрошен с `limit` вне диапазона 1..100 или с отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

### Requirement: Чтение одной операции
`GET /api/transactions/{transaction_id}` SHALL возвращать операцию по `id`, только если она принадлежит текущему
аутентифицированному пользователю.

#### Scenario: Успешное чтение своей операции
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/transactions/{transaction_id}` для своей
  операции
- **THEN** ответ 200 содержит `id`, `wallet_id`, `category_id`, `currency_id`, `amount`, `occurred_at`,
  `created_at`, `updated_at`

#### Scenario: Несуществующая операция
- **WHEN** запрашивается `GET /api/transactions/{transaction_id}` с `transaction_id`, которого нет ни у одного
  пользователя
- **THEN** ответ 404

### Requirement: Полное обновление операции
`PUT /api/transactions/{transaction_id}` SHALL полностью заменять `wallet_id`, `category_id`, `currency_id`,
`amount` и `occurred_at` операции, принадлежащей текущему аутентифицированному пользователю, с той же валидацией,
что и при создании. Частичное обновление (`PATCH`) не поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT /api/transactions/{transaction_id}` для своей операции
  с новыми корректными `wallet_id`, `category_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит операцию с обновлёнными значениями и обновлённым `updated_at`

#### Scenario: Обновление несуществующей операции
- **WHEN** `PUT /api/transactions/{transaction_id}` отправлен с `transaction_id`, которого нет ни у одного
  пользователя
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/transactions/{transaction_id}` отправлен с валютой, не входящей в набор валют кошелька,
  неположительной суммой, суммой с превышением знаков валюты, либо несуществующим/чужим `wallet_id` или
  `category_id`
- **THEN** ответ 400 или 404 (в зависимости от причины), изменения не применяются

### Requirement: Удаление операции
`DELETE /api/transactions/{transaction_id}` SHALL физически удалять операцию, принадлежащую текущему
аутентифицированному пользователю, вместе со связанной строкой `transaction_legs` (каскадно).

#### Scenario: Успешное удаление
- **WHEN** аутентифицированный пользователь отправляет `DELETE /api/transactions/{transaction_id}` для своей
  операции
- **THEN** ответ 204, операция и её нога удалены; последующий `GET /api/transactions/{transaction_id}` для того же
  `id` возвращает 404

#### Scenario: Удаление несуществующей операции
- **WHEN** `DELETE /api/transactions/{transaction_id}` отправлен с `transaction_id`, которого нет ни у одного
  пользователя
- **THEN** ответ 404

### Requirement: Баланс по кошельку и валюте
`GET /api/wallets/{wallet_id}/balances` SHALL возвращать баланс кошелька, принадлежащего текущему
аутентифицированному пользователю, по каждой валюте из набора валют кошелька (включая валюты без единой операции —
с балансом 0), отсортированный по коду валюты. Баланс по валюте вычисляется на лету как сумма `amount` операций с
категорией типа `income` минус сумма `amount` операций с категорией типа `expense`, отфильтрованных по этому
кошельку и валюте.

#### Scenario: Баланс кошелька без операций — нули по всем его валютам
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/wallets/{wallet_id}/balances` для своего
  кошелька, у которого ещё нет ни одной операции
- **THEN** ответ 200 содержит запись с `balance = 0` для каждой валюты из `currency_ids` этого кошелька

#### Scenario: Баланс учитывает доходы и расходы
- **WHEN** у кошелька есть операции дохода на сумму X и операции расхода на сумму Y в одной и той же валюте
- **THEN** ответ 200 содержит баланс, равный X минус Y, для этой валюты

#### Scenario: Баланс отдельен по валютам многовалютного кошелька
- **WHEN** у кошелька с несколькими валютами есть операции в разных валютах
- **THEN** ответ 200 содержит отдельную запись `{currency_id, balance}` для каждой валюты кошелька, не смешивая
  суммы разных валют

#### Scenario: Несуществующий или чужой кошелёк
- **WHEN** запрашивается `GET /api/wallets/{wallet_id}/balances` с `wallet_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий операцией или балансом кошелька, SHALL проверять принадлежность данных текущему
аутентифицированному пользователю на уровне запроса к данным (`GET`, `PUT`, `DELETE
/api/transactions/{transaction_id}`, `GET /api/wallets/{wallet_id}/balances`; не отдельной проверкой после
чтения). Операция или кошелёк, принадлежащие другому пользователю, MUST быть неотличимы снаружи от несуществующих:
в обоих случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужая операция недоступна для чтения
- **WHEN** пользователь A запрашивает `GET /api/transactions/{transaction_id}` с `transaction_id` операции,
  принадлежащей пользователю B
- **THEN** ответ 404, а не 403; данные операции B не раскрываются

#### Scenario: Чужая операция недоступна для обновления
- **WHEN** пользователь A отправляет `PUT /api/transactions/{transaction_id}` с `transaction_id` операции,
  принадлежащей пользователю B
- **THEN** ответ 404, операция B не изменяется

#### Scenario: Чужая операция недоступна для удаления
- **WHEN** пользователь A отправляет `DELETE /api/transactions/{transaction_id}` с `transaction_id` операции,
  принадлежащей пользователю B
- **THEN** ответ 404, операция B не удаляется

#### Scenario: Список одного пользователя не содержит операций другого
- **WHEN** пользователь A запрашивает `GET /api/transactions`, при этом у пользователя B есть операции по его
  собственным кошелькам и категориям
- **THEN** ответ 200 содержит только операции пользователя A

#### Scenario: Баланс чужого кошелька недоступен
- **WHEN** пользователь A запрашивает `GET /api/wallets/{wallet_id}/balances` с `wallet_id` кошелька,
  принадлежащего пользователю B
- **THEN** ответ 404, баланс кошелька B не раскрывается
