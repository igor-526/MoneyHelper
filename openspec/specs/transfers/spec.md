# transfers Specification

## Purpose
Перевод денежных средств между двумя разными кошельками одного воркспейса в одной валюте, без конвертации:
создание, чтение одной/списка с фильтром по кошельку (совпадение с `from_wallet_id` или `to_wallet_id`) и
пагинацией, полная замена (`PUT`) и физическое удаление. Допустим только если выбранная валюта входит в набор
валют обоих кошельков. Данные изолированы между воркспейсами (и транзитивно — между пользователями) на уровне
каждого SQL-запроса — чужой перевод или чужой/несуществующий воркспейс неотличимы снаружи от несуществующего
перевода (везде 404, не 403). Перевод учитывается в балансе обоих кошельков (см. `transactions`) и блокирует
удаление задействованных кошельков, пока перевод существует (см. `wallets`). Все эндпоинты вложены под путь
`/api/workspaces/{workspace_id}/transfers...`.

## Requirements
### Requirement: Создание перевода
`POST /api/workspaces/{workspace_id}/transfers` SHALL создавать перевод денежных средств между двумя разными
кошельками указанного воркспейса, принадлежащего текущему аутентифицированному пользователю, в одной валюте, без
конвертации. `workspace_id` MUST принадлежать текущему пользователю. `from_wallet_id` и `to_wallet_id` MUST
принадлежать указанному воркспейсу и MUST NOT совпадать. `currency_id` MUST входить в набор валют одновременно
`from_wallet_id` И `to_wallet_id`. Сумма MUST быть положительной, число знаков после запятой MUST NOT превышать
`decimal_places` валюты; округление не выполняется. `occurred_at` — опциональное поле; при отсутствии SHALL
использоваться текущее время сервера. Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с
ошибкой аутентификации.

#### Scenario: Успешное создание перевода
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/transfers` с
  корректными `from_wallet_id` и `to_wallet_id` (оба — кошельки этого воркспейса, разные), `currency_id`, входящим
  в набор валют обоих кошельков, положительным `amount` с числом знаков не более `decimal_places` валюты и явным
  `occurred_at`
- **THEN** ответ 201 содержит созданный перевод с этим `id`, `from_wallet_id`, `to_wallet_id`, `currency_id`,
  `amount`, `occurred_at` (равным переданному), `created_at` и `updated_at`

#### Scenario: Успешное создание перевода без даты — используется текущее время
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит перевод с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Отклонение перевода без общей валюты у кошельков
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `currency_id`, отсутствующим в наборе валют
  `from_wallet_id` или отсутствующим в наборе валют `to_wallet_id` (включая случай, когда у кошельков вовсе нет
  общей валюты)
- **THEN** ответ 400 с понятным сообщением, перевод не создаётся

#### Scenario: Отклонение перевода самому себе
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с одинаковыми `from_wallet_id` и
  `to_wallet_id`
- **THEN** ответ 400 с ошибкой валидации, перевод не создаётся

#### Scenario: Отклонение несуществующего или чужого исходного кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `from_wallet_id`, которого нет в указанном
  воркспейсе
- **THEN** ответ 404, перевод не создаётся

#### Scenario: Отклонение несуществующего или чужого целевого кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `to_wallet_id`, которого нет в указанном
  воркспейсе
- **THEN** ответ 404, перевод не создаётся

#### Scenario: Отклонение неположительной суммы
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `amount`, равным нулю или отрицательным
- **THEN** ответ 400 с ошибкой валидации, перевод не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `amount`, число знаков после запятой
  которого превышает `decimal_places` валюты `currency_id`
- **THEN** ответ 400, перевод не создаётся, сумма не округляется

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, перевод не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/transfers` отправлен без действительного access-cookie
- **THEN** ответ 401, перевод не создаётся

### Requirement: Список переводов пользователя с фильтром по кошельку и пагинацией
`GET /api/workspaces/{workspace_id}/transfers` SHALL возвращать постраничный список переводов, принадлежащих
только указанному воркспейсу текущего аутентифицированного пользователя, отсортированный по `occurred_at` по
убыванию, затем по `id` по убыванию как детерминированному tie-breaker (новые переводы первыми). Опциональный
query-параметр `wallet_id` SHALL сужать список до переводов, у которых `wallet_id` совпадает с `from_wallet_id`
ИЛИ с `to_wallet_id`. Опциональные `date_from` и `date_to` (включительно, диапазон по `occurred_at`) SHALL
дополнительно сужать список; если заданы оба и `date_from` позже `date_to`, запрос SHALL быть отклонён. Параметры
пагинации — `limit` (1..100, по умолчанию 20) и `offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только переводы указанного воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/transfers` для одного
  из своих воркспейсов, при этом у него есть переводы в других его воркспейсах
- **THEN** ответ 200 содержит только переводы указанного воркспейса, `total` равен числу его переводов

#### Scenario: Порядок списка — новые переводы первыми
- **WHEN** в воркспейсе есть несколько переводов с разными `occurred_at`
- **THEN** ответ 200 возвращает их отсортированными по `occurred_at` по убыванию, а при равном `occurred_at` — по
  `id` по убыванию

#### Scenario: Фильтр по кошельку учитывает и исходный, и целевой кошелёк
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/transfers?wallet_id=...` для одного из
  кошельков этого воркспейса
- **THEN** ответ 200 содержит переводы, у которых указанный кошелёк является либо `from_wallet_id`, либо
  `to_wallet_id`

#### Scenario: Фильтр по диапазону дат
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/transfers?date_from=...&date_to=...`
- **THEN** ответ 200 содержит только переводы с `occurred_at` в указанном диапазоне включительно

#### Scenario: Некорректный диапазон дат отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers?date_from=...&date_to=...` запрошен с `date_from`, позже
  `date_to`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` запрошен с `limit` вне диапазона 1..100 или с
  отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/transfers` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Чтение одного перевода
`GET /api/workspaces/{workspace_id}/transfers/{transfer_id}` SHALL возвращать перевод по `id`, только если и
перевод принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю.

#### Scenario: Успешное чтение своего перевода
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transfers/{transfer_id}` для перевода своего воркспейса
- **THEN** ответ 200 содержит `id`, `from_wallet_id`, `to_wallet_id`, `currency_id`, `amount`, `occurred_at`,
  `created_at`, `updated_at`

#### Scenario: Несуществующий перевод
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/transfers/{transfer_id}` с `transfer_id`, которого
  нет в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление перевода
`PUT /api/workspaces/{workspace_id}/transfers/{transfer_id}` SHALL полностью заменять `from_wallet_id`,
`to_wallet_id`, `currency_id`, `amount` и `occurred_at` перевода, принадлежащего указанному воркспейсу текущего
аутентифицированного пользователя, с той же валидацией, что и при создании. Частичное обновление (`PATCH`) не
поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transfers/{transfer_id}` для перевода своего воркспейса с новыми корректными
  `from_wallet_id`, `to_wallet_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит перевод с обновлёнными значениями и обновлённым `updated_at`

#### Scenario: Обновление несуществующего перевода
- **WHEN** `PUT /api/workspaces/{workspace_id}/transfers/{transfer_id}` отправлен с `transfer_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}/transfers/{transfer_id}` отправлен с одинаковыми
  `from_wallet_id`/`to_wallet_id`, валютой, не входящей в набор валют одного из кошельков, неположительной суммой,
  суммой с превышением знаков валюты, либо несуществующим/чужим `from_wallet_id` или `to_wallet_id`
- **THEN** ответ 400 или 404 (в зависимости от причины), изменения не применяются

### Requirement: Удаление перевода
`DELETE /api/workspaces/{workspace_id}/transfers/{transfer_id}` SHALL физически удалять перевод, принадлежащий
указанному воркспейсу текущего аутентифицированного пользователя.

#### Scenario: Успешное удаление
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/transfers/{transfer_id}` для перевода своего воркспейса
- **THEN** ответ 204, перевод удалён; последующий `GET /api/workspaces/{workspace_id}/transfers/{transfer_id}` для
  того же `id` возвращает 404

#### Scenario: Удаление несуществующего перевода
- **WHEN** `DELETE /api/workspaces/{workspace_id}/transfers/{transfer_id}` отправлен с `transfer_id`, которого нет
  в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретным переводом или списком переводов, SHALL проверять принадлежность воркспейса
текущему аутентифицированному пользователю и принадлежность перевода указанному воркспейсу — на уровне запроса к
данным (`GET`, `PUT`, `DELETE /api/workspaces/{workspace_id}/transfers/{transfer_id}`; не отдельной проверкой
после чтения). Перевод из чужого воркспейса или чужой воркспейс в пути MUST быть неотличимы снаружи от
несуществующих: во всех случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужой перевод недоступен для чтения
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/transfers/{transfer_id}`, где
  `workspace_id` и `transfer_id` принадлежат воркспейсу пользователя B
- **THEN** ответ 404, а не 403; данные перевода B не раскрываются

#### Scenario: Чужой перевод недоступен для обновления
- **WHEN** пользователь A отправляет `PUT /api/workspaces/{workspace_id}/transfers/{transfer_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, перевод B не изменяется

#### Scenario: Чужой перевод недоступен для удаления
- **WHEN** пользователь A отправляет `DELETE /api/workspaces/{workspace_id}/transfers/{transfer_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, перевод B не удаляется

#### Scenario: Список одного воркспейса не содержит переводов другого
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/transfers` для одного из своих
  воркспейсов, при этом в другом его воркспейсе (или воркспейсе пользователя B) есть переводы по своим кошелькам
- **THEN** ответ 200 содержит только переводы запрошенного воркспейса
