## Why

Backend-капабилити `transfers` (011) уже реализована и заархивирована: `Transaction` стала ногозависимой
(`legs: list[TransactionLeg]`), появился эндпоинт пополнения `POST /api/transactions/topups` (несколько ног —
ровно по одной сумме на каждую валюту кошелька) и полноценная сущность `Transfer` с CRUD `/api/transfers*`. Но
пользователь до сих пор не может ни пополнить многовалютный кошелёк во всех его валютах сразу, ни перевести
деньги между своими кошельками через интерфейс — экран «Операции» (016) создаёт только одноногие
доходы/расходы, а раздел переводов не существует вовсе. Дизайн `frontend-transactions` (016) явно предсказывает
эту задачу («задел на 017»): `Transaction.legs` уже массив, а `TransactionCard` намеренно работает только с
`legs[0]`. Это последняя из пяти frontend-задач роадмапа перед аналитикой (018), поэтому она должна закрыть
данный задел и завести полноценный раздел переводов сейчас.

## What Changes

- `TransactionsPage` (016): кнопка «Создать операцию» становится выпадающим меню (antd `Dropdown`) с тремя
  пунктами — «Доход/расход» (существующий `TransactionForm`, без изменений), «Пополнение» (новый `TopupForm`),
  «Перевод» (навигация на `/transfers`); рядом с заголовком «Операции» появляется ссылка «Переводы» на
  `/transfers`.
- `features/transactions/TopupForm.tsx` и `features/transactions/useCreateTopup.ts` — новая форма пополнения
  многовалютного кошелька: кошелёк → динамический набор полей сумм (по одному на каждую валюту кошелька) →
  категория (только доходные) → дата; отправляет `POST /api/transactions/topups`.
- `TransactionCard` (016) — отображает ВСЕ ноги операции (не только `legs[0]`): список строк «сумма код» при
  `legs.length > 1`; кнопка «Редактировать» блокируется для многоногих операций (backend может заменить их только
  ровно одной ногой через `PUT`, что молча схлопнуло бы пополнение), кнопка «Удалить» остаётся доступной всегда.
- Новая капабилити `frontend-transfers` — отдельная фича `features/transfers/`: тип `Transfer`, hooks
  `useTransfers` (список с реальной серверной пагинацией и фильтрами кошелёк/диапазон дат),
  `useCreateTransfer`/`useUpdateTransfer`/`useDeleteTransfer`, `TransferForm` (исходный и целевой кошелёк, валюта —
  пересечение наборов валют обоих кошельков через `CurrencyPicker.allowedIds`, сумма, дата), `TransferCard`,
  `TransfersPage`.
- Маршрут `/transfers` в `app/routes.tsx` под `RequireAuth`. Пункт `navItems` не добавляется — бюджет нижней
  панели (5 пунктов) занят решением 013/016 и зарезервирован под «Аналитику» (018); точка входа — только со
  страницы «Операции».
- Тесты hooks и компонентов (`FakeApiClient`, по образцу существующих тестов `features/wallets`/
  `features/categories`/`features/transactions`).

Backend, база данных и миграции Alembic **не затрагиваются**: используется уже готовый и заархивированный API
`transactions`/`topups`/`transfers` (010, 011) без изменений контракта.

## Capabilities

### New Capabilities
- `frontend-transfers`: раздел переводов между собственными кошельками пользователя — маршрут `/transfers` без
  отдельного пункта навигации, список переводов с фильтрами (кошелёк, диапазон дат) и серверной пагинацией,
  создание и редактирование через единую форму с валютой, ограниченной пересечением наборов валют исходного и
  целевого кошельков, удаление с подтверждением.

### Modified Capabilities
- `frontend-transactions`: экран «Операции» получает выпадающее меню создания из трёх пунктов (доход/расход,
  пополнение, переход к переводам) вместо одной кнопки; форма пополнения многовалютного кошелька (`TopupForm`);
  карточка операции отображает все ноги, а не только первую, и блокирует редактирование многоногих операций.

## Impact

- Новые файлы: `frontend/src/features/transfers/` (тип, hooks, `TransferForm`, `TransferCard`, `TransfersPage` и
  тесты рядом с кодом), `frontend/src/features/transactions/TopupForm.tsx` и
  `frontend/src/features/transactions/useCreateTopup.ts` (плюс тесты).
- Изменяются существующие файлы: `frontend/src/features/transactions/TransactionCard.tsx` (многоногое
  отображение, блокировка редактирования), `frontend/src/features/transactions/TransactionsPage.tsx`
  (выпадающее меню создания, ссылка «Переводы»), `frontend/src/app/routes.tsx` (новый маршрут `/transfers`).
  `frontend/src/app/navItems.ts` не меняется.
- Backend, база данных, миграции Alembic — **не затрагиваются вовсе**. Используются уже существующие эндпоинты
  `POST /api/transactions/topups` (`TopupCreate`/`TransactionOut`) и `/api/transfers*`
  (`TransferCreate`/`TransferUpdate`/`TransferOut`/`TransferListParams`).
- Новых npm-зависимостей не требуется: используются уже установленные `antd` (`Dropdown`, `Select`, `DatePicker`,
  `Pagination`, `Card`, `Drawer`, `Modal`, `Popconfirm`, `Form`, `Tooltip`), `dayjs`, `@tanstack/react-query`,
  уже готовые `CurrencyPicker`/`MoneyInput`/`EmptyState` из `shared/ui` (013, `CurrencyPicker.allowedIds` из 016
  используется как есть, без дальнейшего расширения).

## Non-goals

- Конвертация валют внутри перевода — backend её не поддерживает, перевод всегда в одной валюте без изменения
  суммы.
- Редактирование пополнения на месте — backend не даёт менять число ног через `PUT` (только полная замена ровно
  одной ногой, что превратило бы многовалютное пополнение в одноногую операцию); форма редактирования
  пополнения не делается, доступны только просмотр (в списке) и удаление.
- Отдельный пункт нижней/верхней навигации для переводов — бюджет `navItems` исчерпан решением 013 и
  зарезервирован под «Аналитику» (018); точка входа — только ссылка со страницы «Операции».
- Подсказка/предпросмотр implied-курса между валютами пополнения по мере ввода сумм — не требуется постановкой
  задачи.
