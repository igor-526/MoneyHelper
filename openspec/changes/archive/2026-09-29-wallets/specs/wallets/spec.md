## ADDED Requirements

### Requirement: Создание кошелька
`POST /api/wallets` SHALL создавать кошелёк, принадлежащий текущему аутентифицированному пользователю, с
названием, иконкой из реестра допустимых имён и набором из одной или нескольких валют из глобального справочника
валют. Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с ошибкой аутентификации.

#### Scenario: Успешное создание кошелька с одной валютой
- **WHEN** аутентифицированный пользователь отправляет `POST /api/wallets` с корректным `name`, допустимым `icon`
  и `currency_ids` из одного существующего `currency_id`
- **THEN** ответ 201 содержит созданный кошелёк с этим `id`, `name`, `icon`, `currency_ids` из одного элемента,
  `created_at` и `updated_at`

#### Scenario: Успешное создание кошелька с несколькими валютами
- **WHEN** аутентифицированный пользователь отправляет `POST /api/wallets` с `currency_ids`, содержащим несколько
  различных существующих `currency_id`
- **THEN** ответ 201 содержит кошелёк со всеми переданными валютами в `currency_ids`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/wallets` отправлен с `name`, состоящим только из пробелов или пустой строкой
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной иконки
- **WHEN** `POST /api/wallets` отправлен с `icon`, отсутствующим в реестре допустимых имён иконок
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение пустого набора валют
- **WHEN** `POST /api/wallets` отправлен с пустым списком `currency_ids`
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение дублей в наборе валют
- **WHEN** `POST /api/wallets` отправлен с `currency_ids`, содержащим один и тот же `currency_id` более одного раза
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной валюты
- **WHEN** `POST /api/wallets` отправлен с `currency_ids`, содержащим `currency_id`, отсутствующий в справочнике
  валют
- **THEN** ответ 400 с сообщением, перечисляющим неизвестные `currency_id`, кошелёк не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/wallets` отправлен без действительного access-cookie
- **THEN** ответ 401, кошелёк не создаётся

### Requirement: Список кошельков пользователя
`GET /api/wallets` SHALL возвращать постраничный список кошельков, принадлежащих только текущему
аутентифицированному пользователю, отсортированный по `created_at` по возрастанию, затем по `id` как
детерминированному tie-breaker. Параметры пагинации — `limit` (1..100, по умолчанию 20) и `offset` (≥ 0, по
умолчанию 0).

#### Scenario: Список содержит только кошельки текущего пользователя
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/wallets`, при этом в системе есть кошельки,
  принадлежащие другим пользователям
- **THEN** ответ 200 содержит только кошельки текущего пользователя, `total` равен числу его кошельков

#### Scenario: Порядок списка детерминирован
- **WHEN** у пользователя есть несколько кошельков
- **THEN** ответ 200 возвращает их отсортированными по `created_at` по возрастанию, а при равном `created_at` — по
  `id` по возрастанию

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/wallets` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/wallets` запрошен с `limit` вне диапазона 1..100 или с отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

### Requirement: Чтение одного кошелька
`GET /api/wallets/{wallet_id}` SHALL возвращать кошелёк по `id`, только если он принадлежит текущему
аутентифицированному пользователю.

#### Scenario: Успешное чтение своего кошелька
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/wallets/{wallet_id}` для своего кошелька
- **THEN** ответ 200 содержит `id`, `name`, `icon`, `currency_ids`, `created_at`, `updated_at`

#### Scenario: Валюты кошелька отсортированы по коду
- **WHEN** запрашивается кошелёк с несколькими валютами
- **THEN** `currency_ids` в ответе упорядочены по коду соответствующей валюты

#### Scenario: Несуществующий кошелёк
- **WHEN** запрашивается `GET /api/wallets/{wallet_id}` с `wallet_id`, которого нет ни у одного пользователя
- **THEN** ответ 404

### Requirement: Полное обновление кошелька
`PUT /api/wallets/{wallet_id}` SHALL полностью заменять `name`, `icon` и `currency_ids` кошелька, принадлежащего
текущему аутентифицированному пользователю. Частичное обновление (`PATCH`) не поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT /api/wallets/{wallet_id}` для своего кошелька с новыми
  корректными `name`, `icon` и `currency_ids`
- **THEN** ответ 200 содержит кошелёк с обновлёнными значениями и обновлённым `updated_at`; предыдущий набор валют
  кошелька полностью заменяется новым

#### Scenario: Обновление несуществующего кошелька
- **WHEN** `PUT /api/wallets/{wallet_id}` отправлен с `wallet_id`, которого нет ни у одного пользователя
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/wallets/{wallet_id}` отправлен с пустым `name`, неизвестным `icon`, пустым или содержащим
  дубли `currency_ids`, либо с неизвестным `currency_id`
- **THEN** ответ 400, изменения не применяются

### Requirement: Удаление кошелька
`DELETE /api/wallets/{wallet_id}` SHALL физически удалять кошелёк, принадлежащий текущему аутентифицированному
пользователю, вместе со всеми его записями о валютах, безусловно (без проверки связанных данных — операции вне
рамок этого требования).

#### Scenario: Успешное удаление
- **WHEN** аутентифицированный пользователь отправляет `DELETE /api/wallets/{wallet_id}` для своего кошелька
- **THEN** ответ 204, кошелёк и его записи о валютах удалены; последующий `GET /api/wallets/{wallet_id}` для того
  же `id` возвращает 404

#### Scenario: Удаление несуществующего кошелька
- **WHEN** `DELETE /api/wallets/{wallet_id}` отправлен с `wallet_id`, которого нет ни у одного пользователя
- **THEN** ответ 404

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретным кошельком (`GET`, `PUT`, `DELETE /api/wallets/{wallet_id}`), SHALL
проверять принадлежность кошелька текущему аутентифицированному пользователю на уровне запроса к данным (не
отдельной проверкой после чтения). Кошелёк, принадлежащий другому пользователю, MUST быть неотличим снаружи от
несуществующего: в обоих случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужой кошелёк недоступен для чтения
- **WHEN** пользователь A запрашивает `GET /api/wallets/{wallet_id}` с `wallet_id` кошелька, принадлежащего
  пользователю B
- **THEN** ответ 404, а не 403; данные кошелька B не раскрываются

#### Scenario: Чужой кошелёк недоступен для обновления
- **WHEN** пользователь A отправляет `PUT /api/wallets/{wallet_id}` с `wallet_id` кошелька, принадлежащего
  пользователю B
- **THEN** ответ 404, кошелёк B не изменяется

#### Scenario: Чужой кошелёк недоступен для удаления
- **WHEN** пользователь A отправляет `DELETE /api/wallets/{wallet_id}` с `wallet_id` кошелька, принадлежащего
  пользователю B
- **THEN** ответ 404, кошелёк B не удаляется
