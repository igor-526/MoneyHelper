## Why

Backend-капабилити `analytics` (012) уже реализована и заархивирована: единственный read-эндпоинт
`GET /api/analytics` считает доходы и расходы пользователя в выбранной валюте отображения по среднему курсу
диапазона, группируя их по одному из трёх срезов (кошелёк/категория/валюта), и явно перечисляет валюты, для
которых курс не найден (`unconverted_currencies`), вместо того чтобы занижать суммы молча. Но у пользователя до
сих пор нет способа увидеть эти данные — на frontend нет ни экрана, ни пункта навигации для аналитики. Это
последняя содержательная frontend-задача дорожной карты (018, этап F2f) перед чисто верификационной 019
(проверка PWA): без неё вся цепочка «кошельки → категории → операции → пополнения/переводы» не даёт пользователю
итогового представления о его финансах, ради которого приложение и заводилось.

## What Changes

- Новый пункт `navItems` «Аналитика» (путь `/analytics`, иконка `"trending-up"`, уже существующая в
  `BUSINESS_ICONS`) между «Операции» и «Настройки» — пятый и последний пункт нижней панели, бюджет которой
  зарезервирован решением 013. Маршрут `/analytics` под `RequireAuth`.
- Новая фича `features/analytics/`: тип `AnalyticsResult`/`AnalyticsBucket` (без camelCase-маппинга, как
  `Wallet`/`Category`/`Transaction`/`Transfer`), hook `useAnalytics(filters: AnalyticsFilters | null)`, гейтящий
  запрос `GET /api/analytics` через `enabled: filters !== null` — в отличие от всех предыдущих списков
  (кошельки/категории/операции/переводы), где фильтры опциональны, здесь backend требует одновременно валюту
  отображения, диапазон дат и срез, поэтому запрос выполняется только когда все три заполнены, без отдельной
  кнопки «Применить».
- `AnalyticsPage`: обязательные элементы управления — валюта отображения (`CurrencyPicker`, одиночный режим, без
  сентинела «все» — целевая валюта пересчёта, а не фильтр), диапазон дат (`antd RangePicker`), срез
  (`Segmented`: «Кошелёк»/«Категория»/«Валюта», без выбора по умолчанию); опциональные сужающие фильтры —
  кошелёк, категория, тип, валюта операции (обычные `Select` с сентинелом «Все …», по образцу
  `TransactionsPage`). Пока не заполнены все обязательные поля — информационный `Alert` вместо списка корзин.
- Отображение результата — карточки по корзинам (без пагинации, backend не разбивает `buckets` на страницы):
  подпись корзины, резолвленная по активному срезу через реестр резолверов (три `Map` из
  `useWallets()`/`useCategories(undefined)`/`useCurrencies()`), доход и расход (оба всегда показаны, `0` при
  отсутствии), сортировка по резолвленной подписи в алфавитном порядке (не по сумме — суммы остаются строками).
- Предупреждающий `Alert`, если `unconverted_currencies` не пуст — коды валют без найденного курса.
- Тесты hooks и компонентов (`FakeApiClient`), по mobile-first правилам `AGENTS.md`.

Backend, база данных и миграции Alembic **не затрагиваются**: используется уже готовый и заархивированный
эндпоинт `GET /api/analytics` (012) без изменений контракта.

## Capabilities

### New Capabilities
- `frontend-analytics`: раздел аналитики доходов и расходов (`/analytics`, пятый и последний пункт навигации) —
  обязательные валюта отображения/диапазон дат/срез, гейтинг запроса без кнопки отправки, опциональные сужающие
  фильтры, карточки корзин с доходом и расходом, предупреждение о валютах без курса, обработка стандартных
  ошибок API через глобальный toast.

### Modified Capabilities
Нет — существующие капабилити (`frontend-shell`, `frontend-wallets`, `frontend-categories`,
`frontend-transactions`, `frontend-transfers`) не меняют своих требований; эта задача только использует их
готовые компоненты и hooks (`CurrencyPicker`, `useWallets`, `useCategories`, `useCurrencies`) без изменения их
контрактов.

## Impact

- Новые файлы: `frontend/src/features/analytics/` (тип `AnalyticsResult`/`AnalyticsBucket`/`AnalyticsFilters`,
  `useAnalytics.ts`, `AnalyticsPage.tsx`, и тесты рядом с кодом).
- Изменяются существующие файлы: `frontend/src/app/navItems.ts` (новый пункт «Аналитика»),
  `frontend/src/app/routes.tsx` (новый маршрут `/analytics`).
- Backend, база данных, миграции Alembic — **не затрагиваются вовсе**. Используется уже существующий
  `GET /api/analytics` (`AnalyticsQueryParams`/`AnalyticsOut`) без изменений контракта.
- Новых npm-зависимостей не требуется: используются уже установленные `antd` (`Alert`, `Segmented`,
  `DatePicker.RangePicker`, `Select`, `Card`, `Spin`, `Typography`), `@tanstack/react-query`, уже готовые
  `CurrencyPicker`/`EmptyState` из `shared/ui` (013) и hooks `useWallets`/`useCategories`/`useCurrencies` (014,
  015, 013).

## Non-goals

- Графики и экспорт отчёта — backend сам вынес их за рамки капабилити `analytics` (012) как будущую задачу; эта
  задача продолжает то же ограничение объёма на frontend.
- Переводы (`transfers`) в аналитике не участвуют — backend их не учитывает при агрегации (012), frontend не
  добавляет собственной агрегации сверх ответа backend.
- Пагинация корзин — backend не разбивает `buckets` на страницы (их число ограничено справочниками кошельков/
  категорий/валют пользователя), frontend не вводит клиентскую пагинацию сверх этого.
- Отдельная кнопка «Показать»/«Применить фильтры» — запрос выполняется реактивно, как только заполнены все
  обязательные поля, тот же принцип, что и у остальных экранов со фильтрами в проекте.
