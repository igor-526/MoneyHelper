## MODIFIED Requirements

### Requirement: Создание воркспейса
`POST /api/workspaces` SHALL создавать рабочее пространство (воркспейс), принадлежащее текущему аутентифицированному
пользователю, с названием и основной валютой (`currency_id` — обязательное поле, идентификатор валюты из глобального
справочника). Совместный доступ нескольких пользователей к одному воркспейсу не поддерживается — воркспейс
принадлежит ровно одному пользователю. Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с
ошибкой аутентификации. Воркспейс MUST NOT создаваться без валюты или с валютой, которой нет в справочнике.

#### Scenario: Успешное создание воркспейса
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces` с корректными `name` и существующим
  `currency_id`
- **THEN** ответ 201 содержит созданный воркспейс с этим `id`, `name`, `currency_id`, `created_at` и `updated_at`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/workspaces` отправлен с `name`, состоящим только из пробелов или пустой строкой
- **THEN** ответ 400 с ошибкой валидации, воркспейс не создаётся

#### Scenario: Отклонение запроса без валюты
- **WHEN** `POST /api/workspaces` отправлен без `currency_id`
- **THEN** ответ 400 с ошибкой валидации, воркспейс не создаётся

#### Scenario: Отклонение неизвестной валюты
- **WHEN** `POST /api/workspaces` отправлен с `currency_id`, которого нет в справочнике валют
- **THEN** ответ 400, воркспейс не создаётся

#### Scenario: Названия воркспейсов не обязаны быть уникальными
- **WHEN** у пользователя уже есть воркспейс с названием «Поездка», и он отправляет `POST /api/workspaces` с тем же
  `name = "Поездка"`
- **THEN** ответ 201, оба воркспейса существуют одновременно с разными `id`

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces` отправлен без действительного access-cookie
- **THEN** ответ 401, воркспейс не создаётся

### Requirement: Чтение одного воркспейса
`GET /api/workspaces/{workspace_id}` SHALL возвращать воркспейс по `id`, только если он принадлежит текущему
аутентифицированному пользователю. Ответы чтения воркспейса (одного и в списке) SHALL содержать `currency_id`.

#### Scenario: Успешное чтение своего воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}` для своего воркспейса
- **THEN** ответ 200 содержит `id`, `name`, `currency_id`, `created_at`, `updated_at`

#### Scenario: Несуществующий воркспейс
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}` с `workspace_id`, которого нет ни у одного
  пользователя
- **THEN** ответ 404

### Requirement: Полное обновление воркспейса
`PUT /api/workspaces/{workspace_id}` SHALL заменять `name` воркспейса, принадлежащего текущему аутентифицированному
пользователю, и SHALL принимать необязательное поле `currency_id`. Если `currency_id` не передан или совпадает с
текущим, валюта не меняется (переименование свободно). Смена валюты SHALL быть отклонена с ошибкой 409, если в
воркспейсе есть хотя бы один кошелёк; новая валюта SHALL существовать в справочнике. Частичное обновление (`PATCH`)
не поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT /api/workspaces/{workspace_id}` для своего воркспейса с
  новым корректным `name`
- **THEN** ответ 200 содержит воркспейс с обновлённым `name`, прежним `currency_id` и обновлённым `updated_at`

#### Scenario: Смена валюты воркспейса без кошельков
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с другим существующим `currency_id` для воркспейса, в
  котором нет кошельков
- **THEN** ответ 200, `currency_id` воркспейса обновлён

#### Scenario: Запрет смены валюты при наличии кошельков
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с другим `currency_id` для воркспейса, в котором есть
  кошелёк
- **THEN** ответ 409, ни `name`, ни `currency_id` не изменяются

#### Scenario: Переименование воркспейса с кошельками
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с новым `name` и тем же `currency_id` (или без него) для
  воркспейса, в котором есть кошелёк
- **THEN** ответ 200, `name` обновлён, `currency_id` прежний

#### Scenario: Смена валюты на неизвестную
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с `currency_id`, которого нет в справочнике
- **THEN** ответ 400, изменения не применяются

#### Scenario: Обновление несуществующего воркспейса
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с `workspace_id`, которого нет ни у одного пользователя
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}` отправлен с `name`, состоящим только из пробелов или пустой строкой
- **THEN** ответ 400, изменения не применяются

## ADDED Requirements

### Requirement: Защита валюты справочника от удаления
Внешний ключ `workspaces.currency_id` SHALL иметь поведение `ON DELETE RESTRICT`: валюту справочника, на которую
ссылается воркспейс, MUST NOT быть возможно удалить.

#### Scenario: Удаление используемой валюты запрещено
- **WHEN** выполняется удаление валюты, на которую ссылается хотя бы один воркспейс
- **THEN** БД отклоняет операцию нарушением внешнего ключа

### Requirement: Миграция существующих воркспейсов
Миграция, добавляющая `workspaces.currency_id`, SHALL удалить все кошельки, операции и переводы (с зависимыми
строками) и SHALL присвоить существующим воркспейсам валюту по умолчанию RUB.

#### Scenario: Существующие воркспейсы получают RUB, данные сбрасываются
- **WHEN** миграция применяется к БД с воркспейсами, кошельками, операциями и переводами
- **THEN** воркспейсы сохранены с `currency_id` валюты RUB, а кошельки, операции и переводы отсутствуют
