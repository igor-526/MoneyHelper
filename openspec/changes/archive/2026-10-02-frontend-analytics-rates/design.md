## Context

Контракт аналитики (029): `GET /api/workspaces/{id}/analytics` принимает необязательный `display_currency`
(по умолчанию валюта воркспейса; допустимы валюта воркспейса и валюты кошельков, иначе 400), возвращает
`{display_currency_id, buckets, unconverted_currencies}`. Курс кошелька: `GET .../wallets/{id}/rates` →
`{workspace_currency_id, wallet_currency_id, rate|null}`; для кошелька в валюте воркспейса `rate = 1`.
Экран аналитики сейчас требует валюту отображения без значения по умолчанию.

## Goals / Non-Goals

**Goals:**
- Суммы по умолчанию в валюте воркспейса без лишних действий; выбор только допустимых валют.
- Пользователь понимает, в какой валюте суммы и почему часть операций не учтена.
- Карточка курса понятна во всех состояниях.

**Non-Goals:**
- Изменения API и backend; значения по умолчанию для диапазона дат и среза (остаются обязательными, как в 018).

## Decisions

1. **Значение по умолчанию не хранится в состоянии.** `AnalyticsPageState.displayCurrencyId` остаётся
   `string | undefined`: `undefined` — «валюта воркспейса». `buildAnalyticsFilters` больше не требует его и передаёт
   как есть; `useAnalytics` не добавляет `display_currency` в запрос при `undefined` — умолчание определяет backend
   (единственный источник правды). В выборе отображается `state.displayCurrencyId ?? workspace.currency_id`.
   Альтернатива — подставлять id воркспейса на клиенте: дублирует правило backend и требует дожидаться загрузки
   воркспейса до первого запроса.
2. **Допустимые валюты** — `{валюта воркспейса} ∪ {валюты кошельков}` (чистая функция `allowedDisplayCurrencyIds`,
   тест); передаются в `CurrencyPicker` через уже существующий `allowedIds`. Тот же набор кошельковых валют
   ограничивает фильтр «Валюта операции» (операция всегда в валюте своего кошелька). `CurrencyPicker` получает проп
   `allowClear` (по умолчанию `true`, не ломает остальных потребителей); для валюты отображения он `false`, так как
   «пустого» значения нет.
3. **Сброс невалидного выбора не нужен.** Воркспейс переключается на другом экране («Настройки»), поэтому
   `AnalyticsPage` при возврате создаётся заново с пустым состоянием; на случай рассинхрона backend ответит 400 и
   покажет toast по общему правилу.
4. **Код валюты в суммах.** `AnalyticsBucketCard` получает `currencyCode` и показывает «Доход: 780 RUB». Заголовок
   «Суммы в RUB» берётся из `display_currency_id` ответа. При срезе «Валюта» подпись — валюта операций, а суммы —
   в валюте отображения; код в сумме снимает неоднозначность.
5. **Предупреждение о неконвертируемых валютах.** Текст: «Операции в валютах {CNY} не вошли в итоги: за выбранный
   период нет пополнений, по которым можно вычислить курс к {RUB}. Выберите другой период или валюту
   отображения.» — одно сообщение `Alert` (warning); формирование текста в чистой функции.
6. **`WalletRateCard`.** Состояния: загрузка (`Spin`), ошибка (не рендерится — toast показывает глобальный
   обработчик), валюты совпадают (`wallet_currency_id === workspace_currency_id`) — не рендерится, `rate === null` —
   карточка «Курс пока не определён: пополните кошелёк, указав суммы в обеих валютах», иначе строка
   «1 {кошелёк} ≈ {rate} {воркспейс}» и пояснение «Среднее по пополнениям этого кошелька за всё время». Курс на
   экране аналитики может отличаться: там усреднение по всему воркспейсу за выбранный диапазон.
7. **Размеры.** Элементы ≥ 44 px обеспечивает глобальная тема antd.
