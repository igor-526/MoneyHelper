## Context

Контракты backend: пополнение `{wallet_id, category_id, legs[{currency_id, amount}], occurred_at?, comment?}` —
набор валют ног ровно `{валюта воркспейса, валюта кошелька}`; расход `{wallet_id, category_id, amount, occurred_at?,
comment?}` (`extra=forbid`), ответ расхода и пополнения — `TransactionOut` с `legs`. `GET /transactions` — только
расходы, `GET /topups` — только пополнения; оба с `wallet_id`, `category_id`, `date_from`, `date_to`, пагинацией.
Перевод: тело без `currency_id`, ответ без `currency_id`.

## Goals / Non-Goals

**Goals:** две вкладки с самостоятельными списками и CRUD; формы под новые контракты; корректная инвалидация.

**Non-Goals:** перенос переводов на вкладку/страницу (034), курс и аналитика (035), размещение переводов строк (034).

## Decisions

1. **Вкладки — таблица `OPERATION_KINDS`** (`operationKinds.ts`): для каждого вида ключ, подпись вкладки, тип
   категорий (`income`/`expense`), тексты (пустое состояние, подтверждение удаления), хуки `useList`/`useDelete` и
   компонент формы. `TransactionsPage` строит `Tabs` из таблицы; общий `OperationsTab` (фильтры, список,
   пагинация, форма) получает вид параметром и не знает конкретных видов. Новый вид — новая строка таблицы (O).
   Активная вкладка хранится в query-параметре `?tab=` (ссылка на вкладку, состояние при перезагрузке); `Tabs`
   antd держит смонтированными посещённые панели, поэтому фильтры вкладки сохраняются при переключении.
2. **Хуки.** Пополнения: `useTopups`, `useCreateTopup`, `useUpdateTopup`, `useDeleteTopup` (`/topups`). Расходы:
   прежние `useTransactions` (без `type`), `useCreateTransaction`, `useUpdateTransaction`, `useDeleteTransaction`.
   Тип `Transaction` общий для обоих ответов (`legs`); отдельный `Topup` не вводится (форма ответа одинакова).
3. **Инвалидация одной функцией** `invalidateOperationCaches(queryClient, workspaceId)`: списки расходов и
   пополнений, балансы, курсы кошельков (`["wallet-rates", ws]` — префикс), аналитика. Её вызывают все шесть
   мутаций (расход влияет на аналитику и баланс, пополнение — ещё и на курс). Ключи берутся из экспортируемых
   функций своих фич; для курса `walletRatesQueryKey` принимает необязательный `walletId` (префиксный ключ).
4. **`TopupForm`.** Набор полей суммы — валюты `[валюта воркспейса, валюта кошелька]` без повторов
   (`useCurrentWorkspace`); подпись «Сумма (КОД)». Создание и редактирование одной формой (`topup?`), в режиме
   редактирования суммы берутся из ног. Смена кошелька сбрасывает суммы. Категории — `useCategories("income")`.
5. **`TransactionForm`.** Остаётся только расход: поля кошелёк, категория (расходные), сумма с подписью
   «Сумма (КОД валюты кошелька)», дата, комментарий. Переключатель типа и выбор валюты удалены, `decimalPlaces` — из
   валюты кошелька.
6. **`TransactionCard`.** Без индикатора типа (вид задан вкладкой), без блокировки редактирования; удаление
   делает сама карточка через `useDelete` вида (по-прежнему `Popconfirm`).
7. **`TransferForm`.** Без `currency_id`; поле «Куда» показывает только кошельки валюты «Откуда»; подпись суммы с
   кодом валюты. `Transfer` теряет `currency_id`; `TransferCard` берёт код валюты по кошельку-источнику.
   Страница переводов и маршрут `/transfers` не меняются (034), ссылка «Переводы» на странице операций остаётся.
8. **Mobile-first.** Формы — нижний `Drawer` на телефоне, `Modal` на десктопе; `Tabs` — полноширинные, цели ≥ 44 px;
   «Добавить» — кнопка на всю ширину на телефоне.

## Risks / Trade-offs

- Строка `?tab=` с неизвестным значением → вкладка по умолчанию («Пополнение»).
- Одновременно смонтированные панели делают по запросу списка при первом посещении вкладки — приемлемо.
