## MODIFIED Requirements

### Requirement: Создание кошелька
`POST /api/workspaces/{workspace_id}/wallets` SHALL создавать кошелёк в указанном воркспейсе, принадлежащем
текущему аутентифицированному пользователю, с названием, иконкой из реестра допустимых имён и набором из одной
или нескольких валют из глобального справочника валют. `workspace_id` MUST принадлежать текущему пользователю.
Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с ошибкой аутентификации.

#### Scenario: Успешное создание кошелька с одной валютой
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/wallets` для своего
  воркспейса с корректным `name`, допустимым `icon` и `currency_ids` из одного существующего `currency_id`
- **THEN** ответ 201 содержит созданный кошелёк с этим `id`, `name`, `icon`, `currency_ids` из одного элемента,
  `created_at` и `updated_at`

#### Scenario: Успешное создание кошелька с несколькими валютами
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/wallets` с
  `currency_ids`, содержащим несколько различных существующих `currency_id`
- **THEN** ответ 201 содержит кошелёк со всеми переданными валютами в `currency_ids`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `name`, состоящим только из пробелов или
  пустой строкой
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной иконки
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `icon`, отсутствующим в реестре допустимых
  имён иконок
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение пустого набора валют
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с пустым списком `currency_ids`
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение дублей в наборе валют
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `currency_ids`, содержащим один и тот же
  `currency_id` более одного раза
- **THEN** ответ 400 с ошибкой валидации, кошелёк не создаётся

#### Scenario: Отклонение неизвестной валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `currency_ids`, содержащим `currency_id`,
  отсутствующий в справочнике валют
- **THEN** ответ 400 с сообщением, перечисляющим неизвестные `currency_id`, кошелёк не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, кошелёк не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/wallets` отправлен без действительного access-cookie
- **THEN** ответ 401, кошелёк не создаётся

### Requirement: Список кошельков пользователя
`GET /api/workspaces/{workspace_id}/wallets` SHALL возвращать постраничный список кошельков, принадлежащих только
указанному воркспейсу текущего аутентифицированного пользователя, отсортированный по `created_at` по возрастанию,
затем по `id` как детерминированному tie-breaker. Параметры пагинации — `limit` (1..100, по умолчанию 20) и
`offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только кошельки указанного воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/wallets` для одного из
  своих воркспейсов, при этом у него есть кошельки в других его воркспейсах
- **THEN** ответ 200 содержит только кошельки указанного воркспейса, `total` равен числу его кошельков

#### Scenario: Порядок списка детерминирован
- **WHEN** в воркспейсе есть несколько кошельков
- **THEN** ответ 200 возвращает их отсортированными по `created_at` по возрастанию, а при равном `created_at` — по
  `id` по возрастанию

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` запрошен с `limit` вне диапазона 1..100 или с отрицательным
  `offset`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/wallets` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Чтение одного кошелька
`GET /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL возвращать кошелёк по `id`, только если и кошелёк
принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю.

#### Scenario: Успешное чтение своего кошелька
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`
  для кошелька своего воркспейса
- **THEN** ответ 200 содержит `id`, `name`, `icon`, `currency_ids`, `created_at`, `updated_at`

#### Scenario: Валюты кошелька отсортированы по коду
- **WHEN** запрашивается кошелёк с несколькими валютами
- **THEN** `currency_ids` в ответе упорядочены по коду соответствующей валюты

#### Scenario: Несуществующий кошелёк
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}` с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление кошелька
`PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL полностью заменять `name`, `icon` и `currency_ids`
кошелька, принадлежащего указанному воркспейсу текущего аутентифицированного пользователя. Частичное обновление
(`PATCH`) не поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/wallets/{wallet_id}` для кошелька своего воркспейса с новыми корректными `name`,
  `icon` и `currency_ids`
- **THEN** ответ 200 содержит кошелёк с обновлёнными значениями и обновлённым `updated_at`; предыдущий набор валют
  кошелька полностью заменяется новым

#### Scenario: Обновление несуществующего кошелька
- **WHEN** `PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}` отправлен с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}` отправлен с пустым `name`, неизвестным `icon`,
  пустым или содержащим дубли `currency_ids`, либо с неизвестным `currency_id`
- **THEN** ответ 400, изменения не применяются

### Requirement: Удаление кошелька
`DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}` SHALL физически удалять кошелёк, принадлежащий
указанному воркспейсу текущего аутентифицированного пользователя, вместе со всеми его записями о валютах, если у
кошелька нет связанных операций и переводов. Если по кошельку есть хотя бы одна операция (`transactions.wallet_id`)
или хотя бы один перевод (`transfers.from_wallet_id` или `transfers.to_wallet_id`), запрос SHALL быть отклонён с
ошибкой конфликта, кошелёк не удаляется.

#### Scenario: Успешное удаление кошелька без операций и переводов
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/wallets/{wallet_id}` для кошелька своего воркспейса, по которому нет ни одной
  операции и ни одного перевода
- **THEN** ответ 204, кошелёк и его записи о валютах удалены; последующий `GET
  /api/workspaces/{workspace_id}/wallets/{wallet_id}` для того же `id` возвращает 404

#### Scenario: Удаление несуществующего кошелька
- **WHEN** `DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}` отправлен с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404

#### Scenario: Отклонение удаления кошелька с операциями
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/wallets/{wallet_id}` для кошелька своего воркспейса, по которому есть хотя бы одна
  операция
- **THEN** ответ 409, кошелёк и его операции не удаляются

#### Scenario: Отклонение удаления кошелька с переводом
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/wallets/{wallet_id}` для кошелька своего воркспейса, который является
  `from_wallet_id` или `to_wallet_id` хотя бы одного перевода
- **THEN** ответ 409, кошелёк и связанный перевод не удаляются

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретным кошельком или списком кошельков, SHALL проверять принадлежность воркспейса
текущему аутентифицированному пользователю и принадлежность кошелька указанному воркспейсу — на уровне запроса к
данным (`GET`, `PUT`, `DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}`; не отдельной проверкой после
чтения). Кошелёк из чужого воркспейса или чужой воркспейс в пути MUST быть неотличимы снаружи от несуществующих:
во всех случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужой кошелёк недоступен для чтения
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где `workspace_id`
  и `wallet_id` принадлежат воркспейсу пользователя B
- **THEN** ответ 404, а не 403; данные кошелька B не раскрываются

#### Scenario: Чужой кошелёк недоступен для обновления
- **WHEN** пользователь A отправляет `PUT /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где `workspace_id`
  принадлежит пользователю B
- **THEN** ответ 404, кошелёк B не изменяется

#### Scenario: Чужой кошелёк недоступен для удаления
- **WHEN** пользователь A отправляет `DELETE /api/workspaces/{workspace_id}/wallets/{wallet_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, кошелёк B не удаляется

#### Scenario: Кошелёк недоступен через чужой воркспейс даже с верным wallet_id
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}`, подставив `id`
  своего собственного `wallet_id`, но `workspace_id` воркспейса, принадлежащего пользователю B
- **THEN** ответ 404 (кошелёк с таким `wallet_id` не принадлежит указанному воркспейсу)
