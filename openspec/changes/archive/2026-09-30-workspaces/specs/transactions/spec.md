## MODIFIED Requirements

### Requirement: Создание операции
`POST /api/workspaces/{workspace_id}/transactions` SHALL создавать операцию (доход или расход) с ровно одной
«ногой» (валюта + сумма) в указанном воркспейсе, принадлежащем текущему аутентифицированному пользователю, с
указанием кошелька, категории, валюты и положительной суммы. `workspace_id` MUST принадлежать текущему
пользователю. Кошелёк и категория MUST принадлежать указанному воркспейсу. Валюта операции MUST входить в набор
валют указанного кошелька. Число знаков после запятой суммы MUST NOT превышать `decimal_places` валюты; округление
не выполняется. `occurred_at` — опциональное поле; при отсутствии SHALL использоваться текущее время сервера.
Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с ошибкой аутентификации. Ответ
представляет операцию в ногозависимой форме: `legs` — список из одного элемента `{currency_id, amount}`.

#### Scenario: Успешное создание операции с указанной датой
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/transactions` с
  корректными `wallet_id` (кошелька своего воркспейса), `category_id` (категории своего воркспейса), `currency_id`
  из набора валют кошелька, положительным `amount` с числом знаков не более `decimal_places` валюты и явным
  `occurred_at`
- **THEN** ответ 201 содержит созданную операцию с этим `id`, `wallet_id`, `category_id`, `legs` (список из одного
  элемента с этими `currency_id` и `amount`), `occurred_at` (равным переданному), `created_at` и `updated_at`

#### Scenario: Успешное создание операции без даты — используется текущее время
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит операцию с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Отклонение валюты, не входящей в набор валют кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `currency_id`, отсутствующим в
  `currency_ids` указанного кошелька
- **THEN** ответ 400 с понятным сообщением, операция не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `amount`, число знаков после запятой
  которого превышает `decimal_places` валюты `currency_id`
- **THEN** ответ 400, операция не создаётся, сумма не округляется

#### Scenario: Отклонение неположительной суммы
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `amount`, равным нулю или отрицательным
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `wallet_id`, которого нет в указанном
  воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующей или чужой категории
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `category_id`, которой нет в указанном
  воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен без действительного access-cookie
- **THEN** ответ 401, операция не создаётся

### Requirement: Список операций пользователя с фильтрами и сортировкой
`GET /api/workspaces/{workspace_id}/transactions` SHALL возвращать постраничный список операций, принадлежащих
только указанному воркспейсу текущего аутентифицированного пользователя, отсортированный по `occurred_at` по
убыванию, затем по `id` по убыванию как детерминированному tie-breaker (новые операции первыми). Опциональные
query-параметры `wallet_id`, `category_id`, `type` (`income`/`expense`, через тип связанной категории), `date_from`
и `date_to` (включительно, диапазон по `occurred_at`) SHALL сужать список. Если заданы оба `date_from` и `date_to`,
и `date_from` позже `date_to`, запрос SHALL быть отклонён. Параметры пагинации — `limit` (1..100, по умолчанию 20)
и `offset` (≥ 0, по умолчанию 0). Каждый элемент списка представляет операцию в ногозависимой форме (`legs`) — как
обычные операции (список из одного элемента), так и пополнения (список из нескольких элементов), без отдельного
признака различия.

#### Scenario: Список содержит только операции указанного воркспейса
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/transactions` для
  одного из своих воркспейсов, при этом у него есть операции в других его воркспейсах
- **THEN** ответ 200 содержит только операции указанного воркспейса, `total` равен числу его операций

#### Scenario: Порядок списка — новые операции первыми
- **WHEN** в воркспейсе есть несколько операций с разными `occurred_at`
- **THEN** ответ 200 возвращает их отсортированными по `occurred_at` по убыванию, а при равном `occurred_at` — по
  `id` по убыванию

#### Scenario: Фильтр по кошельку
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/transactions?wallet_id=...` для одного из
  кошельков этого воркспейса
- **THEN** ответ 200 содержит только операции этого кошелька

#### Scenario: Фильтр по категории
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/transactions?category_id=...` для одной из
  категорий этого воркспейса
- **THEN** ответ 200 содержит только операции этой категории

#### Scenario: Фильтр по типу операции
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/transactions?type=income` (или
  `type=expense`)
- **THEN** ответ 200 содержит только операции, чья категория имеет соответствующий `type`

#### Scenario: Фильтр по диапазону дат
- **WHEN** пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transactions?date_from=...&date_to=...`
- **THEN** ответ 200 содержит только операции с `occurred_at` в указанном диапазоне включительно

#### Scenario: Некорректный диапазон дат отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions?date_from=...&date_to=...` запрошен с `date_from`,
  позже `date_to`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` запрошен с `limit` вне диапазона 1..100 или с
  отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: Список отображает пополнение с несколькими ногами
- **WHEN** в воркспейсе есть операция-пополнение (созданная через `POST
  /api/workspaces/{workspace_id}/transactions/topups`) с несколькими валютами
- **THEN** соответствующий элемент списка `GET /api/workspaces/{workspace_id}/transactions` содержит `legs` со
  всеми ногами этого пополнения

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Чтение одной операции
`GET /api/workspaces/{workspace_id}/transactions/{transaction_id}` SHALL возвращать операцию по `id`, только если
и операция принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю.
Ответ представляет операцию в ногозависимой форме: `legs` — список из одного элемента `{currency_id, amount}` для
обычной операции или из нескольких элементов для пополнения; по числу элементов `legs` пополнение отличимо от
обычной операции, отдельного признака типа нет.

#### Scenario: Успешное чтение своей операции
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для операции своего воркспейса
- **THEN** ответ 200 содержит `id`, `wallet_id`, `category_id`, `legs`, `occurred_at`, `created_at`, `updated_at`

#### Scenario: Чтение пополнения возвращает все его ноги
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для своего пополнения с несколькими валютами
- **THEN** ответ 200 содержит `legs` со всеми ногами пополнения, отсортированными по коду валюты

#### Scenario: Несуществующая операция
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/transactions/{transaction_id}` с `transaction_id`,
  которого нет в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление операции
`PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` SHALL полностью заменять `wallet_id`,
`category_id`, `currency_id`, `amount` и `occurred_at` операции, принадлежащей указанному воркспейсу текущего
аутентифицированного пользователя, с той же валидацией, что и при создании. Результат всегда содержит ровно одну
ногу — `PUT` не поддерживает многовалютные операции (пополнение с несколькими ногами нельзя отредактировать через
`PUT`; изменить его можно только удалением через `DELETE
/api/workspaces/{workspace_id}/transactions/{transaction_id}` и созданием заново через `POST
/api/workspaces/{workspace_id}/transactions/topups`). Частичное обновление (`PATCH`) не поддерживается.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для операции своего воркспейса с новыми
  корректными `wallet_id`, `category_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит операцию с `legs` — списком из одного элемента с обновлёнными `currency_id`/
  `amount`, и обновлённым `updated_at`

#### Scenario: Обновление несуществующей операции
- **WHEN** `PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен с `transaction_id`,
  которого нет в указанном воркспейсе
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен с валютой, не входящей в
  набор валют кошелька, неположительной суммой, суммой с превышением знаков валюты, либо несуществующим/чужим
  `wallet_id` или `category_id`
- **THEN** ответ 400 или 404 (в зависимости от причины), изменения не применяются

#### Scenario: Полная замена превращает пополнение в операцию с одной ногой
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для своего пополнения (ранее имевшего несколько
  ног) с новыми корректными `wallet_id`, `category_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит операцию с `legs` — списком ровно из одного элемента; прежние ноги пополнения
  заменены полностью

### Requirement: Удаление операции
`DELETE /api/workspaces/{workspace_id}/transactions/{transaction_id}` SHALL физически удалять операцию,
принадлежащую указанному воркспейсу текущего аутентифицированного пользователя, вместе со связанной строкой
`transaction_legs` (каскадно).

#### Scenario: Успешное удаление
- **WHEN** аутентифицированный пользователь отправляет `DELETE
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для операции своего воркспейса
- **THEN** ответ 204, операция и её нога удалены; последующий `GET
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для того же `id` возвращает 404

#### Scenario: Удаление несуществующей операции
- **WHEN** `DELETE /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен с `transaction_id`,
  которого нет в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Баланс по кошельку и валюте
`GET /api/workspaces/{workspace_id}/wallets/{wallet_id}/balances` SHALL возвращать баланс кошелька, принадлежащего
указанному воркспейсу текущего аутентифицированного пользователя, по каждой валюте из набора валют кошелька
(включая валюты без единой операции и перевода — с балансом 0), отсортированный по коду валюты. Баланс по валюте
вычисляется на лету как сумма вклада всех источников: операций (сумма `amount` операций с категорией типа `income`
минус сумма `amount` операций с категорией типа `expense`) и переводов (сумма `amount` переводов, у которых
кошелёк — `to_wallet_id`, минус сумма `amount` переводов, у которых кошелёк — `from_wallet_id`), отфильтрованных по
этому кошельку, валюте и воркспейсу.

#### Scenario: Баланс кошелька без операций и переводов — нули по всем его валютам
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/wallets/{wallet_id}/balances` для кошелька своего воркспейса, у которого ещё нет
  ни одной операции и ни одного перевода
- **THEN** ответ 200 содержит запись с `balance = 0` для каждой валюты из `currency_ids` этого кошелька

#### Scenario: Баланс учитывает доходы и расходы
- **WHEN** у кошелька есть операции дохода на сумму X и операции расхода на сумму Y в одной и той же валюте
- **THEN** ответ 200 содержит баланс, равный X минус Y, для этой валюты

#### Scenario: Баланс учитывает переводы
- **WHEN** у кошелька есть перевод на сумму Z, в котором кошелёк — целевой (`to_wallet_id`), и перевод на сумму W,
  в котором кошелёк — исходный (`from_wallet_id`), в одной и той же валюте
- **THEN** ответ 200 содержит баланс по этой валюте, увеличенный на Z и уменьшенный на W относительно баланса без
  этих переводов

#### Scenario: Баланс отдельен по валютам многовалютного кошелька
- **WHEN** у кошелька с несколькими валютами есть операции и переводы в разных валютах
- **THEN** ответ 200 содержит отдельную запись `{currency_id, balance}` для каждой валюты кошелька, не смешивая
  суммы разных валют

#### Scenario: Несуществующий или чужой кошелёк
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}/balances` с `wallet_id`, которого
  нет в указанном воркспейсе
- **THEN** ответ 404

#### Scenario: Баланс кошелька из чужого воркспейса недоступен через свой workspace_id
- **WHEN** у пользователя есть воркспейсы A и B с кошельками, и он запрашивает `GET
  /api/workspaces/{workspace_id}/wallets/{wallet_id}/balances`, подставив `workspace_id` воркспейса A и
  `wallet_id` кошелька, принадлежащего воркспейсу B
- **THEN** ответ 404 (кошелёк с таким `wallet_id` не принадлежит воркспейсу A), баланс не раскрывается

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий операцией или балансом кошелька, SHALL проверять принадлежность воркспейса текущему
аутентифицированному пользователю и принадлежность операции/кошелька указанному воркспейсу на уровне запроса к
данным (`GET`, `PUT`, `DELETE /api/workspaces/{workspace_id}/transactions/{transaction_id}`, `GET
/api/workspaces/{workspace_id}/wallets/{wallet_id}/balances`; не отдельной проверкой после чтения). Операция или
кошелёк из чужого воркспейса, либо чужой воркспейс в пути, MUST быть неотличимы снаружи от несуществующих: во всех
случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужая операция недоступна для чтения
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/transactions/{transaction_id}`, где
  `workspace_id` и `transaction_id` принадлежат воркспейсу пользователя B
- **THEN** ответ 404, а не 403; данные операции B не раскрываются

#### Scenario: Чужая операция недоступна для обновления
- **WHEN** пользователь A отправляет `PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, операция B не изменяется

#### Scenario: Чужая операция недоступна для удаления
- **WHEN** пользователь A отправляет `DELETE /api/workspaces/{workspace_id}/transactions/{transaction_id}`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, операция B не удаляется

#### Scenario: Список одного воркспейса не содержит операций другого
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/transactions` для одного из своих
  воркспейсов, при этом в другом его воркспейсе (или воркспейсе пользователя B) есть операции по своим кошелькам и
  категориям
- **THEN** ответ 200 содержит только операции запрошенного воркспейса

#### Scenario: Баланс чужого кошелька недоступен
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/wallets/{wallet_id}/balances`, где
  `workspace_id` принадлежит пользователю B
- **THEN** ответ 404, баланс кошелька B не раскрывается

### Requirement: Пополнение многовалютного кошелька
`POST /api/workspaces/{workspace_id}/transactions/topups` SHALL создавать операцию пополнения — доход, в указанном
воркспейсе, принадлежащем текущему аутентифицированному пользователю, с несколькими «ногами» (валюта + сумма),
одной на каждую валюту указанного кошелька. `workspace_id` MUST принадлежать текущему пользователю. Кошелёк и
категория MUST принадлежать указанному воркспейсу. Категория MUST иметь тип `income`. Набор валют переданных ног
MUST совпадать ровно с набором валют кошелька (`wallet.currency_ids`) — без отсутствующих, без лишних, без
повторов. Каждая сумма MUST быть положительной, число знаков после запятой MUST NOT превышать `decimal_places`
соответствующей валюты; округление не выполняется. Курс между валютами пополнения не хранится отдельным полем —
воспроизводим как отношение сохранённых сумм ног. `occurred_at` — опциональное поле; при отсутствии SHALL
использоваться текущее время сервера. Запрос без действительной сессии (без access-cookie) SHALL быть отклонён с
ошибкой аутентификации.

#### Scenario: Успешное пополнение с полным набором валют кошелька
- **WHEN** аутентифицированный пользователь отправляет `POST
  /api/workspaces/{workspace_id}/transactions/topups` с `wallet_id` своего многовалютного кошелька в этом
  воркспейсе, `category_id` своей категории типа `income` в этом же воркспейсе и `legs`, содержащими ровно по
  одной ноге на каждую валюту кошелька с положительными суммами без превышения знаков после запятой
- **THEN** ответ 201 содержит созданную операцию с этим `id`, `wallet_id`, `category_id`, `legs` (все переданные
  валюты и суммы, отсортированные по коду валюты), `occurred_at`, `created_at` и `updated_at`

#### Scenario: Успешное пополнение без даты — используется текущее время
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит операцию с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Курс воспроизводим по сохранённым ногам
- **WHEN** пополнение создано с ногами, например, 10 000 в одной валюте и 780 в другой
- **THEN** после создания курс между этими валютами вычислим как отношение сохранённых сумм ног (10 000 / 780) без
  отдельно хранимого значения курса

#### Scenario: Отклонение пополнения с неполным набором валют
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен для многовалютного кошелька с
  `legs`, не содержащими ногу хотя бы для одной из валют кошелька
- **THEN** ответ 400 с сообщением, перечисляющим отсутствующие валюты, операция не создаётся

#### Scenario: Отклонение пополнения с избыточным набором валют
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `legs`, содержащими валюту,
  отсутствующую в наборе валют указанного кошелька
- **THEN** ответ 400 с сообщением, перечисляющим лишние валюты, операция не создаётся

#### Scenario: Отклонение пополнения с повторяющейся валютой в ногах
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `legs`, содержащими одну и ту же
  валюту более одного раза
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение пополнения с категорией не типа income
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `category_id` категории типа
  `expense`
- **THEN** ответ 400 с понятным сообщением, операция не создаётся

#### Scenario: Отклонение неположительной суммы в ноге пополнения
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с хотя бы одной ногой, у которой
  `amount` равен нулю или отрицателен
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты в ноге пополнения
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с хотя бы одной ногой, у которой
  число знаков после запятой `amount` превышает `decimal_places` соответствующей валюты
- **THEN** ответ 400, операция не создаётся, сумма не округляется

#### Scenario: Отклонение несуществующего или чужого кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующей или чужой категории
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `category_id`, которой нет в
  указанном воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `workspace_id`, которого нет ни у
  одного пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен без действительного access-cookie
- **THEN** ответ 401, операция не создаётся
