## MODIFIED Requirements

### Requirement: Отчёт аналитики по операциям с группировкой
`GET /api/workspaces/{workspace_id}/analytics` SHALL возвращать суммы доходов и расходов указанного воркспейса,
принадлежащего текущему аутентифицированному пользователю, за явный диапазон дат `[date_from, date_to]`,
пересчитанные в валюту отображения `display_currency`, сгруппированные по одной из трёх осей `group_by` (`wallet`
— по `wallet_id`, `category` — по `category_id`, `currency` — по `currency_id`). `workspace_id` MUST принадлежать
текущему пользователю. Каждый элемент ответа (`buckets`) SHALL содержать `group_key` (значение соответствующего
поля), `income` и `expense` — обе суммы всегда присутствуют одновременно (`0`, если операций соответствующего типа
в корзине нет). Корзины, для которых в диапазоне (после всех фильтров) нет ни одной подходящей ноги операции, SHALL
NOT включаться в ответ нулевой записью. Аналитика охватывает только `transactions` указанного воркспейса
(доходы/расходы через `categories.type`); переводы (`transfers`) не являются ни доходом, ни расходом, не имеют
категории и SHALL NOT учитываться ни в одной корзине.

#### Scenario: Группировка по кошельку
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/analytics?group_by=wallet` с корректными `display_currency`, `date_from`,
  `date_to`, и в диапазоне есть операции по нескольким кошелькам этого воркспейса
- **THEN** ответ 200 содержит по одной корзине `{group_key, income, expense}` на каждый кошелёк, по которому есть
  хотя бы одна операция в диапазоне, с суммами в валюте `display_currency`

#### Scenario: Группировка по категории
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/analytics?group_by=category` с корректными обязательными параметрами, и в
  диапазоне есть операции по нескольким категориям этого воркспейса
- **THEN** ответ 200 содержит по одной корзине на каждую категорию, по которой есть хотя бы одна операция в
  диапазоне

#### Scenario: Группировка по валюте
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/analytics?group_by=currency` с корректными обязательными параметрами, и в
  диапазоне есть операции в нескольких валютах
- **THEN** ответ 200 содержит по одной корзине на каждую валюту операции (`currency_id` исходной ноги, не валюту
  отображения), по которой есть хотя бы одна операция в диапазоне

#### Scenario: Обе суммы корзины присутствуют, даже если фильтр сузил выборку до одного типа
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/analytics?type=income` (или `type=expense`) с прочими корректными обязательными
  параметрами
- **THEN** каждая корзина ответа 200 содержит и `income`, и `expense`; сторона, исключённая фильтром, равна `0`

#### Scenario: Пустые корзины не включаются в ответ
- **WHEN** в воркспейсе есть кошелёк/категория/валюта, по которым в диапазоне `[date_from, date_to]` (с учётом
  прочих фильтров) нет ни одной операции
- **THEN** ответ 200 не содержит корзину с `group_key`, равным этому кошельку/категории/валюте

#### Scenario: Переводы не учитываются в аналитике
- **WHEN** в воркспейсе в диапазоне есть и операции (доходы/расходы), и переводы между его кошельками
- **THEN** суммы `income`/`expense` во всех корзинах ответа 200 вычислены только по операциям; ни один перевод не
  увеличивает и не уменьшает ни одну сумму

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404

### Requirement: Конвертация сумм по среднему курсу диапазона
Сумма каждой ноги операции, чья валюта совпадает с `display_currency`, SHALL включаться в соответствующую корзину
без конвертации. Сумма ноги в другой валюте SHALL пересчитываться по курсу — простому среднему арифметическому
значений `target_leg.amount / source_leg.amount` по всем операциям-пополнениям того же воркспейса (операциям с
более чем одной «ногой»), содержащим ногу и в валюте ноги (`source`), и в `display_currency` (`target`), за тот же
диапазон `[date_from, date_to]`, что и сам запрос аналитики. Пополнения из других воркспейсов пользователя (или
других пользователей) в усреднении не участвуют.

#### Scenario: Курс вычисляется по одному пополнению
- **WHEN** в воркспейсе в диапазоне `[date_from, date_to]` есть ровно одно пополнение с ногами 10 000 в валюте A и
  780 в валюте B (валюта отображения — B), и есть операция расхода на 1 000 в валюте A в том же диапазоне
- **THEN** ответ 200 пересчитывает эту операцию по курсу `780 / 10000 = 0.078` B за единицу A, т. е. вносит в
  корзину сумму `1000 × 0.078 = 78` (до применения округления, см. отдельное требование об округлении)

#### Scenario: Курс усредняется по нескольким пополнениям
- **WHEN** в воркспейсе в диапазоне есть два пополнения с ногами в одной и той же паре валют (A и B — валюта
  отображения), дающими два разных курса `target/source`
- **THEN** для пересчёта операций в валюте A используется простое среднее арифметическое этих двух курсов, а не
  средневзвешенное по суммам ног

#### Scenario: Валюта отображения не требует похода за курсом
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics` с
  `display_currency`, совпадающей с валютой части операций в диапазоне
- **THEN** суммы этих операций включаются в ответ 200 без пересчёта, курс для этой валюты не вычисляется

### Requirement: Обработка отсутствия курса для валюты
Суммы операции в валюте, для которой не найден курс к `display_currency`, SHALL исключаться из всех сумм ответа (не
включаться в `income`/`expense` ни одной корзины) — валюта считается неконвертируемой, если в диапазоне запроса
нет ни одного пополнения того же воркспейса с ногой и в этой валюте, и в `display_currency`; курс `1` SHALL NOT
подставляться вместо отсутствующего. Валюта SHALL добавляться в `AnalyticsOut.unconverted_currencies` (список без
дублей). Отсутствие курса для одной валюты SHALL NOT приводить к ошибке всего запроса.

#### Scenario: Валюта без курса исключается из сумм, но не ломает запрос
- **WHEN** в воркспейсе в диапазоне есть операция в валюте C, для которой нет ни одного пополнения с ногой в
  валюте C и в `display_currency` за этот же диапазон
- **THEN** ответ 200 не включает сумму этой операции ни в одну корзину, `unconverted_currencies` содержит `C`, а
  корзины по остальным валютам рассчитаны как обычно

#### Scenario: Валюта с найденным курсом не попадает в unconverted_currencies
- **WHEN** в воркспейсе в диапазоне есть операция в валюте, для которой найден хотя бы один курс к
  `display_currency`, и операция в валюте, для которой курса нет
- **THEN** `unconverted_currencies` ответа 200 содержит только вторую валюту

### Requirement: Округление итоговых сумм корзины
Суммирование конвертированных сумм внутри каждой корзины SHALL выполняться в полной точности (без округления
промежуточных сумм ног). Округление до `decimal_places` валюты `display_currency` SHALL выполняться один раз — над
уже просуммированным итогом `income` и отдельно `expense` каждой корзины.

#### Scenario: Ошибки округления не накапливаются по множеству мелких операций
- **WHEN** в воркспейсе в диапазоне есть много операций в валюте, требующей конвертации, суммы которых по
  отдельности округлились бы по-разному, чем их сумма
- **THEN** ответ 200 содержит `income`/`expense` корзины, равные округлению суммы всех неокруглённых
  конвертированных сумм, а не сумме отдельно округлённых сумм каждой операции

### Requirement: Обязательность и валидация диапазона дат
`date_from` и `date_to` SHALL быть обязательными query-параметрами `GET /api/workspaces/{workspace_id}/analytics`
(без умолчания «за всё время»). Если `date_from` позже `date_to`, запрос SHALL быть отклонён.

#### Scenario: Запрос без date_from или date_to отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен без параметра `date_from` или без `date_to`
- **THEN** ответ 400 с ошибкой валидации

#### Scenario: date_from позже date_to отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен с `date_from`, позже `date_to`
- **THEN** ответ 400 с понятным сообщением

### Requirement: Валидация валюты отображения
`display_currency` SHALL быть обязательным query-параметром, ссылающимся на существующую валюту глобального
справочника. Неизвестная валюта отображения SHALL приводить к отклонению запроса.

#### Scenario: Неизвестная валюта отображения отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен с `display_currency`, которой нет в
  справочнике валют
- **THEN** ответ 400 с понятным сообщением

#### Scenario: Запрос без display_currency отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен без параметра `display_currency`
- **THEN** ответ 400 с ошибкой валидации

### Requirement: Фильтры набора операций
`GET /api/workspaces/{workspace_id}/analytics` SHALL принимать опциональные query-параметры `wallet_id`,
`category_id`, `currency_id`, `type` (`income`/`expense`), сужающие набор операций, участвующих в агрегации, теми
же смысловыми правилами, что и одноимённые фильтры `GET /api/workspaces/{workspace_id}/transactions`. Эти фильтры
сужают только набор конвертируемых операций, но не набор пополнений того же воркспейса, по которым усредняется
курс.

#### Scenario: Фильтр по кошельку
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics?wallet_id=...` для одного из
  кошельков этого воркспейса
- **THEN** ответ 200 агрегирует только операции этого кошелька

#### Scenario: Фильтр по категории
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics?category_id=...` для одной из
  категорий этого воркспейса
- **THEN** ответ 200 агрегирует только операции этой категории

#### Scenario: Фильтр по валюте операции
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics?currency_id=...`
- **THEN** ответ 200 агрегирует только операции с ногой в этой валюте

#### Scenario: Фильтр по типу операции
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics?type=income` (или
  `type=expense`)
- **THEN** ответ 200 агрегирует только операции, чья категория имеет соответствующий `type`

#### Scenario: Фильтры кошелька/категории/валюты не сужают набор пополнений для усреднения курса
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics?wallet_id=...`, и пополнения
  этого же воркспейса, участвующие в усреднении курса, относятся к другим кошелькам того же воркспейса в том же
  диапазоне дат
- **THEN** курс, применённый к операциям отфильтрованного кошелька, всё равно вычислен по этим пополнениям

### Requirement: Изоляция данных по владельцу
Каждый расчёт `GET /api/workspaces/{workspace_id}/analytics` SHALL проверять принадлежность воркспейса текущему
аутентифицированному пользователю и учитывать только операции и пополнения, принадлежащие указанному воркспейсу.
Операции и пополнения другого воркспейса (того же пользователя или другого пользователя) MUST NOT участвовать ни в
агрегированных суммах, ни в усреднении курса.

#### Scenario: Чужие операции не участвуют в суммах
- **WHEN** пользователь A запрашивает `GET /api/workspaces/{workspace_id}/analytics` для одного из своих
  воркспейсов, при этом в системе есть операции за тот же диапазон дат в других воркспейсах (своих или
  пользователя B)
- **THEN** ответ 200 содержит суммы, рассчитанные только по операциям запрошенного воркспейса

#### Scenario: Пополнение другого воркспейса не влияет на усреднённый курс
- **WHEN** пользователь запрашивает `GET /api/workspaces/{workspace_id}/analytics` для операции в валюте, для
  которой в запрошенном воркспейсе в диапазоне нет ни одного своего пополнения с нужной парой валют, но в другом
  воркспейсе того же пользователя (или у пользователя B) в этом же диапазоне такое пополнение есть
- **THEN** курс не вычислен по пополнению другого воркспейса; валюта операции считается неконвертируемой (попадает
  в `unconverted_currencies`, не пересчитывается по чужому курсу)

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, данные не возвращаются

### Requirement: Отказ без аутентификации
`GET /api/workspaces/{workspace_id}/analytics` SHALL быть отклонён с ошибкой аутентификации при отсутствии
действительной сессии (access-cookie).

#### Scenario: Запрос без сессии отклоняется
- **WHEN** `GET /api/workspaces/{workspace_id}/analytics` отправлен без действительного access-cookie
- **THEN** ответ 401, данные не возвращаются
