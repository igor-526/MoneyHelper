## Why

Управление воркспейсами (список, переключение, переименование, удаление, создание) было спрятано в разделе
«Настройки», хотя воркспейсы — это основная концепция приложения («поездки»), между которыми пользователь
переключается постоянно, а не изредка настраивает. Пользователь не нашёл переключение воркспейса там, где ожидал
его увидеть — на «Главной» (корневой маршрут `/`, первый пункт навигации). Секция переносится на «Главную», ближе
к точке входа в приложение.

## What Changes

- Секция управления воркспейсами (`WorkspacesSection`) перемещена из `SettingsPage` в `HealthPage` (маршрут `/`,
  пункт навигации «Главная»). Функциональность не меняется — тот же список, переключение, переименование,
  удаление, создание.
- Карточка «Воркспейсы» убрана из «Настроек».
- `HealthPage` перестаёт быть страницей-заглушкой только со статусом backend — теперь это главная точка входа:
  статус backend + управление воркспейсами.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `frontend-workspaces`: требование «Управление воркспейсами» меняет место размещения — с раздела «Настройки» на
  «Главную» (маршрут `/`).

## Impact

- Затронутый код: `frontend/src/features/health/HealthPage.tsx`,
  `frontend/src/features/settings/SettingsPage.tsx`, комментарий в
  `frontend/src/features/workspaces/WorkspacesSection.tsx`.
- API и БД не затрагиваются, миграция Alembic не требуется.
- Изменение чисто фронтовое, затрагивает только расположение уже существующего компонента на странице.

## Вне рамок

- Переключатель воркспейса в шапке/навигации (quick switcher) — не входит, обсуждается отдельно при наличии
  запроса.
- Известная проблема вёрстки `Popconfirm` при удалении воркспейса (кнопки подтверждения уезжают за пределы
  экрана на широких viewport) — предсуществующий баг, не вызванный этим изменением, фиксится отдельной задачей.
