## ADDED Requirements

### Requirement: Хранение пользователей
Система SHALL хранить пользователей в таблице `users`: `id` (UUID, первичный ключ), `email` (уникален, в нижнем регистре), `password_hash`, `token_version` (целое число, не меньше 0, по умолчанию 0), `created_at`, `updated_at`. Идентификатор пользователя MUST генерироваться через `IdGenerator`, время — через `Clock`. Пароль MUST NOT храниться и возвращаться в открытом виде; ответы API MUST NOT содержать `password_hash` и `token_version`.

#### Scenario: Ответ без секретов
- **WHEN** клиент получает данные пользователя от любого эндпоинта
- **THEN** ответ содержит `id`, `email` и `created_at`, но не содержит `password_hash` и `token_version`

### Requirement: Регистрация
`POST /api/auth/register` с JSON `{"email": ..., "password": ...}` SHALL создавать пользователя и возвращать 201 с данными пользователя. Email MUST приводиться к нижнему регистру и очищаться от пробелов по краям; формат проверяется как email длиной не более 254 символов. Пароль хешируется argon2id вне event loop. Регистрация не устанавливает cookies (вход выполняется отдельно).

#### Scenario: Успешная регистрация
- **WHEN** отправляется `{"email": "  User@Example.COM ", "password": "correct-horse"}` при включённой регистрации
- **THEN** ответ 201 содержит `email = "user@example.com"`, а в БД появляется пользователь с хешем argon2id

#### Scenario: Email уже занят
- **WHEN** регистрируется email, который уже есть (в любом регистре)
- **THEN** ответ 409 с текстовым `detail`

#### Scenario: Некорректный email
- **WHEN** отправляется значение, не являющееся email
- **THEN** ответ 400 с ошибками валидации по полю `email`

### Requirement: Флаг регистрации
Регистрация SHALL быть доступна только при `REGISTRATION_ENABLED=true`; при `false` эндпоинт MUST отвечать 403 с текстовым `detail`, не создавая пользователя и не проверяя занятость email. Значение по умолчанию — `false`.

#### Scenario: Регистрация отключена
- **WHEN** `REGISTRATION_ENABLED=false` и приходит корректный запрос регистрации
- **THEN** ответ 403, пользователь не создан

### Requirement: Правила пароля
Пароль SHALL быть длиной от 8 до 128 символов; иначе запрос отклоняется как ошибка валидации (400) по полю `password`. Хеширование и проверка пароля MUST выполняться вне event loop (в потоке), чтобы не блокировать обслуживание запросов.

#### Scenario: Короткий пароль
- **WHEN** отправляется пароль из 7 символов
- **THEN** ответ 400 с ошибкой по полю `password`, пользователь не создан

#### Scenario: Слишком длинный пароль
- **WHEN** отправляется пароль из 129 символов
- **THEN** ответ 400 с ошибкой по полю `password`

### Requirement: Смена пароля
`POST /api/auth/password` с JSON `{"current_password": ..., "new_password": ...}` SHALL требовать действующую сессию (access-cookie), проверять текущий пароль, применять правила пароля к новому, сохранять новый хеш, увеличивать `token_version` пользователя на 1 и устанавливать новые cookies (пара токенов с новым `ver`) с ответом 204. Неверный текущий пароль MUST давать 401 с тем же текстом, что и неверный вход, без изменения данных.

#### Scenario: Успешная смена
- **WHEN** авторизованный пользователь отправляет верный текущий пароль и новый пароль из 8+ символов
- **THEN** ответ 204, cookies обновлены, вход со старым паролем невозможен, `token_version` увеличен на 1

#### Scenario: Неверный текущий пароль
- **WHEN** текущий пароль указан неверно
- **THEN** ответ 401, пароль и `token_version` не изменены

#### Scenario: Старые refresh гаснут
- **WHEN** пароль сменён на одном устройстве, а на другом лежит refresh, выданный до смены
- **THEN** обновление сессии с этим refresh даёт 401

### Requirement: Текущий пользователь
`GET /api/auth/me` SHALL возвращать данные текущего пользователя (по access-cookie) либо 401. Сервисы последующих задач MUST получать `user_id` явным аргументом из зависимости `get_current_user`.

#### Scenario: Пользователь найден
- **WHEN** запрос содержит валидный access-cookie существующего пользователя
- **THEN** ответ 200 с `id`, `email`, `created_at`

#### Scenario: Пользователь удалён
- **WHEN** access валиден, но пользователя в БД уже нет
- **THEN** ответ 401
