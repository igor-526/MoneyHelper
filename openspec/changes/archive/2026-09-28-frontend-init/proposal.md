## Why

Backend-скелет готов (`backend-foundation`), а каркаса клиента нет. Все следующие этапы (авторизация, кошельки, операции,
аналитика) требуют frontend, который уже умеет ходить в API с cookies и гарантированно показывает пользователю любую
ошибку. Закладываем это один раз в фундаменте, чтобы не переделывать каждую фичу.

## What Changes

- Новый проект `frontend/`: Vite + React + TypeScript, полностью CSR, структура `app` / `features` / `shared`.
- API-клиент за интерфейсом в `shared/api`: `credentials: "include"`, таймаут, нормализация любого сбоя в типизированную `ApiError`, хук для 401 (refresh и повтор — подключается в задаче 005).
- UI-библиотека Ant Design (antd 6): `ConfigProvider` с русской локалью и темой, компонент `App`; все компоненты интерфейса строятся на antd.
- **Mobile-first**: приложение в основном используется на телефоне. Адаптивный layout (на телефоне — нижняя навигация, на широких экранах — верхняя), безопасные зоны экрана, touch-цели не меньше 44 px, поля ввода без авто-зума iOS, отсутствие горизонтальной прокрутки от 320 px.
- **Тёмная тема**: режимы «светлая / тёмная / как в системе» (по умолчанию как в системе), переключатель на странице настроек, выбор сохраняется на устройстве, тема применяется без мигания при загрузке, в тёмной теме сохраняются размеры и контраст.
- **PWA**: web app manifest, иконки (в т.ч. maskable и для iOS), service worker с кэшем оболочки приложения (открывается офлайн), запрос данных API не кэшируется, установка на домашний экран (кнопка установки и подсказка для iOS), баннеры «нет соединения» и «доступна новая версия» с обновлением по кнопке.
- Система уведомлений Toast: хук `useToast` (типы: ошибка, успех, предупреждение) — тонкая обёртка над antd `message` с дедупликацией, лимитом и автоскрытием.
- Единая обработка ошибок: глобальный обработчик запросов и мутаций показывает toast по умолчанию; действие может переопределить сообщение; ошибки валидации 400 привязываются к полям форм; корневой error boundary для ошибок рендеринга.
- Роутинг, провайдеры, базовый layout, страница-заглушка, которая обращается к `GET /health`.
- Обёртка `Icon` над Lucide: принимает имя иконки из БД, для неизвестного имени показывает запасную иконку.
- Настройка адреса backend через `VITE_API_URL`, файл `.env.example`.
- QualityGate frontend: ESLint, Prettier, `tsc --noEmit`, Vitest; подключение к корневым `make format`, `make lint`, `make test`; отдельный job в CI.
- Обновление README.md и AGENTS.md (структура и правила frontend).

Backend, БД и миграции Alembic **не затрагиваются**; API не меняется. **BREAKING**-изменений нет.

## Capabilities

### New Capabilities
- `api-client`: интерфейс HTTP-клиента, cookies, таймаут, нормализация ответов и сбоев в `ApiError`, хук 401.
- `error-handling`: обязательная обработка любой ошибки каждого действия, toast по умолчанию, переопределение сообщения, ошибки по полям форм, error boundary.
- `toast-notifications`: интерфейс `useToast` поверх antd `message`, типы, дедупликация, лимит, автоскрытие, закрытие вручную.
- `dark-theme`: режимы темы, определение системной темы, сохранение выбора, отсутствие мигания, `theme-color`, переключатель.
- `pwa`: manifest, иконки, service worker и стратегия кэша, установка, офлайн-оболочка, обновление версии, iOS-специфика.
- `mobile-layout`: mobile-first адаптация — viewport, безопасные зоны, размеры touch-целей, адаптивная навигация, правила для форм и списков на телефоне.
- `frontend-app-shell`: структура проекта, Ant Design и провайдеры, роутинг, layout, страница-заглушка с проверкой `/health`, обёртка `Icon`, конфигурация окружения.
- `frontend-quality-gate`: lint, format, typecheck и тесты frontend в составе `make format|lint|test` и CI.

## Impact

- Новый каталог `frontend/` (npm, Node 24), новые dev- и runtime-зависимости только внутри него; основные: react, react-router, @tanstack/react-query, antd, lucide-react.
- Корневой `Makefile`: `format`, `lint`, `test` дополняются вызовами frontend; добавляются цели запуска dev-сервера.
- `.github/workflows/ci.yml`: job для frontend (без БД).
- `AGENTS.md`, `README.md`: раздел Frontend уточняется по итогам выбора инструментов.
- `frontend/public` (иконки, manifest, генерация иконок из SVG), `vite-plugin-pwa` и `@vite-pwa/assets-generator`.
- Backend: используются существующие `GET /health`, формат ошибок `{"detail": ...}` и `CORS_ORIGINS=http://localhost:5173`; изменений кода нет.

## Non-goals

- Экраны авторизации и бизнес-функций (появятся вместе с соответствующими backend-этапами).
- Реализация refresh-потока: в этом изменении только точка расширения, работающий refresh — задача 005.
- Docker-образ frontend и деплой.
- Собственная дизайн-система и брендовые палитры (используются светлый и тёмный алгоритмы antd с настройкой размеров под телефон).
- Офлайн-работа с данными: кэширование ответов API, очередь мутаций, фоновая синхронизация; push-уведомления.
- Нативные приложения и отдельная библиотека antd-mobile.
- Публикация в HTTPS-окружении и настройка домена (для PWA в проде нужен HTTPS — задача деплоя).
- E2E-тесты в браузере.
