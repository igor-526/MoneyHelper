## Why

Backend-капабилити категорий (`categories`, задача 009) и frontend-фундамент (`frontend-shell`, задача 013:
`IconPicker`, `EmptyState`, тип `Page<T>`) уже готовы и заархивированы, но пользователь до сих пор не может
управлять категориями доходов и расходов через интерфейс — раздел «Категории» не существует ни как экран, ни как
точка входа. Это второй из пяти оставшихся frontend-экранов (F2c дорожной карты) и прямая зависимость для операций
(016: без категорий нельзя создать доход/расход), поэтому он должен появиться сейчас, повторяя архитектуру уже
реализованного и заархивированного `frontend-wallets` (014) для почти идентичной по структуре сущности.

## What Changes

- Новый маршрут `/categories` в `app/routes.tsx` под `RequireAuth`, **без** нового пункта `navItems` (бюджет 5
  пунктов нижней панели уже занят решением 013 и зарезервирован под «Операции»/«Аналитику» 016/018). Точка входа —
  ссылка со страницы «Настройки» (`SettingsPage.tsx`), новая `Card title="Категории"` с кнопкой-ссылкой «Открыть».
- `features/categories/useCategories(type)` — hook на `useQuery`, читающий `GET /api/categories` одним запросом с
  максимальным `limit` (100) и опциональным query-параметром `type`, фильтр — часть `queryKey`
  (`["categories", type ?? "all"]"`), по образцу `useWallets` (014) с добавлением фильтра.
- `features/categories/useCreateCategory`, `useUpdateCategory`, `useDeleteCategory` — мутации на `useMutation`,
  инвалидирующие категорийный `queryKey` по префиксу на `onSuccess` (все варианты фильтра обновляются одним
  вызовом `invalidateQueries({ queryKey: ["categories"] })`).
- `features/categories/CategoryForm` — один компонент формы (тип, название, `IconPicker`), используемый и для
  создания, и для редактирования; открывается в `Drawer`/`Modal` поверх списка, без отдельного маршрута — по
  образцу `WalletForm` (014).
- `features/categories/CategoryCard` и `features/categories/CategoriesPage` — список карточек категорий (иконка,
  название, индикатор типа — `antd Tag`) с фильтром «доход / расход / все» (`antd Segmented`) в порядке, отданном
  backend; пустое состояние — `EmptyState` (`icon="coins"`) с кнопкой «Создать категорию».
- Обработка 409 при создании/редактировании (дубль названия в пределах типа) — **field-level**, по образцу
  `RegisterPage` (не по образцу `useDeleteWallet`): ошибка привязывается к полю `name` формы, а не показывается
  общим toast.
- Удаление категории — `Popconfirm`, 409 (категория с операциями) обрабатывается уже существующим глобальным
  обработчиком ошибок (`MESSAGE_BUILDERS.conflict`), без специального кода — по образцу `useDeleteWallet` (014).
- Тесты hooks и компонентов (`FakeApiClient`, по образцу существующих тестов `features/wallets`).

Backend, база данных и миграции Alembic **не затрагиваются**: используется уже готовый и заархивированный API
`categories` (009) без изменений контракта.

## Capabilities

### New Capabilities
- `frontend-categories`: экран управления категориями доходов и расходов пользователя (список с фильтром по типу,
  создание, редактирование, удаление) — точка входа со страницы «Настройки», список карточек с индикатором типа,
  форма в `Drawer`/`Modal`, обработка ошибок API по общим правилам `AGENTS.md`, включая field-level обработку
  конфликта имени в пределах типа.

## Impact

- Новые файлы только внутри `frontend/src/features/categories/` (страница, компоненты, hooks, типы, тесты рядом
  с кодом).
- Изменяются существующие файлы `frontend/src/app/routes.tsx` (новый маршрут `/categories` под `RequireAuth`, без
  изменений `navItems`) и `frontend/src/features/settings/SettingsPage.tsx` (новая `Card` — точка входа на
  `/categories`).
- Backend, база данных, миграции Alembic — **не затрагиваются вовсе**. Используется только уже существующий
  эндпоинт `/api/categories*` (`GET`/`POST`/`PUT`/`DELETE`, `CategoryOut`/`CategoryCreate`/`CategoryUpdate`,
  опциональный query-параметр `type` у списка).
- Новых npm-зависимостей не требуется: используются уже установленные `antd` (`Card`, `Tag`, `Segmented`,
  `Drawer`, `Modal`, `Popconfirm`, `Form`, `Input`, `Radio`), `@tanstack/react-query`, уже готовые `IconPicker`/
  `EmptyState` из `shared/ui` (013); иконка `"coins"` для пустого состояния уже есть в `BUSINESS_ICONS`
  (`shared/ui/icons.ts`), новая запись не заводится.

## Non-goals

- Иерархия категорий (родитель/подкатегория) — backend хранит плоский список, поддержки вложенности нет.
- Набор категорий по умолчанию для нового пользователя — backend не сидирует категории, экран остаётся пустым до
  первого создания пользователем (вне рамок и на backend, и здесь).
- Отдельный пункт нижней навигации «Категории» — бюджет 5 пунктов (013) занят и зарезервирован под «Операции»/
  «Аналитику» (016/018); точка входа — только ссылка со страницы «Настройки».
- Отдельные маршруты для форм создания/редактирования (`/categories/new` и т. п.) — форма открывается поверх
  списка в `Drawer`/`Modal`, не как отдельная страница.
- Серверная/клиентская постраничная пагинация в UI — список категорий загружается одним запросом с максимальным
  `limit`, персональный объём категорий пользователя мал.
