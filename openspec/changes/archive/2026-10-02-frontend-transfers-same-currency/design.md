## Context

033 разбила «Операции» на вкладки по таблице `OPERATION_KINDS`, но таблица жёстко привязана к форме
`Transaction` (тип категорий, `useList` страниц `Page<Transaction>`, `Form` с пропом `transaction`).
Перевод — другая сущность: нет категорий, у карточки «откуда → куда». Переводы по-прежнему на `/transfers` со ссылкой
«Переводы» (минимальная совместимость формы уже сделана в 033).

## Goals / Non-Goals

**Goals:**
- Переводы — третья вкладка «Перевод» без ветвлений по ключу вкладки.
- Перевод создаётся только между кошельками одной валюты; пустое состояние с пояснением; балансы обновляются.

**Non-Goals:**
- Изменения API и backend. Фильтр переводов по категории (его у переводов нет).

## Decisions

1. **Вкладка, а не маршрут.** Все движения денег в одном месте (по задаче 034). `/transfers` не удаляется, а
   становится `<Navigate to="/transactions?tab=transfer" replace />`: дешёвый способ не ломать закладки и ссылки.
   Ссылка «Переводы» на странице «Операции» удаляется — вкладка делает её лишней. Отдельного пункта навигации
   по-прежнему нет.
2. **`OperationKind` = описание вкладки.** `{ key, label, Panel: ComponentType }`; `TransactionsPage` строит `Tabs` из
   таблицы, рендеря `<kind.Panel />`. Пополнение и расход используют `Panel = ` обёртку над `OperationsTab` с
   конкретным `TransactionKind` (прежний набор полей: `categoryType`, `createLabel`, `emptyTitle`, `deleteTitle`,
   `useList`, `useDelete`, `Form`); вкладка перевода — `TransfersTab`. Новый вид операции — новая строка таблицы,
   без `if`. `OperationsTab` и `TransactionCard` принимают `TransactionKind`.
3. **Зависимость слоёв.** `features/transactions` импортирует `TransfersTab` из `features/transfers`; обратной
   зависимости нет (в `features/transfers` ключ кэша баланса по-прежнему локальная копия).
4. **`TransfersTab`** — содержимое прежней `TransfersPage` без заголовка `h3`; состояние фильтров/страницы локально,
   как у `OperationsTab` (при переключении вкладок Tabs не размонтирует панели, фильтры сохраняются).
5. **Пустое состояние формы.** Когда отправитель выбран и других кошельков его валюты нет, вместо предупреждающей
   строки показывается `Alert` (info) с текстом «Нет других кошельков в валюте RUB. Чтобы перевести деньги в
   другую валюту, пополните нужный кошелёк — конвертация делается через пополнение.»; поле «Куда» отключено, кнопка
   отправки отключена. Список «Откуда» остаётся полным (иначе пользователь не поймёт, почему кошелька нет).
6. **Инвалидация.** Три мутации переводов зовут общую `invalidateTransferCaches(queryClient, workspaceId)`:
   списки переводов + балансы кошельков (курсы и аналитика от переводов не зависят: перевод не меняет суммы пополнений
   и расходов). Локальный ключ баланса остаётся единственным местом дублирования.
7. **Элементы ≥ 44 px** обеспечивает глобальная тема antd (`controlHeight`), как в остальных формах.

## Risks / Trade-offs

- Вкладка «Перевод» остаётся с отдельным списком/фильтрами (кошелёк, даты) — единой ленты операций нет; это
  осознанно (разные ресурсы API).
- Редирект `/transfers` — устаревший маршрут, который можно удалить позже, когда закладки не важны.
