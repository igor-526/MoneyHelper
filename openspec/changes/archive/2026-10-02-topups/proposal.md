## Why

Валютная модель (024–035): пополнение — самостоятельный вид операции, а не «операция с несколькими ногами внутри
`/transactions`». Сумма пополнения всегда вводится в валюте воркспейса и в валюте кошелька (из пары ног выводится
курс); при совпадающих валютах достаточно одной ноги. Временная адаптация из `wallet-single-currency` (одна нога в
валюте кошелька) заменяется настоящим правилом.

## What Changes

- Новый ресурс `/api/workspaces/{workspace_id}/topups`: создание, чтение, список, полное обновление, удаление
  пополнений. Пополнение остаётся доходом: категория обязана быть типа `income`.
- Набор валют ног = `{валюта воркспейса, валюта кошелька}`: две ноги при разных валютах, одна — при совпадающих; иначе
  400. Стратегии проверки набора ног («одна валюта» / «две валюты») оформлены за протоколом `TopupLegsRule`.
- **BREAKING**: `POST /api/workspaces/{workspace_id}/transactions/topups` удалён (заменён на `POST .../topups`).
- **BREAKING**: `POST`/`PUT .../transactions` больше не принимают категорию типа `income` (400): доход создаётся
  только пополнением кошелька.
- **BREAKING**: ресурс `.../transactions` теперь отдаёт, читает, обновляет и удаляет только расходы (пополнение по
  `id` из этого ресурса — 404); параметр `type` списка удалён. Пополнения и расходы разделены для двух вкладок
  frontend (031–033).
- Валюта воркспейса читается через узкий протокол `WorkspaceCurrencyReader` (сервис пополнений знает только
  `workspace_id`).

## Capabilities

### New Capabilities

- `topups`: пополнения кошелька — создание, чтение, список, обновление, удаление; правило набора ног (валюта
  воркспейса + валюта кошелька), категория `income`, точность сумм, изоляция воркспейсов.

### Modified Capabilities

- `transactions`: ресурс только для расходов (отклонение категории `income`, список/чтение/обновление/удаление не
  затрагивают пополнения); требование «Пополнение многовалютного кошелька» удалено (перенесено в `topups`).

## Impact

- Backend: новые `core/services/topup.py`, `core/services/topup_legs.py`, `core/protocols/topup_legs_rule.py`,
  `core/protocols/repositories/workspace_currency_reader.py`, `api/topups.py`, `api/schemas/topup.py`,
  `depends/topup.py`; правки `TransactionService`, `api/transactions.py`, схем операций, `WorkspaceRepository`
  (+ `get_currency_id`), `main.py`.
- API: появляется `/api/workspaces/{id}/topups*`, меняется контракт `/transactions*`; frontend несовместим до
  задач 031–035 (по плану идут после backend).
- БД: схема не меняется (пополнение — это `transactions` + `transaction_legs` с категорией `income`).
- Тесты: unit (сервис, правила ног), api, smoke, infrastructure (чтение валюты воркспейса, изоляция воркспейсов).

## Вне рамок

- Расходы (027), переводы (028), расчёт курса (029), frontend.
