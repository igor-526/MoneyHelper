## ADDED Requirements

### Requirement: Тип денег
Денежные суммы SHALL представляться типом `Decimal` в `core`, `NUMERIC(24, 8)` в БД и строкой в JSON. Система MUST
NOT использовать `float` для сумм. Значения `NaN` и `Infinity`, а также значения с более чем 8 знаками после запятой
или более чем 24 значащими цифрами MUST быть отклонены валидацией.

#### Scenario: Сумма сериализуется строкой
- **WHEN** схема ответа содержит сумму `Decimal("12.50")`
- **THEN** в JSON она передаётся строкой `"12.50"`

#### Scenario: Сумма с лишними знаками отклоняется
- **WHEN** в запросе сумма `"1.123456789"`
- **THEN** запрос завершается ошибкой валидации с кодом 400

#### Scenario: Нечисловое значение отклоняется
- **WHEN** в запросе сумма `"NaN"` или `"Infinity"`
- **THEN** запрос завершается ошибкой валидации с кодом 400

### Requirement: Параметры пагинации
Списочные эндпоинты SHALL принимать `limit` (целое от 1 до 100, по умолчанию 20) и `offset` (целое не менее 0, по
умолчанию 0) через общую схему `PageParams`.

#### Scenario: Значения по умолчанию
- **WHEN** клиент не передаёт `limit` и `offset`
- **THEN** используются `limit=20` и `offset=0`

#### Scenario: Выход за границы
- **WHEN** клиент передаёт `limit=0`, `limit=101` или `offset=-1`
- **THEN** ответ имеет код 400 и тело `{"detail": [...]}`

### Requirement: Формат страницы ответа
Списочные эндпоинты SHALL возвращать общую схему `Page` с полями `items`, `total`, `limit` и `offset`, где `total` —
общее число записей без учёта пагинации.

#### Scenario: Ответ со страницей
- **WHEN** клиент запрашивает страницу списка
- **THEN** тело содержит `items` (не более `limit` элементов), `total`, `limit` и `offset`, совпадающие с запросом

### Requirement: Иерархия исключений и коды ответов
Бизнес-ошибки SHALL наследоваться от `AppError`, а обработчик в `main.py` MUST возвращать код, заданный в `status_code`
исключения, и тело `{"detail": <сообщение>}`. Система SHALL поддерживать как минимум коды: 400 (`ClientError`),
401 (`AuthenticationError`), 403 (`PermissionDeniedError`), 404 (`NotFoundError`), 409 (`AlreadyExistsError`).

#### Scenario: Ошибка аутентификации
- **WHEN** сервис бросает `AuthenticationError("Требуется вход")`
- **THEN** ответ имеет код 401 и тело `{"detail": "Требуется вход"}`

#### Scenario: Доступ запрещён
- **WHEN** сервис бросает `PermissionDeniedError`
- **THEN** ответ имеет код 403 и тело `{"detail": <сообщение>}`

#### Scenario: Ресурс не найден
- **WHEN** сервис бросает `NotFoundError`
- **THEN** ответ имеет код 404 и тело `{"detail": <сообщение>}`

### Requirement: Сериализуемые ошибки валидации
Ответ на ошибку валидации запроса SHALL иметь код 400 и тело `{"detail": [...]}`, которое MUST сериализоваться даже
если контекст ошибки содержит исключения.

#### Scenario: Ошибка из пользовательского валидатора
- **WHEN** валидатор поля бросает `ValueError`, и его экземпляр попадает в `ctx` ошибки
- **THEN** ответ имеет код 400, а не 500, и тело является корректным JSON

### Requirement: Необработанные исключения
Необработанное исключение SHALL приводить к ответу с кодом 500 и телом `{"detail": "Internal server error"}`, без
внутренних деталей. Исключение MUST быть записано в лог и отправлено в Sentry (при включённом Sentry).

#### Scenario: Неожиданная ошибка
- **WHEN** обработчик запроса бросает исключение, не являющееся `AppError`
- **THEN** ответ имеет код 500 и тело `{"detail": "Internal server error"}`

#### Scenario: Ошибка фиксируется
- **WHEN** обработчик запроса бросает необработанное исключение
- **THEN** исключение записано в лог и передано в `sentry_sdk.capture_exception`

### Requirement: Единый JSON-формат для всех ошибок
Все ответы с ошибками (400, 401, 403, 404, 405, 409, 500) SHALL иметь тело JSON с полем `detail`, чтобы frontend мог
показать уведомление по любой ошибке.

#### Scenario: Несуществующий маршрут
- **WHEN** клиент запрашивает несуществующий путь
- **THEN** ответ имеет код 404 и тело JSON с полем `detail`

#### Scenario: Неподдерживаемый метод
- **WHEN** клиент вызывает существующий путь неподдерживаемым методом
- **THEN** ответ имеет код 405 и тело JSON с полем `detail`
