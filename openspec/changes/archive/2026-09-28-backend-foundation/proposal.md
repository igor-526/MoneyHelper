## Why

Шаблон backend содержит только `/health`, базовую иерархию `AppError` и пустые пакеты слоёв. Все следующие задачи
(авторизация, валюты, кошельки, операции) опираются на общие соглашения и инфраструктуру, которых пока нет:
абстракции времени и идентификаторов, тип денег, единые контракты пагинации и ошибок, CORS для frontend на другом
origin и тестовая БД. Без них каждый этап изобретал бы своё, нарушая единообразие и SOLID. Делаем это сейчас, до
появления бизнес-кода, чтобы дальше только расширять.

## What Changes

- Добавить протоколы `Clock` и `IdGenerator` в `core/protocols` с боевыми реализациями и fake-реализациями для тестов;
  связать их в `depends/`.
- Зафиксировать соглашения API:
  - тип денег: `Decimal` в `core`, `NUMERIC` в БД, строка в JSON (без `float`);
  - пагинация: общие схемы запроса (`limit`/`offset`) и ответа (`items`, `total`, `limit`, `offset`);
  - формат ошибок: единое тело `{"detail": ...}`; расширить иерархию исключений (`AuthenticationError` 401,
    `PermissionDeniedError` 403, `NotFoundError` 404); исправить сериализацию ошибок валидации;
  - доставка ошибок до frontend: все ответы с ошибками (400, 401, 403, 404, 409, 500) возвращаются в формате JSON и
    с CORS-заголовками для разрешённого origin, включая 500 — frontend показывает по каждой ошибке уведомление (toast).
- Добавить настройку CORS: `CORS_ORIGINS` в `Settings` и `.env.example`, подключение middleware с
  `allow_credentials=true` и точным списком origin, запрет `*`.
- **BREAKING (для тестов шаблона):** заменить тест `test_template_runtime_has_no_cors_configuration_or_headers`
  тестами разрешённого и чужого origin.
- Добавить тестовую БД для `make test-infra`: отдельная база на инфраструктурном PostgreSQL, применение миграций
  Alembic, фикстуры сессии с откатом, пример infrastructure-теста.
- Чётко разделить тесты: `make test` (и просто `pytest`) по умолчанию работает без БД и подходит для CI на GitHub;
  тесты с БД лежат в `tests/infrastructure/`, получают маркер автоматически и запускаются только через `make test-infra`.
- Добавить workflow GitHub Actions: job `quality` (`make lint`, `make test`) без БД и job `infrastructure` с
  сервисным контейнером PostgreSQL (`make test-infra`).
- Унифицировать имя переменной БД: везде `POSTGRES_DB` (так называется переменная официального образа PostgreSQL
  и она уже используется backend); `POSTGRES_NAME` в конфигурации инфраструктуры переименовывается.
- Добавить вспомогательные fake-репозитории и базовые фикстуры для unit-тестов сервисов.
- Обновить `AGENTS.md` и `README.md` описанием соглашений.

Миграции Alembic не добавляются: схема БД не меняется (тип денег фиксируется в коде для будущих таблиц).

## Capabilities

### New Capabilities
- `runtime-providers`: протоколы и реализации `Clock` и `IdGenerator`, их fake-версии и подключение через `depends/`.
- `api-conventions`: тип денег, схемы пагинации, единый формат ошибок и иерархия исключений 401/403/404.
- `cors-policy`: настройка CORS для frontend на другом origin (список `CORS_ORIGINS`, credentials, запрет `*`).
- `test-infrastructure`: тестовая БД для infrastructure-тестов, откат транзакций, fake-репозитории для unit-тестов.

## Impact

- **Код:** `core/protocols`, `core/schemas` (пагинация, деньги), `core/exceptions`, `core/services` (без бизнес-логики),
  `depends/`, `utils/` (CORS, провайдеры), `settings.py`, `main.py`; `tests/` (заменённый CORS-тест, фикстуры, fakes).
- **API:** формат ошибок унифицируется, добавляются коды 401/403/404 в обработчик `AppError`; новых эндпоинтов нет.
- **БД:** новых таблиц нет, миграций нет; появляется отдельная тестовая база `*_test` в существующем PostgreSQL.
- **Конфигурация:** новые переменные `CORS_ORIGINS` и `TEST_POSTGRES_DB` в `.env.example`; переименование
  `POSTGRES_NAME` → `POSTGRES_DB` в `.docker-compose/.env` и `docker-compose.infra.yml`.
- **CI:** новый `.github/workflows/ci.yml`.
- **Зависимости:** новых runtime-зависимостей нет; для тестов используется уже установленный стек pytest/httpx2.
- **Документация:** `AGENTS.md`, `README.md`, `backend/README.md`; правило обработки ошибок и toast на frontend
  фиксируется в задаче 003.

## Вне рамок

- Пользователи, JWT, cookies, проверка `Origin` для CSRF (задача 005).
- Сидирование и валюты (задача 006), iconpack (007).
- Бизнес-сущности и таблицы кошельков, категорий, операций.
- Конкретная валидация точности сумм по знакам валюты (появится вместе с валютами и операциями).
- Rate limit, логирование запросов, observability сверх существующего Sentry.
- Реализация toast и обработки ошибок на frontend (задача 003); backend лишь гарантирует контракт ошибок.
- Автоматический деплой (в CI входит только проверка качества).
