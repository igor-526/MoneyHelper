## Context

После 024–029 backend реализует новую валютную модель; итоговые решения зафиксированы в архиве
`openspec/changes/archive/2026-10-02-*/design.md`. Поиск остатков старой модели (`currency_ids`,
`wallet_currencies`, «ноги по каждой валюте кошелька», «общая валюта» у переводов, баланс списком) показал: в
исполняемом коде и seed-данных их нет (таблица `wallet_currencies` упоминается только в миграциях 0004/0008/0010/0011
как история и откат). Остатки — в документации и в одном имени метода.

## Goals / Non-Goals

**Goals:**
- Документация и контекст OpenSpec описывают только действующую модель.
- Основные specs не противоречат поведению.
- Миграции 0010–0012 откатываются и накатываются на чистой БД.

**Non-Goals:**
- Изменение поведения, API, схемы БД; frontend; правка исторических задач и архива.

## Decisions

1. **Specs: правятся только Purpose.** Требования и сценарии `wallets`, `transactions`, `transfers`, `analytics`,
   `workspaces`, `topups` сверены с кодом и верны; устарели лишь вводные абзацы. Purpose не входит в требования,
   поэтому delta-specs не создаются, правка вносится прямо в основные specs.
2. **Frontend-specs не трогаем.** `frontend-wallets`, `frontend-transfers`, `frontend-shell` и др. описывают
   многовалютный UI; их обновляют задачи 031–035 вместе с кодом frontend.
3. **`config.yaml` context переписывается сжато.** Старый текст — хроника по задачам 003–012 с многовалютными
   деталями; новый описывает актуальные инварианты (воркспейсы, валютная модель, пополнения и курс, переводы,
   аналитика, баланс) без номеров устаревших таблиц.
4. **Переименование `get_currency_ids` → `get_currency_id_by_wallet`.** Словарь `wallet_id -> currency_id`; прежнее имя
   множественного числа наследует `currency_ids` кошелька. Альтернатива «оставить» отвергнута: имя вводит в
   заблуждение и совпадает с удалённым полем. Протокол `WalletCurrencyReader` остаётся узким.
5. **Миграции проверяются на отдельной временной БД** (`downgrade base` / `upgrade head` / `downgrade 0009` /
   `upgrade head`), БД разработки и тестовая `app_test` не затрагиваются; после проверки БД удаляется.

## Risks / Trade-offs

- Переименование затрагивает несколько файлов → закрывается mypy и тестами (unit + infrastructure).
- Историческая миграция 0004 по-прежнему создаёт `wallet_currencies` — это корректно: миграции неизменяемы.
