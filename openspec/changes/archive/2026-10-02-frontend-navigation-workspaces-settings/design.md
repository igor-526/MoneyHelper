## Context

После 023 управление воркспейсами переехало на «Главную» (`HealthPage`), рядом со статусом backend. Backend 024
сделал `currency_id` обязательным при `POST /api/workspaces` и необязательным в `PUT` (смена валюты запрещена с 409,
если в воркспейсе есть кошельки, операции или переводы; пока кошельков нет — разрешена). Список и чтение отдают
`currency_id`. Текущий воркспейс переключается только из «Настроек», поэтому пользователю нужно видеть, в каком
воркспейсе он находится, на любом экране.

## Goals / Non-Goals

**Goals:**
- Убрать `features/health` и «Главную»; `/` ведёт на «Кошельки».
- Управление воркспейсами в «Настройках», создание с обязательной валютой, показ валюты существующего.
- Видимый индикатор текущего воркспейса в оболочке на телефоне и на широком экране.

**Non-Goals:**
- Одновалютные кошельки, вкладки операций, аналитика с `display_currency` (032–035).
- Изменение backend.

## Decisions

### 1. Индикатор текущего воркспейса — `WorkspaceBadge` в оболочке

Компактная ссылка на `/settings` (в «Настройках» воркспейс и переключается): иконка `briefcase`, название (обрезается
с многоточием), тег с кодом валюты воркспейса. Высота ≥ 44 px. Один компонент, два места:
- широкий экран — в `Layout.Header` справа от меню (`margin-left: auto`);
- телефон — тонкая полоса над контентом внутри `MobileShell` (внутри `main`, в потоке, с отступом
  `safe-area-inset-top` от `.shell`), а не фиксированная шапка: нижняя панель уже занимает место, а полоса в потоке
  не перекрывает контент и не требует дополнительных отступов.

Альтернативы: выпадающий переключатель в шапке (отвергнуто: решение пользователя — переключение только из
«Настроек», лишний второй путь); пункт навигации (отвергнуто: лимит 5 пунктов, это не раздел); отдельный заголовок на
каждой странице (отвергнуто: дублирование во всех страницах).

Данные индикатора: `useCurrentWorkspace()` — `useWorkspaces()` + поиск по `useCurrentWorkspaceId()` (без нового
запроса, кэш общий с `RequireWorkspace`), код валюты — из `useCurrencies()`. Пока валюты не загружены или недоступны,
тег с валютой не показывается (название остаётся) — индикатор не должен ломать оболочку.

### 2. `/` → `/wallets` через `<Navigate replace>`

Индексный маршрут защищённого поддерева рендерит `<Navigate to="/wallets" replace />`. Редиректы после входа и
`GuestOnly` ведут на `/`, поэтому правки в auth не нужны. `NotFoundPage` ссылка «На главную» остаётся (ведёт на `/`,
дальше на «Кошельки»).

### 3. Валюта в `WorkspaceForm`

`Workspace` получает `currency_id`, `WorkspaceFormValues` — `name` и `currency_id`. Одна форма на создание и
редактирование (как сейчас):
- создание: `CurrencyPicker` (одиночный, из справочника), поле обязательное, `allowClear` не нужен — валидатор
  `required`;
- редактирование: поле валюты предзаполнено; блокируется, пока в воркспейсе есть кошельки (подсказка «Валюту нельзя
  изменить: в воркспейсе есть кошельки»). Наличие кошельков — запрос `GET /api/workspaces/{id}/wallets?limit=1`
  (`useWorkspaceHasWallets`, `total > 0`), включается только при открытой форме редактирования. Операции и переводы
  невозможны без кошельков, поэтому проверки кошельков достаточно; остаточный 409 backend показывается обычным toast
  (общее правило обработки ошибок).
- в `PUT` всегда отправляются оба поля (`name`, `currency_id`): совпадающая валюта — не изменение.
- 400 по полю `currency_id` привязывается к полю формы (`KNOWN_FIELDS`).

Экран `RequireWorkspace` без воркспейсов использует ту же форму, поэтому требует валюту автоматически.

### 4. Тестовые фикстуры

`DEFAULT_WORKSPACE` в `test/session.ts` получает `currency_id`; фикстуры в тестах воркспейсов — тоже.
Тесты, опиравшиеся на `/health`, переписываются: `sessionExpiry` использует иной обычный (не silent) запрос.

## Risks / Trade-offs

- [Полоса индикатора на телефоне отъедет вместе с прокруткой, т.к. не фиксирована] → осознанно: достаточно видеть при
  входе на экран; фиксированная шапка потребовала бы доп. отступов для всех страниц.
- [Проверка кошельков для не текущего воркспейса — отдельный запрос] → запрос лёгкий (`limit=1`) и только при
  открытой форме редактирования.
- [Одно стороннее поведение `NotFoundPage`: «На главную» проходит через редирект] → безвредно.
