## MODIFIED Requirements

### Requirement: Создание операции
`POST /api/workspaces/{workspace_id}/transactions` SHALL создавать операцию (доход или расход) с ровно одной
«ногой» (валюта + сумма) в указанном воркспейсе, принадлежащем текущему аутентифицированному пользователю, с
указанием кошелька, категории, валюты, положительной суммы и опционального комментария (`comment`, не более 1000
символов). `workspace_id` MUST принадлежать текущему пользователю. Кошелёк и категория MUST принадлежать указанному
воркспейсу. Валюта операции MUST входить в набор валют указанного кошелька. Число знаков после запятой суммы MUST
NOT превышать `decimal_places` валюты; округление не выполняется. `comment`, состоящий только из пробелов или не
переданный, SHALL сохраняться как отсутствующий (`null`), а не как пустая строка. `occurred_at` — опциональное
поле; при отсутствии SHALL использоваться текущее время сервера. Запрос без действительной сессии (без
access-cookie) SHALL быть отклонён с ошибкой аутентификации. Ответ представляет операцию в ногозависимой форме:
`legs` — список из одного элемента `{currency_id, amount}`, и включает `comment`.

#### Scenario: Успешное создание операции с указанной датой
- **WHEN** аутентифицированный пользователь отправляет `POST /api/workspaces/{workspace_id}/transactions` с
  корректными `wallet_id` (кошелька своего воркспейса), `category_id` (категории своего воркспейса), `currency_id`
  из набора валют кошелька, положительным `amount` с числом знаков не более `decimal_places` валюты и явным
  `occurred_at`
- **THEN** ответ 201 содержит созданную операцию с этим `id`, `wallet_id`, `category_id`, `legs` (список из одного
  элемента с этими `currency_id` и `amount`), `occurred_at` (равным переданному), `created_at` и `updated_at`

#### Scenario: Успешное создание операции без даты — используется текущее время
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит операцию с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Отклонение валюты, не входящей в набор валют кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `currency_id`, отсутствующим в
  `currency_ids` указанного кошелька
- **THEN** ответ 400 с понятным сообщением, операция не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `amount`, число знаков после запятой
  которого превышает `decimal_places` валюты `currency_id`
- **THEN** ответ 400, операция не создаётся, сумма не округляется

#### Scenario: Отклонение неположительной суммы
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `amount`, равным нулю или отрицательным
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `wallet_id`, которого нет в указанном
  воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующей или чужой категории
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `category_id`, которой нет в указанном
  воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `workspace_id`, которого нет ни у одного
  пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен без действительного access-cookie
- **THEN** ответ 401, операция не создаётся

#### Scenario: Успешное создание операции с комментарием
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с непустым `comment` (не более 1000
  символов)
- **THEN** ответ 201 содержит операцию с этим `comment`

#### Scenario: Пробельный комментарий сохраняется как отсутствующий
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `comment`, состоящим только из пробелов
- **THEN** ответ 201 содержит операцию с `comment = null`

#### Scenario: Операция без комментария
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен без поля `comment`
- **THEN** ответ 201 содержит операцию с `comment = null`

#### Scenario: Отклонение слишком длинного комментария
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions` отправлен с `comment` длиннее 1000 символов
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

### Requirement: Чтение одной операции
`GET /api/workspaces/{workspace_id}/transactions/{transaction_id}` SHALL возвращать операцию по `id`, только если
и операция принадлежит указанному воркспейсу, и воркспейс принадлежит текущему аутентифицированному пользователю.
Ответ представляет операцию в ногозависимой форме: `legs` — список из одного элемента `{currency_id, amount}` для
обычной операции или из нескольких элементов для пополнения; по числу элементов `legs` пополнение отличимо от
обычной операции, отдельного признака типа нет. Ответ включает `comment` (`null`, если комментарий не задан).

#### Scenario: Успешное чтение своей операции
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для операции своего воркспейса
- **THEN** ответ 200 содержит `id`, `wallet_id`, `category_id`, `legs`, `comment`, `occurred_at`, `created_at`,
  `updated_at`

#### Scenario: Чтение пополнения возвращает все его ноги
- **WHEN** аутентифицированный пользователь запрашивает `GET
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для своего пополнения с несколькими валютами
- **THEN** ответ 200 содержит `legs` со всеми ногами пополнения, отсортированными по коду валюты

#### Scenario: Несуществующая операция
- **WHEN** запрашивается `GET /api/workspaces/{workspace_id}/transactions/{transaction_id}` с `transaction_id`,
  которого нет в указанном воркспейсе
- **THEN** ответ 404

### Requirement: Полное обновление операции
`PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` SHALL полностью заменять `wallet_id`,
`category_id`, `currency_id`, `amount`, `occurred_at` и `comment` операции, принадлежащей указанному воркспейсу
текущего аутентифицированного пользователя, с той же валидацией, что и при создании (включая нормализацию
пробельного `comment` в `null` и ограничение длины). Результат всегда содержит ровно одну ногу — `PUT` не
поддерживает многовалютные операции (пополнение с несколькими ногами нельзя отредактировать через `PUT`; изменить
его можно только удалением через `DELETE /api/workspaces/{workspace_id}/transactions/{transaction_id}` и созданием
заново через `POST /api/workspaces/{workspace_id}/transactions/topups`). Частичное обновление (`PATCH`) не
поддерживается — отсутствие `comment` в теле `PUT` заменяет существующий комментарий на `null`, как и любое другое
опущенное поле было бы отклонено валидацией (все поля `PUT` обязательны, кроме `comment`).

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для операции своего воркспейса с новыми
  корректными `wallet_id`, `category_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит операцию с `legs` — списком из одного элемента с обновлёнными `currency_id`/
  `amount`, и обновлённым `updated_at`

#### Scenario: Обновление несуществующей операции
- **WHEN** `PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен с `transaction_id`,
  которого нет в указанном воркспейсе
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен с валютой, не входящей в
  набор валют кошелька, неположительной суммой, суммой с превышением знаков валюты, либо несуществующим/чужим
  `wallet_id` или `category_id`
- **THEN** ответ 400 или 404 (в зависимости от причины), изменения не применяются

#### Scenario: Полная замена превращает пополнение в операцию с одной ногой
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для своего пополнения (ранее имевшего несколько
  ног) с новыми корректными `wallet_id`, `category_id`, `currency_id`, `amount` и `occurred_at`
- **THEN** ответ 200 содержит операцию с `legs` — списком ровно из одного элемента; прежние ноги пополнения
  заменены полностью

#### Scenario: Изменение комментария существующей операции
- **WHEN** аутентифицированный пользователь отправляет `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` для своей операции с новым `comment`
- **THEN** ответ 200 содержит операцию с обновлённым `comment`

#### Scenario: Удаление комментария полной заменой
- **WHEN** операция ранее имела непустой `comment`, и `PUT
  /api/workspaces/{workspace_id}/transactions/{transaction_id}` отправлен без поля `comment`
- **THEN** ответ 200 содержит операцию с `comment = null`

### Requirement: Пополнение многовалютного кошелька
`POST /api/workspaces/{workspace_id}/transactions/topups` SHALL создавать операцию пополнения — доход, в указанном
воркспейсе, принадлежащем текущему аутентифицированному пользователю, с несколькими «ногами» (валюта + сумма),
одной на каждую валюту указанного кошелька, и опциональным комментарием (`comment`, не более 1000 символов, с той
же нормализацией пробельного значения в `null`, что и у обычной операции). `workspace_id` MUST принадлежать
текущему пользователю. Кошелёк и категория MUST принадлежать указанному воркспейсу. Категория MUST иметь тип
`income`. Набор валют переданных ног MUST совпадать ровно с набором валют кошелька (`wallet.currency_ids`) — без
отсутствующих, без лишних, без повторов. Каждая сумма MUST быть положительной, число знаков после запятой MUST NOT
превышать `decimal_places` соответствующей валюты; округление не выполняется. Курс между валютами пополнения не
хранится отдельным полем — воспроизводим как отношение сохранённых сумм ног. `occurred_at` — опциональное поле;
при отсутствии SHALL использоваться текущее время сервера. Запрос без действительной сессии (без access-cookie)
SHALL быть отклонён с ошибкой аутентификации.

#### Scenario: Успешное пополнение с полным набором валют кошелька
- **WHEN** аутентифицированный пользователь отправляет `POST
  /api/workspaces/{workspace_id}/transactions/topups` с `wallet_id` своего многовалютного кошелька в этом
  воркспейсе, `category_id` своей категории типа `income` в этом же воркспейсе и `legs`, содержащими ровно по
  одной ноге на каждую валюту кошелька с положительными суммами без превышения знаков после запятой
- **THEN** ответ 201 содержит созданную операцию с этим `id`, `wallet_id`, `category_id`, `legs` (все переданные
  валюты и суммы, отсортированные по коду валюты), `occurred_at`, `created_at` и `updated_at`

#### Scenario: Успешное пополнение без даты — используется текущее время
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен без поля `occurred_at`
- **THEN** ответ 201 содержит операцию с `occurred_at`, равным текущему времени сервера на момент создания

#### Scenario: Курс воспроизводим по сохранённым ногам
- **WHEN** пополнение создано с ногами, например, 10 000 в одной валюте и 780 в другой
- **THEN** после создания курс между этими валютами вычислим как отношение сохранённых сумм ног (10 000 / 780) без
  отдельно хранимого значения курса

#### Scenario: Отклонение пополнения с неполным набором валют
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен для многовалютного кошелька с
  `legs`, не содержащими ногу хотя бы для одной из валют кошелька
- **THEN** ответ 400 с сообщением, перечисляющим отсутствующие валюты, операция не создаётся

#### Scenario: Отклонение пополнения с избыточным набором валют
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `legs`, содержащими валюту,
  отсутствующую в наборе валют указанного кошелька
- **THEN** ответ 400 с сообщением, перечисляющим лишние валюты, операция не создаётся

#### Scenario: Отклонение пополнения с повторяющейся валютой в ногах
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `legs`, содержащими одну и ту же
  валюту более одного раза
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение пополнения с категорией не типа income
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `category_id` категории типа
  `expense`
- **THEN** ответ 400 с понятным сообщением, операция не создаётся

#### Scenario: Отклонение неположительной суммы в ноге пополнения
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с хотя бы одной ногой, у которой
  `amount` равен нулю или отрицателен
- **THEN** ответ 400 с ошибкой валидации, операция не создаётся

#### Scenario: Отклонение суммы с превышением числа знаков валюты в ноге пополнения
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с хотя бы одной ногой, у которой
  число знаков после запятой `amount` превышает `decimal_places` соответствующей валюты
- **THEN** ответ 400, операция не создаётся, сумма не округляется

#### Scenario: Отклонение несуществующего или чужого кошелька
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `wallet_id`, которого нет в
  указанном воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующей или чужой категории
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `category_id`, которой нет в
  указанном воркспейсе
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отклонение несуществующего или чужого воркспейса
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с `workspace_id`, которого нет ни у
  одного пользователя, либо принадлежащим другому пользователю
- **THEN** ответ 404, операция не создаётся

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен без действительного access-cookie
- **THEN** ответ 401, операция не создаётся

#### Scenario: Успешное пополнение с комментарием
- **WHEN** `POST /api/workspaces/{workspace_id}/transactions/topups` отправлен с непустым `comment` (не более 1000
  символов)
- **THEN** ответ 201 содержит пополнение с этим `comment`
