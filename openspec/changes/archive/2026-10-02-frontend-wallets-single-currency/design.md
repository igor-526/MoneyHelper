## Context

Backend 025/029 изменил контракты: кошелёк `{id, name, icon, currency_id, ...}`; `GET .../balances` —
`{currency_id, balance}`; `GET .../rates` — без параметров, ответ
`{workspace_currency_id, wallet_currency_id, rate: string | null}` (`rate = "1"` при совпадении валют, `null` — нет
пополнений с обеими ногами). Смена `currency_id` кошелька с операциями/переводами — 409 с `detail`.
Задачи 033–035 переделывают операции, переводы и курс; здесь — кошельки и минимальная совместимость.

## Goals / Non-Goals

**Goals:**
- Создание и редактирование кошелька с одной валютой; баланс одной суммой.
- Приложение не падает на экранах, зависящих от нового контракта кошелька.

**Non-Goals:**
- Вкладки «Пополнение»/«Расход» (033), переводы одной валюты (034), `WalletRateCard` и аналитика (035).

## Decisions

1. **Типы без маппинга.** `Wallet.currency_id: string`, `WalletFormValues.currency_id: string` (форма ответа
   backend, как и раньше).

2. **Блокировка смены валюты — по 409, без признака.** В ответе кошелька признака «есть операции» нет; отдельный
   запрос ради блокировки поля лишний (и не атомарен). Поле валюты в режиме редактирования остаётся активным, при
   409 форма остаётся открытой, под полем `currency_id` показывается `detail` backend, и дополнительно toast.
   Реализация: `apiError.kind === "conflict"` в `onError` формы (`KNOWN_FIELDS` и `applyFieldErrors` для 400 —
   как раньше). Альтернатива «предварительно блокировать» отвергнута — требует нового поля/запроса на backend.

3. **`CurrencyPicker` одиночный.** Используется существующий режим `multiple: false`; режим `multiple` остаётся
   (другие потребители/тесты), не удаляется. Правило формы — `required` с сообщением «Выберите валюту».

4. **`WalletCard`.** Принимает `currencyCode?: string` и показывает один `Tag`; `WalletsPage` находит код по
   `wallet.currency_id`.

5. **Баланс.** `WalletBalance` остаётся `{currency_id, balance}`, но хук возвращает один объект (не массив);
   `WalletBalanceCard` показывает `CODE: сумма` одной строкой.

6. **Минимальная совместимая правка курса (до 035).** `useWalletRates(walletId)` — без `target_currency_id` и
   `enabled`, тип `WalletRates = {workspace_currency_id, wallet_currency_id, rate: string | null}`.
   `WalletRateCard(wallet, currencyCodeById)`: не рендерится, если `rate === null` (нет данных) или ответ — ошибка;
   иначе одна строка «1 {код кошелька} ≈ {rate} {код воркспейса}»; при совпадении валют (`rate = "1"`, валюты
   равны) карточка скрыта. Только чтобы страница «Операции»/«Кошельки» не падала; дизайн карточки — задача 035.

7. **Минимальная совместимая правка форм 033/034.** `TransactionForm`: `allowedIds={[wallet.currency_id]}`;
   `TopupForm`: список валют кошелька — `[wallet.currency_id]` (пополнение в двух валютах — 033);
   `TransferForm`: общие валюты — `[currency_id]`, если у кошельков она совпадает, иначе пусто (правило 034).
   Никакого нового поведения, только замена источника данных.

## Risks / Trade-offs

- Форма пополнения/перевода временно работает по старому контракту backend-эндпоинтов (backend 026/028 уже
  ожидают иное) → допускаем временно, устраняется в 033/034.
- Без предварительной блокировки пользователь узнаёт о запрете после отправки → понятное сообщение из `detail`.

## Итоги проверки

- Браузер (временная БД): воркспейс RUB, кошелёк с валютой CNY создан и отредактирован; смена валюты кошелька с
  пополнением даёт 409 — сообщение у поля и toast; баланс «CNY: 90.00000000» одной суммой; карточка курса работает
  по новому контракту; на 390 px нет горизонтальной прокрутки, цели 44 px, форма — нижний `Drawer`.
- Устаревшие пропсы antd в `WalletForm` (`destroyOnClose`, `height` у `Drawer`) заменены на `destroyOnHidden`/`size`;
  те же предупреждения остаются в других формах (категории, операции, переводы, воркспейсы) — вне объёма.
- Операции со списком `/transactions` не показывают пополнения (backend 026 вынес их в `/topups`) — задача 033.
