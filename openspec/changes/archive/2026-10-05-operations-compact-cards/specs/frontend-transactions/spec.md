## MODIFIED Requirements

### Requirement: Список операций с фильтрами
Каждая вкладка экрана `/transactions` SHALL загружать свой список текущего воркспейса: «Пополнение» —
`GET /api/workspaces/{workspace_id}/topups`, «Расход» — `GET /api/workspaces/{workspace_id}/transactions`, с
фильтрами: кошелёк (`wallet_id`), категория (`category_id`, в списке только категории типа вкладки), диапазон дат
(`date_from`/`date_to`). Фильтра типа нет. Каждая операция SHALL отображаться компактной карточкой из двух строк:
в первой — иконка и название категории и сумма с кодом валюты по каждой ноге (одна сумма при одной ноге, по сумме
на валюту при двух); во второй — название кошелька, дата и комментарий, если он задан. На карточке SHALL не быть
кнопок действий: нажатие на карточку открывает форму редактирования. Порядок карточек — как вернул backend.

#### Scenario: Загрузка списка
- **WHEN** вкладка только что открыта
- **THEN** отображается индикатор загрузки, пока ответ списка не получен

#### Scenario: Список получен и не пуст
- **WHEN** список вернул одну или несколько операций
- **THEN** каждая отображается карточкой с кошельком, иконкой и названием категории, суммами с кодами валют и
  датой, в порядке ответа, без кнопок «Редактировать» и «Удалить»

#### Scenario: Пополнение с двумя ногами
- **WHEN** в списке пополнений есть пополнение кошелька другой валюты
- **THEN** карточка показывает две суммы «сумма код»

### Requirement: Редактирование операции
Вкладка «Расход» SHALL позволять отредактировать расход, нажав на его карточку: открывается та же форма,
предзаполненная кошельком, категорией, суммой, датой и комментарием; `PUT /api/workspaces/{workspace_id}/transactions/{id}`;
после успеха карточка обновляется без перезагрузки.

#### Scenario: Открытие формы редактирования
- **WHEN** пользователь нажимает на карточку расхода (мышью, касанием или клавишами Enter/Space)
- **THEN** форма открыта с текущими значениями

#### Scenario: Успешное редактирование
- **WHEN** пользователь меняет данные и отправляет форму
- **THEN** выполняется `PUT`, форма закрывается, карточка показывает новые данные, показан toast

#### Scenario: Изменение и очистка комментария
- **WHEN** пользователь меняет или очищает комментарий и отправляет форму
- **THEN** `PUT` содержит новый `comment` либо не содержит его; карточка отражает изменение

### Requirement: Удаление операции
Форма редактирования расхода SHALL содержать кнопку «Удалить» с подтверждением (`Popconfirm`); в форме создания её
нет. `DELETE /api/workspaces/{workspace_id}/transactions/{id}` убирает карточку без перезагрузки, форма закрывается.

#### Scenario: Успешное удаление
- **WHEN** пользователь в форме редактирования подтверждает удаление
- **THEN** выполняется `DELETE`, форма закрывается, карточка исчезает

#### Scenario: Отмена удаления
- **WHEN** пользователь отменяет подтверждение
- **THEN** запрос не выполняется, форма остаётся открытой, карточка остаётся

#### Scenario: Форма создания без удаления
- **WHEN** пользователь открывает форму создания расхода
- **THEN** кнопки «Удалить» в форме нет

#### Scenario: Баланс обновляется после изменений
- **WHEN** карточка баланса отображается и пользователь создаёт, редактирует или удаляет расход этого кошелька
- **THEN** баланс перезапрашивается и показывает актуальную сумму

### Requirement: Создание, редактирование и удаление пополнения
Вкладка «Пополнение» SHALL позволять создать пополнение формой (`Drawer` на телефоне, `Modal` на широком экране):
кошелёк, суммы, категория только типа «доход», необязательные дата и комментарий (до 1000 символов). Поля сумм SHALL
строиться по валютам `{валюта воркспейса, валюта выбранного кошелька}`: два поля («Сумма (КОД)» на каждую), если
валюты различаются, и одно, если совпадают. Смена кошелька SHALL сбрасывать введённые суммы. Создание —
`POST /api/workspaces/{workspace_id}/topups` с ногами по каждой валюте; редактирование открывается нажатием на
карточку пополнения, той же формой, предзаполненной ногами, комментарием и датой, через `PUT .../topups/{id}`;
удаление — кнопка «Удалить» с `Popconfirm` в форме редактирования, `DELETE .../topups/{id}`. После успеха список
обновляется без перезагрузки.

#### Scenario: Кошелёк в валюте воркспейса — одно поле суммы
- **WHEN** выбран кошелёк с валютой воркспейса
- **THEN** форма показывает одно поле суммы, запрос содержит одну ногу

#### Scenario: Кошелёк в другой валюте — два поля суммы
- **WHEN** выбран кошелёк с валютой, отличной от валюты воркспейса
- **THEN** форма показывает два поля суммы (валюта воркспейса и валюта кошелька), запрос содержит две ноги

#### Scenario: Смена кошелька сбрасывает суммы
- **WHEN** пользователь ввёл суммы, затем сменил кошелёк
- **THEN** суммы сброшены, поля перестроены под новый кошелёк

#### Scenario: Категории только доходные
- **WHEN** пользователь открывает выбор категории в форме пополнения
- **THEN** доступны только категории типа «доход»

#### Scenario: Ошибка валидации
- **WHEN** backend отвечает 400 с сообщениями по полям `wallet_id`, `category_id`, `comment` или текстом об
  отсутствующей, лишней или повторяющейся валюте
- **THEN** форма остаётся открытой, известные поля показывают сообщения, остальные тексты показываются toast

#### Scenario: Редактирование пополнения
- **WHEN** пользователь нажимает на карточку пополнения, меняет суммы и отправляет форму
- **THEN** выполняется `PUT .../topups/{id}`, форма закрывается, карточка показывает новые суммы

#### Scenario: Удаление пополнения
- **WHEN** пользователь в форме редактирования подтверждает удаление пополнения
- **THEN** выполняется `DELETE .../topups/{id}`, форма закрывается, карточка исчезает; отмена запрос не выполняет

### Requirement: Вкладки операций
Экран `/transactions` SHALL быть разделён на три вкладки — «Расход», «Пополнение» и «Перевод» (в этом порядке, по
умолчанию «Расход»), заданные таблицей конфигурации `OPERATION_KINDS` (ключ, подпись, компонент содержимого), а не
ветвлением по ключу. Ключи вкладок: `expense`, `topup`, `transfer`. Активная вкладка SHALL отражаться в
query-параметре `tab`; неизвестное значение открывает вкладку по умолчанию. Каждая вкладка SHALL иметь собственный
список, фильтры, пагинацию, кнопку создания, редактирование и удаление; фильтры вкладки SHALL сохраняться при
переключении вкладок. Элементы управления SHALL быть не менее 44 px по высоте, формы на телефоне — в нижнем `Drawer`.

#### Scenario: Вкладка по умолчанию
- **WHEN** пользователь открывает `/transactions`
- **THEN** активна вкладка «Расход», выполняется `GET /api/workspaces/{workspace_id}/transactions`

#### Scenario: Переключение на вкладку «Пополнение»
- **WHEN** пользователь выбирает вкладку «Пополнение»
- **THEN** выполняется `GET /api/workspaces/{workspace_id}/topups`, адрес содержит `tab=topup`, показан список
  пополнений со своими фильтрами

#### Scenario: Переключение на вкладку «Перевод»
- **WHEN** пользователь выбирает вкладку «Перевод»
- **THEN** выполняется `GET /api/workspaces/{workspace_id}/transfers`, адрес содержит `tab=transfer`, показан список
  переводов

#### Scenario: Вкладка из адреса
- **WHEN** пользователь открывает `/transactions?tab=transfer`
- **THEN** сразу активна вкладка «Перевод»

#### Scenario: Фильтры вкладки сохраняются
- **WHEN** пользователь задал фильтр на вкладке «Расход», перешёл на другую вкладку и вернулся
- **THEN** фильтр вкладки «Расход» сохранён
