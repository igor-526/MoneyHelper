## ADDED Requirements

### Requirement: Создание категории
`POST /api/categories` SHALL создавать категорию, принадлежащую текущему аутентифицированному пользователю, с
типом (`income` или `expense`), названием и иконкой из реестра допустимых имён. Название категории MUST быть
уникальным в пределах пары «пользователь + тип». Запрос без действительной сессии (без access-cookie) SHALL быть
отклонён с ошибкой аутентификации.

#### Scenario: Успешное создание категории дохода
- **WHEN** аутентифицированный пользователь отправляет `POST /api/categories` с `type = "income"`, корректным
  `name` и допустимым `icon`
- **THEN** ответ 201 содержит созданную категорию с этим `id`, `type`, `name`, `icon`, `created_at` и `updated_at`

#### Scenario: Успешное создание категории расхода
- **WHEN** аутентифицированный пользователь отправляет `POST /api/categories` с `type = "expense"`, корректным
  `name` и допустимым `icon`
- **THEN** ответ 201 содержит созданную категорию с `type = "expense"`

#### Scenario: Отклонение пустого названия
- **WHEN** `POST /api/categories` отправлен с `name`, состоящим только из пробелов или пустой строкой
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение неизвестной иконки
- **WHEN** `POST /api/categories` отправлен с `icon`, отсутствующим в реестре допустимых имён иконок
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение невалидного типа
- **WHEN** `POST /api/categories` отправлен с `type`, отличным от `income` и `expense`
- **THEN** ответ 400 с ошибкой валидации, категория не создаётся

#### Scenario: Отклонение дубля названия в пределах того же типа
- **WHEN** у пользователя уже есть категория с типом `income` и названием «Зарплата», и он отправляет
  `POST /api/categories` с тем же `type = "income"` и тем же `name = "Зарплата"`
- **THEN** ответ 409, вторая категория не создаётся

#### Scenario: Одинаковое название допустимо для разных типов
- **WHEN** у пользователя уже есть категория с типом `income` и названием «Прочее», и он отправляет
  `POST /api/categories` с `type = "expense"` и тем же `name = "Прочее"`
- **THEN** ответ 201, обе категории существуют одновременно

#### Scenario: Отказ без аутентификации
- **WHEN** `POST /api/categories` отправлен без действительного access-cookie
- **THEN** ответ 401, категория не создаётся

### Requirement: Список категорий пользователя с фильтром по типу
`GET /api/categories` SHALL возвращать постраничный список категорий, принадлежащих только текущему
аутентифицированному пользователю, отсортированный по `created_at` по возрастанию, затем по `id` как
детерминированному tie-breaker. Опциональный query-параметр `type` SHALL ограничивать список категориями только
указанного типа; при отсутствии параметра список SHALL содержать категории обоих типов. Параметры пагинации —
`limit` (1..100, по умолчанию 20) и `offset` (≥ 0, по умолчанию 0).

#### Scenario: Список содержит только категории текущего пользователя
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/categories`, при этом в системе есть категории,
  принадлежащие другим пользователям
- **THEN** ответ 200 содержит только категории текущего пользователя, `total` равен числу его категорий

#### Scenario: Список без фильтра содержит категории обоих типов
- **WHEN** у пользователя есть категории и типа `income`, и типа `expense`, и он запрашивает `GET /api/categories`
  без параметра `type`
- **THEN** ответ 200 содержит категории обоих типов

#### Scenario: Фильтр по типу возвращает только категории этого типа
- **WHEN** у пользователя есть категории обоих типов, и он запрашивает `GET /api/categories?type=income`
- **THEN** ответ 200 содержит только категории с `type = "income"`, `total` равен числу категорий этого типа у
  пользователя

#### Scenario: Порядок списка детерминирован
- **WHEN** у пользователя есть несколько категорий
- **THEN** ответ 200 возвращает их отсортированными по `created_at` по возрастанию, а при равном `created_at` — по
  `id` по возрастанию

#### Scenario: Пагинация по умолчанию
- **WHEN** `GET /api/categories` запрошен без параметров `limit`/`offset`
- **THEN** ответ 200 использует `limit = 20`, `offset = 0`

#### Scenario: Недопустимые параметры пагинации отклоняются
- **WHEN** `GET /api/categories` запрошен с `limit` вне диапазона 1..100 или с отрицательным `offset`
- **THEN** ответ 400 с ошибкой валидации

### Requirement: Чтение одной категории
`GET /api/categories/{category_id}` SHALL возвращать категорию по `id`, только если она принадлежит текущему
аутентифицированному пользователю.

#### Scenario: Успешное чтение своей категории
- **WHEN** аутентифицированный пользователь запрашивает `GET /api/categories/{category_id}` для своей категории
- **THEN** ответ 200 содержит `id`, `type`, `name`, `icon`, `created_at`, `updated_at`

#### Scenario: Несуществующая категория
- **WHEN** запрашивается `GET /api/categories/{category_id}` с `category_id`, которого нет ни у одного
  пользователя
- **THEN** ответ 404

### Requirement: Полное обновление категории
`PUT /api/categories/{category_id}` SHALL полностью заменять `type`, `name` и `icon` категории, принадлежащей
текущему аутентифицированному пользователю. Частичное обновление (`PATCH`) не поддерживается. Уникальность
`name` в пределах пары «пользователь + тип» MUST соблюдаться и при обновлении.

#### Scenario: Успешная полная замена
- **WHEN** аутентифицированный пользователь отправляет `PUT /api/categories/{category_id}` для своей категории с
  новыми корректными `type`, `name` и `icon`
- **THEN** ответ 200 содержит категорию с обновлёнными значениями и обновлённым `updated_at`

#### Scenario: Обновление несуществующей категории
- **WHEN** `PUT /api/categories/{category_id}` отправлен с `category_id`, которого нет ни у одного пользователя
- **THEN** ответ 404, изменения не применяются

#### Scenario: Обновление с той же валидацией входных данных, что и создание
- **WHEN** `PUT /api/categories/{category_id}` отправлен с пустым `name`, неизвестным `icon` либо невалидным `type`
- **THEN** ответ 400, изменения не применяются

#### Scenario: Конфликт уникальности при переименовании в занятое имя
- **WHEN** у пользователя есть категории A и B одного типа, и он отправляет `PUT /api/categories/{category_id}`
  для категории A с `name`, совпадающим с текущим названием категории B того же типа
- **THEN** ответ 409, категория A не изменяется

### Requirement: Удаление категории
`DELETE /api/categories/{category_id}` SHALL физически удалять категорию, принадлежащую текущему
аутентифицированному пользователю, безусловно (без проверки связанных данных — операции вне рамок этого
требования).

#### Scenario: Успешное удаление
- **WHEN** аутентифицированный пользователь отправляет `DELETE /api/categories/{category_id}` для своей категории
- **THEN** ответ 204, категория удалена; последующий `GET /api/categories/{category_id}` для того же `id`
  возвращает 404

#### Scenario: Удаление несуществующей категории
- **WHEN** `DELETE /api/categories/{category_id}` отправлен с `category_id`, которого нет ни у одного пользователя
- **THEN** ответ 404

### Requirement: Изоляция данных по владельцу
Каждый эндпоинт, оперирующий конкретной категорией (`GET`, `PUT`, `DELETE /api/categories/{category_id}`), SHALL
проверять принадлежность категории текущему аутентифицированному пользователю на уровне запроса к данным (не
отдельной проверкой после чтения). Категория, принадлежащая другому пользователю, MUST быть неотличима снаружи от
несуществующей: в обоих случаях SHALL возвращаться 404, а не 403.

#### Scenario: Чужая категория недоступна для чтения
- **WHEN** пользователь A запрашивает `GET /api/categories/{category_id}` с `category_id` категории, принадлежащей
  пользователю B
- **THEN** ответ 404, а не 403; данные категории B не раскрываются

#### Scenario: Чужая категория недоступна для обновления
- **WHEN** пользователь A отправляет `PUT /api/categories/{category_id}` с `category_id` категории, принадлежащей
  пользователю B
- **THEN** ответ 404, категория B не изменяется

#### Scenario: Чужая категория недоступна для удаления
- **WHEN** пользователь A отправляет `DELETE /api/categories/{category_id}` с `category_id` категории,
  принадлежащей пользователю B
- **THEN** ответ 404, категория B не удаляется

#### Scenario: Список одного пользователя не содержит категорий другого
- **WHEN** пользователь A запрашивает `GET /api/categories`, при этом у пользователя B есть категории с
  названиями, совпадающими с названиями категорий пользователя A
- **THEN** ответ 200 содержит только категории пользователя A, создание одноимённой категории у пользователя A не
  конфликтует с одноимённой категорией пользователя B
