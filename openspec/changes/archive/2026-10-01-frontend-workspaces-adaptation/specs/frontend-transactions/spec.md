## MODIFIED Requirements

### Requirement: Маршрут и точка входа раздела «Операции»
Маршрут `/transactions` SHALL быть доступен только авторизованному пользователю с выбранным текущим воркспейсом
(под `RequireAuth`, затем `RequireWorkspace`, тем же поддеревом маршрутов, что и остальные разделы приложения).
Раздел `navItems` SHALL содержать пункт «Операции», ведущий на `/transactions`, расположенный между пунктом
«Кошельки» и пунктом «Настройки».

#### Scenario: Пункт навигации виден и ведёт на раздел операций
- **WHEN** авторизованный пользователь просматривает навигацию приложения (нижнюю панель на телефоне, верхнее меню
  на широком экране)
- **THEN** среди пунктов навигации между «Кошельки» и «Настройки» отображается пункт «Операции», переход по нему
  открывает `/transactions`

#### Scenario: Переход по прямой ссылке без авторизации
- **WHEN** неавторизованный пользователь переходит на `/transactions`
- **THEN** приложение перенаправляет его на `/login`, экран операций не отображается

### Requirement: Список операций с фильтрами
Экран `/transactions` SHALL загружать список операций текущего воркспейса запросом
`GET /api/workspaces/{workspace_id}/transactions` с фильтрами: кошелёк (query-параметр `wallet_id`), категория
(`category_id`), тип (`type`), диапазон дат (`date_from`/`date_to`). Над списком SHALL отображаться элементы
управления фильтрами: выбор кошелька (со значением «Все кошельки»), выбор категории (со значением «Все
категории»), переключатель типа («Все»/«Доход»/«Расход»), выбор диапазона дат. Каждая операция SHALL отображаться
карточкой: название кошелька, иконка и название категории с индикатором типа, дата операции, сумма с кодом валюты
по каждой ноге операции — одна строка «сумма код», если операция состоит из ровно одной ноги, и список таких строк
(одна на каждую валюту), если операция состоит из нескольких ног (пополнение многовалютного кошелька), и
комментарий, если он задан. Карточки SHALL отображаться в порядке, в котором backend вернул список (без
клиентской пересортировки).

#### Scenario: Загрузка списка
- **WHEN** экран `/transactions` только что открыт
- **THEN** отображается индикатор загрузки, пока ответ `GET /api/workspaces/{workspace_id}/transactions` не
  получен

#### Scenario: Список получен и не пуст
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` вернул страницу с одной или несколькими операциями
- **THEN** каждая операция отображается карточкой с названием кошелька, иконкой, названием и индикатором типа
  категории, суммой с кодом валюты и датой, в порядке ответа backend

#### Scenario: Операция с несколькими ногами отображает сумму по каждой валюте
- **WHEN** в списке присутствует операция (пополнение многовалютного кошелька) с более чем одной ногой
- **THEN** карточка этой операции отображает список строк «сумма код», одну на каждую ногу, а не только на
  первую

#### Scenario: Пустой список
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` вернул пустую страницу (в текущем воркспейсе ещё нет
  операций, соответствующих текущим фильтрам)
- **THEN** вместо списка карточек отображается пустое состояние с призывом создать операцию, элементы управления
  фильтрами остаются видимыми и доступными

#### Scenario: Фильтр по кошельку сужает список
- **WHEN** пользователь выбирает конкретный кошелёк в фильтре «Кошелёк»
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transactions` с query-параметром `wallet_id`,
  равным id выбранного кошелька, список обновляется, отображая только операции этого кошелька

#### Scenario: Фильтр по категории сужает список
- **WHEN** пользователь выбирает конкретную категорию в фильтре «Категория»
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transactions` с query-параметром `category_id`,
  равным id выбранной категории, список обновляется, отображая только операции этой категории

#### Scenario: Фильтр по типу сужает список
- **WHEN** пользователь переключает фильтр типа с «Все» на «Доход» (или «Расход»)
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transactions` с query-параметром `type`, равным
  выбранному значению, список обновляется, отображая только операции этого типа

#### Scenario: Фильтр по диапазону дат сужает список
- **WHEN** пользователь выбирает диапазон дат в фильтре дат
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transactions` с `date_from`, равным началу
  первого выбранного дня, и `date_to`, равным концу последнего выбранного дня, список обновляется, отображая
  только операции внутри диапазона

#### Scenario: Комбинация нескольких фильтров
- **WHEN** пользователь одновременно задаёт фильтр по кошельку, категории, типу и диапазону дат
- **THEN** запрос `GET /api/workspaces/{workspace_id}/transactions` выполняется со всеми соответствующими
  query-параметрами одновременно, список отображает только операции, удовлетворяющие всем условиям сразу

#### Scenario: Ошибка загрузки списка
- **WHEN** `GET /api/workspaces/{workspace_id}/transactions` завершился ошибкой
- **THEN** пользователь получает уведомление об ошибке (toast) по общему правилу обработки ошибок API

#### Scenario: Комментарий отображается, если задан
- **WHEN** операция в списке имеет непустой `comment`
- **THEN** карточка этой операции отображает текст комментария

#### Scenario: Комментарий не отображается, если не задан
- **WHEN** операция в списке имеет `comment = null`
- **THEN** карточка этой операции не показывает место под комментарий (не пустую строку)

### Requirement: Пагинация списка операций
Экран `/transactions` SHALL использовать реальную серверную пагинацию с фиксированным размером страницы 20.
Переключение страницы SHALL выполнять новый запрос `GET /api/workspaces/{workspace_id}/transactions` с
соответствующим `offset`. Изменение любого фильтра (кошелёк, категория, тип, диапазон дат) SHALL сбрасывать
текущую страницу на первую.

#### Scenario: Переключение страницы
- **WHEN** список операций содержит больше одной страницы и пользователь переключается на следующую страницу
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/transactions` с `offset`, равным размеру
  страницы, отображается соответствующий набор операций

#### Scenario: Смена фильтра сбрасывает пагинацию
- **WHEN** пользователь находится не на первой странице списка и меняет любой фильтр
- **THEN** список возвращается к первой странице (`offset: 0`), запрос выполняется с обновлённым фильтром и
  сброшенным смещением

### Requirement: Баланс выбранного кошелька
Когда фильтр «Кошелёк» установлен в конкретный кошелёк (не «Все кошельки»), экран `/transactions` SHALL
показывать карточку баланса этого кошелька по каждой его валюте, загруженную запросом
`GET /api/workspaces/{workspace_id}/wallets/{id}/balances`. Когда фильтр «Кошелёк» установлен в «Все кошельки»,
карточка баланса SHALL не показываться.

#### Scenario: Баланс показывается при выбранном кошельке
- **WHEN** пользователь устанавливает фильтр «Кошелёк» в конкретный кошелёк
- **THEN** выполняется запрос `GET /api/workspaces/{workspace_id}/wallets/{id}/balances`, над списком операций
  отображается карточка с балансом по каждой валюте этого кошелька (включая нулевой баланс)

#### Scenario: Баланс не показывается при «Все кошельки»
- **WHEN** фильтр «Кошелёк» установлен в значение «Все кошельки» (значение по умолчанию)
- **THEN** карточка баланса не отображается, запрос `GET .../wallets/{id}/balances` не выполняется

#### Scenario: Смена выбранного кошелька обновляет баланс
- **WHEN** пользователь переключает фильтр «Кошелёк» с одного конкретного кошелька на другой
- **THEN** карточка баланса обновляется данными нового кошелька (новый запрос
  `GET /api/workspaces/{workspace_id}/wallets/{id}/balances`)

### Requirement: Создание операции
Экран `/transactions` SHALL предоставлять действие создания через выпадающее меню «Добавить» с тремя пунктами:
«Доход/расход», «Пополнение» и «Перевод». Пункт «Доход/расход» SHALL открывать форму создания обычной операции
поверх списка в `Drawer` на телефоне и в `Modal` на широком экране — без перехода на отдельный маршрут. Форма
SHALL содержать выбор кошелька, переключатель типа (сужающий список доступных категорий, не отправляемый в теле
запроса), выбор категории из категорий выбранного типа, выбор валюты, ограниченный набором валют выбранного
кошелька, сумму, необязательную дату операции и необязательный комментарий (не более 1000 символов). Успешное
создание (`POST /api/workspaces/{workspace_id}/transactions`) SHALL добавить новую операцию в список без
перезагрузки страницы. Пункт «Пополнение» открывает форму пополнения многовалютного кошелька (см. отдельное
требование «Создание пополнения многовалютного кошелька»). Пункт «Перевод» переводит пользователя на маршрут
`/transfers` без открытия какой-либо формы на экране `/transactions`.

#### Scenario: Меню «Добавить» показывает три действия
- **WHEN** пользователь открывает меню «Добавить» на экране `/transactions`
- **THEN** меню показывает три пункта: «Доход/расход», «Пополнение», «Перевод»

#### Scenario: Пункт «Перевод» переходит в раздел переводов
- **WHEN** пользователь выбирает пункт «Перевод» в меню «Добавить»
- **THEN** приложение переходит на маршрут `/transfers`, форма перевода не открывается на экране `/transactions`

#### Scenario: Успешное создание дохода
- **WHEN** пользователь выбирает пункт «Доход/расход» в меню «Добавить», заполняет форму с переключателем типа
  «Доход», выбирает кошелёк, категорию дохода, валюту из набора кошелька, положительную сумму и отправляет форму
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transactions` выполняется с данными формы (без отдельного
  поля типа), форма закрывается, список операций обновляется и содержит новую операцию, пользователь получает
  уведомление об успехе

#### Scenario: Успешное создание расхода
- **WHEN** пользователь выбирает пункт «Доход/расход» в меню «Добавить», заполняет форму с переключателем типа
  «Расход», выбирает кошелёк, категорию расхода, валюту из набора кошелька, положительную сумму и отправляет
  форму
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transactions` выполняется с данными формы (без отдельного
  поля типа), форма закрывается, список операций обновляется и содержит новую операцию, пользователь получает
  уведомление об успехе

#### Scenario: Выбор валюты ограничен набором кошелька
- **WHEN** пользователь выбрал конкретный кошелёк в форме создания операции и открывает выбор валюты
- **THEN** в списке доступных для выбора валют показаны только валюты, входящие в набор валют выбранного кошелька

#### Scenario: Смена кошелька сбрасывает выбранную валюту
- **WHEN** пользователь выбрал валюту, затем меняет кошелёк на другой, не содержащий эту валюту
- **THEN** поле валюты сбрасывается, пользователю нужно выбрать валюту заново из набора нового кошелька

#### Scenario: Смена типа сбрасывает выбранную категорию
- **WHEN** пользователь выбрал категорию, затем переключает тип операции
- **THEN** поле категории сбрасывается, список доступных категорий обновляется под новый тип

#### Scenario: Ошибка валидации по полю при создании
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions` ошибкой 400 с сообщениями по
  конкретным полям (`wallet_id`, `category_id`, `currency_id`, `amount`, `occurred_at`, `comment`)
- **THEN** форма остаётся открытой, соответствующие поля показывают полученные сообщения об ошибке, операция не
  добавляется в список

#### Scenario: Валюта операции не входит в набор валют кошелька
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions` ошибкой 400 с текстовым
  описанием, что валюта операции не входит в набор валют кошелька
- **THEN** форма остаётся открытой, пользователь получает уведомление с этим текстом ошибки, операция не
  добавляется в список

#### Scenario: Сумма превышает допустимое число знаков для валюты
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions` ошибкой 400 с текстовым
  описанием, что сумма превышает допустимое число знаков после запятой для выбранной валюты
- **THEN** форма остаётся открытой, пользователь получает уведомление с этим текстом ошибки, операция не
  добавляется в список

#### Scenario: Создание операции с комментарием
- **WHEN** пользователь заполняет поле «Комментарий» непустым текстом (не более 1000 символов) и отправляет форму
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transactions` выполняется с этим `comment`, созданная
  операция в списке отображает комментарий

#### Scenario: Создание операции без комментария
- **WHEN** пользователь оставляет поле «Комментарий» пустым и отправляет форму
- **THEN** запрос выполняется без `comment` (или с пустым значением), созданная операция в списке не показывает
  комментарий

### Requirement: Редактирование операции
Экран `/transactions` SHALL позволять отредактировать существующую операцию, состоящую из ровно одной ноги, той
же формой, что используется для создания, предзаполненной текущими значениями выбранной операции, включая
переключатель типа, вычисленный по типу текущей категории операции, и текущий комментарий. Успешное редактирование
(`PUT /api/workspaces/{workspace_id}/transactions/{id}`) SHALL обновить операцию в списке без перезагрузки
страницы. Операция с более чем одной ногой (пополнение многовалютного кошелька) SHALL не редактироваться этой
формой: кнопка «Редактировать» на карточке такой операции SHALL быть недоступна (`disabled`) и сопровождаться
поясняющей подсказкой о том, что многоногое пополнение нельзя редактировать и что изменить его можно только
удалением и повторным созданием; кнопка «Удалить» при этом остаётся доступной.

#### Scenario: Открытие формы редактирования
- **WHEN** пользователь нажимает «Редактировать» на карточке операции с ровно одной ногой
- **THEN** открывается та же форма, что и для создания, с полями кошелька, категории, валюты, суммы, даты и
  комментария, предзаполненными текущими значениями этой операции, а переключатель типа установлен в значение,
  соответствующее типу текущей категории операции

#### Scenario: Успешное редактирование
- **WHEN** пользователь изменяет данные в форме редактирования и отправляет её
- **THEN** запрос `PUT /api/workspaces/{workspace_id}/transactions/{id}` выполняется, форма закрывается, карточка
  операции в списке отображает обновлённые данные, пользователь получает уведомление об успехе

#### Scenario: Кнопка редактирования недоступна для многоногой операции
- **WHEN** карточка отображает операцию (пополнение) с более чем одной ногой
- **THEN** кнопка «Редактировать» на этой карточке недоступна (`disabled`), при наведении или тапе показывается
  подсказка о том, что многоногое пополнение нельзя редактировать и нужно удалить и создать заново, кнопка
  «Удалить» остаётся доступной

#### Scenario: Изменение комментария
- **WHEN** пользователь меняет текст в поле «Комментарий» формы редактирования и отправляет её
- **THEN** запрос `PUT /api/workspaces/{workspace_id}/transactions/{id}` выполняется с новым `comment`, карточка
  операции отображает обновлённый комментарий

#### Scenario: Очистка комментария
- **WHEN** операция ранее имела комментарий, пользователь очищает поле «Комментарий» в форме редактирования и
  отправляет её
- **THEN** запрос выполняется без `comment`, карточка операции перестаёт отображать комментарий

### Requirement: Удаление операции
Экран `/transactions` SHALL позволять удалить операцию с карточки списка через подтверждение (`Popconfirm`), без
перехода на отдельный маршрут или экран подтверждения. Успешное удаление
(`DELETE /api/workspaces/{workspace_id}/transactions/{id}`) SHALL убрать операцию из списка без перезагрузки
страницы.

#### Scenario: Успешное удаление
- **WHEN** пользователь подтверждает удаление операции
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/transactions/{id}` выполняется, операция пропадает из
  списка, пользователь получает уведомление об успехе

#### Scenario: Отмена удаления
- **WHEN** пользователь открывает подтверждение удаления и отменяет его
- **THEN** запрос `DELETE /api/workspaces/{workspace_id}/transactions/{id}` не выполняется, операция остаётся в
  списке без изменений

#### Scenario: Удаление и редактирование операции обновляют баланс кошелька
- **WHEN** карточка баланса выбранного кошелька отображается и пользователь успешно создаёт, редактирует или
  удаляет операцию по этому кошельку
- **THEN** карточка баланса перезапрашивает данные
  (`GET /api/workspaces/{workspace_id}/wallets/{id}/balances`) и отображает актуальные суммы без перезагрузки
  страницы

### Requirement: Создание пополнения многовалютного кошелька
Экран `/transactions` SHALL позволять создать пополнение многовалютного кошелька через отдельную форму,
открывающуюся из пункта «Пополнение» меню «Добавить», поверх списка в `Drawer` на телефоне и в `Modal` на широком
экране — без перехода на отдельный маршрут. Форма SHALL содержать выбор кошелька, динамический набор полей
суммы — ровно по одному на каждую валюту выбранного кошелька, — выбор категории только среди категорий типа
«доход», необязательную дату и необязательный комментарий (не более 1000 символов). Смена выбранного кошелька
SHALL сбрасывать все введённые суммы и перестраивать набор полей под валюты нового кошелька. Успешное создание
(`POST /api/workspaces/{workspace_id}/transactions/topups`) SHALL добавить новую операцию (с несколькими ногами) в
список без перезагрузки страницы.

#### Scenario: Поля сумм строятся по валютам выбранного кошелька
- **WHEN** пользователь выбирает многовалютный кошелёк в форме пополнения
- **THEN** форма показывает ровно одно поле суммы на каждую валюту выбранного кошелька

#### Scenario: Смена кошелька сбрасывает введённые суммы
- **WHEN** пользователь ввёл суммы для валют одного кошелька в форме пополнения, затем меняет кошелёк на другой
- **THEN** ранее введённые суммы сбрасываются, поля сумм перестраиваются под валюты нового кошелька

#### Scenario: Категория пополнения ограничена доходными
- **WHEN** пользователь открывает выбор категории в форме пополнения
- **THEN** в списке доступны только категории типа «доход»

#### Scenario: Успешное создание пополнения с полным набором валют кошелька
- **WHEN** пользователь выбирает многовалютный кошелёк, заполняет поле суммы для каждой его валюты, выбирает
  доходную категорию и отправляет форму
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transactions/topups` выполняется с телом, содержащим по
  одной ноге на каждую валюту кошелька, форма закрывается, список операций обновляется и содержит новую операцию
  с несколькими ногами, пользователь получает уведомление об успехе

#### Scenario: Ошибка при неполном или избыточном наборе валют
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions/topups` ошибкой 400 с текстовым
  описанием, что набор валют пополнения не совпадает с набором валют кошелька
- **THEN** форма остаётся открытой, пользователь получает уведомление с этим текстом ошибки, пополнение не
  добавляется в список

#### Scenario: Ошибка при категории, не являющейся доходной
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions/topups` ошибкой 400 с текстовым
  описанием, что категория пополнения не является доходной
- **THEN** форма остаётся открытой, пользователь получает уведомление с этим текстом ошибки, пополнение не
  добавляется в список

#### Scenario: Ошибка валидации по известному полю при создании пополнения
- **WHEN** backend отвечает на `POST /api/workspaces/{workspace_id}/transactions/topups` ошибкой 400 с сообщением
  по полю `wallet_id`, `category_id` или `comment`
- **THEN** форма остаётся открытой, соответствующее поле показывает полученное сообщение об ошибке, пополнение не
  добавляется в список

#### Scenario: Пополнение с комментарием
- **WHEN** пользователь заполняет поле «Комментарий» в форме пополнения и отправляет её
- **THEN** запрос `POST /api/workspaces/{workspace_id}/transactions/topups` выполняется с этим `comment`,
  созданное пополнение в списке отображает комментарий

### Requirement: Точка входа в раздел переводов со страницы «Операции»
Экран `/transactions` SHALL предоставлять точку входа в раздел переводов: ссылку «Переводы» рядом с заголовком
«Операции» и пункт «Перевод» в меню «Добавить» (см. требование «Создание операции»). Оба способа SHALL вести на
маршрут `/transfers` без открытия какой-либо формы на экране `/transactions`.

#### Scenario: Ссылка «Переводы» ведёт в раздел переводов
- **WHEN** пользователь нажимает ссылку «Переводы» на экране `/transactions`
- **THEN** приложение переходит на маршрут `/transfers`
