## Why

Кошельки (задача 008) и последующие операции берут валюту только из общего справочника — без него нельзя заводить
кошельки. Задача 006 зависит от готового скелета backend (004) и вводит два связанных результата: сам справочник
валют и переиспользуемый механизм сидирования справочных данных, которым позже воспользуются другие задачи дорожной
карты (например, iconpack, если он тоже потребует сидирования). Механизм нужен уже сейчас, потому что правило
«сидирование в `lifespan`, не миграциями» и «явные UUID» закреплены в AGENTS.md и должны быть реализованы один раз, а
не придуманы заново при каждой новой справочной таблице.

## What Changes

- Таблица `currencies` (`id`, `code`, `name`, `decimal_places`) и миграция Alembic (только схема, без данных).
- Сущность `Currency`, протокол репозитория `CurrencyRepository` (чтение + `upsert_many` без удаления), реализация на
  SQLAlchemy Core, сервис чтения справочника.
- Эндпоинт `GET /api/currencies` — постраничный список валют (`PageParams`/`Page`, как у прочих списочных
  эндпоинтов).
- Переиспользуемый механизм сидирования `utils/seeding.py`: читает JSON из `src/seeds/`, обновляет записи по `id`
  (upsert), не удаляет записи, отсутствующие в JSON; на реальной БД оборачивается PostgreSQL advisory lock
  (`pg_advisory_lock`/`pg_advisory_unlock` через сессионное соединение SQLAlchemy на асинхронном драйвере asyncpg),
  чтобы несколько реплик, стартующих одновременно, не конфликтовали.
- Сид `src/seeds/currencies.json` с тремя валютами (CNY, RUB, USDT) и явными UUID, зафиксированными один раз.
- Настройка `SEEDING_ENABLED` (по умолчанию включена; в тестах выключается через окружение, аналогично
  `SENTRY_ENABLED`), подключение сидирования в `lifespan` приложения.
- Unit-тесты механизма сидирования на fake-репозитории, smoke-тест (без БД), infrastructure-тесты сидирования и
  репозитория на реальной БД (включая advisory lock).

Затрагивается API: новый эндпоинт `GET /api/currencies`. Затрагивается БД: новая таблица `currencies`, **нужна
миграция Alembic** (только схема). Данные заполняются не миграцией, а сидированием при старте приложения.
**BREAKING**-изменений нет.

## Capabilities

### New Capabilities
- `currencies`: справочник валют (хранение, upsert-семантика без удаления, чтение через API).
- `seeding`: переиспользуемый инфраструктурный механизм сидирования справочных данных из JSON — идемпотентность,
  upsert по `id`, отсутствие удаления, безопасность при нескольких репликах через advisory lock, настройка
  включения/отключения.

## Impact

- `backend/src`: `core/entities/currency.py`, `core/protocols/repositories/currency_repository.py`,
  `core/protocols/seed_repository.py` (или обобщение внутри протокола валют), `core/services/currency.py`,
  `core/schemas/currency.py` (при необходимости), `models/currency.py`, `repositories/currency.py`, `api/currencies.py`,
  `api/schemas/currency.py`, `depends/currency.py`, `utils/seeding.py`, `seeds/currencies.py` (описание источника
  сидирования) и `seeds/currencies.json` (данные), `settings.py` (`SEEDING_ENABLED`), `main.py` (подключение
  сидирования в `lifespan` и роутера `currencies`), новая миграция Alembic.
- `backend/.env`, `backend/.env.example`: новая переменная `SEEDING_ENABLED`.
- Тесты backend: unit (сервис/механизм сидирования на fake-репозитории), smoke (эндпоинт зарегистрирован, приложение
  стартует без БД при выключенном сидировании), infrastructure (репозиторий валют, upsert-сидирование на реальной БД,
  advisory lock при параллельном старте).
- Frontend в рамках этой задачи не меняется (потребитель справочника — задача 008 «Кошельки»).

## Non-goals

- Пользовательские валюты поверх глобального справочника.
- Расчёт и хранение курсов валют.
- Создание, изменение и удаление валют через API (справочник управляется только сидом).
