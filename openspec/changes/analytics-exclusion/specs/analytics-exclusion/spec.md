## ADDED Requirements

### Requirement: Исключение операций из аналитики
Система SHALL поддерживать следующее поведение: Расходы и пополнения SHALL хранить exclude_from_analytics, по умолчанию false. Аналитика исключает отмеченные операции и источники курсов; include_excluded=true включает их. В интерфейсе доступен общий переключатель, по умолчанию выключенный.

#### Scenario: Применение параметров
- **WHEN** пользователь применяет соответствующие параметры
- **THEN** результат соответствует выбранным значениям и остаётся ограничен текущим воркспейсом

#### Scenario: Чужой воркспейс
- **WHEN** запрос обращается к чужому воркспейсу
- **THEN** API возвращает 404

### Requirement: Хранение и изменение флага
POST и PUT расходов и пополнений SHALL принимать exclude_from_analytics с default false; GET SHALL возвращать сохранённый флаг. Миграция SHALL установить false для прежних записей без изменения сумм и дат. Флаг SHALL не скрывать операции из обычных списков.

#### Scenario: Редактирование
- **WHEN** пользователь сохраняет операцию с exclude_from_analytics=true
- **THEN** GET возвращает true, форма повторного редактирования показывает установленную галочку

### Requirement: Аналитика без исключённых операций
GET analytics и analytics/rates SHALL по умолчанию исключать помеченные записи как из агрегатов, так и из источников аналитического курса. include_excluded=true SHALL включать обе группы записей. Область дат и правила округления SHALL сохраняться.

#### Scenario: Явное включение
- **WHEN** пользователь включает общий переключатель на странице аналитики
- **THEN** текущий и последующие режимы запрашиваются с include_excluded=true, а ключи кэша различаются

#### Scenario: Нет доступного курса
- **WHEN** единственное подходящее пополнение исключено из аналитики
- **THEN** оно не даёт курс конвертации и соответствующая валюта попадает в unconverted_currencies
