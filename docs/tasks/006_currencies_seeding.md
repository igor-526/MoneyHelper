# 006. Валюты и сидирование (этап 1)

Зависит от: 004 (005 не обязательна для чтения справочника). Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md), раздел «Сидирование».

## Цель
Глобальный справочник валют, заполняемый при старте приложения, и переиспользуемый механизм сидирования.

## Контекст и решения
- Валюты — общий глобальный справочник (CNY, RUB, USDT и др.), из которого кошельки берут свои валюты.
- Сидирование не через миграции, а в `lifespan` при старте приложения.
- Механизм в `utils/seeding.py`, данные в JSON в `src/seeds/`.
- В сидах всегда явные UUID, сгенерированные функцией (`uuid.uuid4()`); выдуманные идентификаторы запрещены; выданный UUID не меняется.
- Сидирование идемпотентно (upsert по UUID) и безопасно при нескольких репликах (advisory lock).
- В тестах сидирование отключается, чтобы `make test` не требовал БД (smoke-тест открывает `TestClient` как контекст, то есть запускает lifespan).

## Объём
- Механизм сидирования и его настройка (включение/отключение).
- Сид валют (код, название, знаков после запятой) с явными UUID.
- Таблица валют и миграция схемы (без данных).
- Сущность, протоколы, репозиторий, сервис и API чтения справочника.
- Unit-тесты механизма (идемпотентность, обновление изменённой записи), smoke-тест, infrastructure-тест сидирования.

## Вне рамок
Пользовательские валюты поверх справочника; расчёт курсов.

## Открытые вопросы
Как сид обновляет уже существующие записи и что делает при удалении записи из JSON; формат JSON; какие валюты входят в начальный набор.

## Критерии готовности
- Повторный старт не создаёт дублей и не меняет UUID.
- `make test` проходит без БД; `make test-infra` проверяет сидирование.
- QualityGate проходит.
