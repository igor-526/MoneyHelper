# 018. Аналитика (frontend, этап F2f)

Зависит от: 016, 012. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь смотрит доходы и расходы в разных разрезах в единой валюте отображения.

## Контекст и решения
- Первая версия — сводные карточки/список сумм по корзинам среза, без графиков (решение дорожной карты; графики —
  отдельная будущая задача, как и на backend, 012).
- `date_from`/`date_to` и валюта отображения обязательны (как того требует `GET /api/analytics`) — форма не даёт
  отправить запрос без них.
- Валюты без найденного курса исключаются backend из сумм и перечисляются в `unconverted_currencies` — экран
  обязан показать это предупреждение, а не просто занизить суммы молча.
- Навигация — эта задача добавляет собственный пункт `navItems` («Аналитика») и маршрут `/analytics` (решение
  013); пятый, последний из пяти пунктов нижней панели.

## Объём
- `navItems`/`routes.tsx` — пункт «Аналитика», маршрут `/analytics` под `RequireAuth`.
- Экран с фильтрами: диапазон дат, валюта отображения, срез (кошелёк/категория/валюта), опционально
  кошелёк/категория/валюта/тип для сужения выборки.
- Сводные карточки по корзинам выбранного среза: доход/расход в валюте отображения.
- Предупреждение о валютах без курса (`unconverted_currencies`) с понятным пояснением, почему суммы в этой валюте
  не учтены.
- Обработка стандартных ошибок API (400 — неизвестная валюта отображения, некорректный диапазон дат).
- Тесты компонентов и hooks.

## Вне рамок
Графики, экспорт отчёта — отдельная будущая задача; переводы в аналитике не участвуют (backend их не учитывает).

## Открытые вопросы
Решено: диапазон дат — один `RangePicker` (без времени в UI); доход и расход в карточке — два `Typography.Text`
рядом, разными семантическими цветами (`success`/`danger`), оба всегда показаны (включая нулевые).

## Критерии готовности
- Аналитика показывает суммы в выбранной валюте по среднему курсу диапазона, сгруппированные по выбранному срезу.
- Отсутствие курса для валюты видно пользователю явно, не как заниженная сумма без объяснения.
- QualityGate проходит.

## Статус
Выполнено (изменение `frontend-analytics`, архив `2026-09-30-frontend-analytics`). В отличие от всех предыдущих
экранов со списками, здесь все три параметра (валюта отображения, диапазон дат, срез) обязательны одновременно —
запрос гейтится через `enabled: filters !== null` (`useAnalytics`), без кнопки подтверждения: как только все три
заполнены, запрос выполняется реактивно. Подпись корзины резолвится по активному срезу через реестр
`Record<GroupBy, resolver>` из трёх справочников — прямая параллель backend-паттерну `DIMENSIONS`
(`analytics_dimensions.py`). Карточки без пагинации (backend не разбивает `buckets` на страницы), сортировка по
подписи (не по сумме — суммы остаются строками). При apply обнаружен и исправлен реальный runtime-баг: `antd
Segmented` с `value={undefined}` подсвечивает первую опцию, но не вызывает `onChange` по клику на неё — заменено
на сентинел `value={state.groupBy ?? ""}`. Пункт навигации «Аналитика» — пятый, последний перед «Настройки»,
завершает бюджет нижней панели, зарезервированный в 013. Проверено полным QualityGate (3 прогона тестов чистые);
backend не затронут.
