# 007. Iconpack (этап 2)

Зависит от: 004. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md), раздел «Иконки».

## Цель
Единый набор иконок для категорий и кошельков, общий для backend и frontend, с проверкой значений на входе API.

## Контекст и решения
- Iconpack — [Lucide](https://lucide.dev).
- В БД хранится имя иконки Lucide в kebab-case (`wallet`, `banknote`).
- Список допустимых имён задаётся в одном месте в `core`; frontend отрисовывает иконку по имени.

## Объём
- Реестр допустимых имён иконок и тип/валидатор для использования в схемах кошельков и категорий.
- Эндпоинт со списком допустимых иконок.
- Правило синхронизации списка с frontend (обёртка `Icon` из задачи 003).
- Unit- и smoke-тесты.

## Вне рамок
Загрузка пользовательских иконок; сами кошельки и категории (008, 009).

## Открытые вопросы
Решено: ограниченное курируемое подмножество Lucide (стартовый набор — 23 уже существовавшие бизнес-иконки категорий
и кошельков); единый источник правды — `backend/src/core/icons.json`, frontend синхронизируется не сетевым запросом,
а `vitest`-тестом, читающим тот же файл с диска и сверяющим его с картой иконок; версия `lucide-react` не менялась —
уже зафиксирована в задаче 003 (`^1.48.0`).

## Критерии готовности
- Некорректное имя иконки отклоняется валидацией; список доступен через API.
- QualityGate проходит.

## Статус
Выполнено (изменение `iconpack`, архив `2026-09-29-iconpack`). Реестр статический (не таблица БД, без миграции и
сидирования) — `core/icons.py` строит `ALLOWED_ICONS` из `icons.json`, `core/schemas/icon.py` даёт переиспользуемый
тип `IconName` для будущих схем кошельков и категорий (008/009; в этой задаче нигде ещё не подключён). `GET
/api/icons` реализован без авторизации и пагинации. Frontend `shared/ui/icons.ts` разделён на `BUSINESS_ICONS`/
`UI_ICONS`; поведение `Icon`/`resolveIcon` не изменилось. Проверено полным QualityGate (`make format/lint/test`;
`make test-infra` не требуется — БД не затрагивается).
