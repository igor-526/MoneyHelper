# 007. Iconpack (этап 2)

Зависит от: 004. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md), раздел «Иконки».

## Цель
Единый набор иконок для категорий и кошельков, общий для backend и frontend, с проверкой значений на входе API.

## Контекст и решения
- Iconpack — [Lucide](https://lucide.dev).
- В БД хранится имя иконки Lucide в kebab-case (`wallet`, `banknote`).
- Список допустимых имён задаётся в одном месте в `core`; frontend отрисовывает иконку по имени.

## Объём
- Реестр допустимых имён иконок и тип/валидатор для использования в схемах кошельков и категорий.
- Эндпоинт со списком допустимых иконок.
- Правило синхронизации списка с frontend (обёртка `Icon` из задачи 003).
- Unit- и smoke-тесты.

## Вне рамок
Загрузка пользовательских иконок; сами кошельки и категории (008, 009).

## Открытые вопросы
Полный список Lucide или ограниченное подмножество; как синхронизировать со списком frontend; версия Lucide.

## Критерии готовности
- Некорректное имя иконки отклоняется валидацией; список доступен через API.
- QualityGate проходит.
