# 010. Доходы и расходы (этап 5)

Зависит от: 008, 009. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md), раздел «Деньги и валюты».

## Цель
Пользователь записывает доходы и расходы, каждая операция привязана к кошельку; можно смотреть список и балансы.

## Контекст и решения
- Операция состоит из «ног» (валюта + сумма); для кошелька с одной валютой это одна нога.
- Суммы — `Decimal`/`NUMERIC`; валюта суммы указывается всегда.
- Валюта каждой ноги обязана входить в набор валют кошелька.
- Категория должна соответствовать типу операции (доход/расход).
- Удаление физическое.

## Объём
- Таблицы операций и ног, миграция.
- Создание, правка, удаление, чтение операции; список с фильтрами (период, кошелёк, категория, тип) и пагинацией.
- Балансы по кошельку и валюте.
- Изоляция по владельцу.
- Unit- и smoke-тесты.

## Вне рамок
Пополнения с несколькими валютами и переводы (011); аналитика (012).

## Открытые вопросы
Решено: баланс вычисляется на лету агрегирующим запросом, без кэширования (нет проблемы инвалидации, датасет
персонального приложения небольшой); БД — две таблицы (`transactions` + `transaction_legs`, как явно требует
«Объём»), но на уровне домена/API для этой задачи операция плоская — ровно одна нога (задел на несколько ног у
`transaction_legs` под многовалютные пополнения 011); `occurred_at` — `DateTime(timezone=True)` (aware, как и
остальные даты в проекте), задаётся клиентом или по умолчанию `Clock.now()`; округление запрещено — превышение
числа знаков валюты отклоняется ошибкой 400, а не округляется молча.

## Критерии готовности
- Доход и расход по кошельку создаются и правятся; баланс соответствует операциям.
- Нельзя записать сумму в валюте, которой нет у кошелька.
- QualityGate проходит.

## Статус
Выполнено (изменение `transactions`, архив `2026-09-29-transactions`). Таблицы `transactions` и `transaction_legs`
(миграция `20260929_0006`); `wallet_id`/`category_id` — `ON DELETE RESTRICT` (нельзя удалить кошелёк/категорию с
операциями — 409 `ConflictError`, доработаны `WalletRepository.delete`/`CategoryRepository.delete`),
`transaction_legs.currency_id` — `ON DELETE RESTRICT`, `transaction_id` — `ON DELETE CASCADE`. Тип операции не
хранится отдельно — определяется через JOIN с `categories.type`. `TransactionRepository` фильтрует по
`transaction_id` И `user_id` в одном запросе — чужая операция везде 404. `GET/POST/PUT/DELETE /api/transactions*`
и `GET /api/wallets/{wallet_id}/balances` (баланс на лету по всем валютам кошелька, включая нулевые) реализованы
под `get_current_user`. Список операций сортируется `occurred_at DESC, id DESC` (новые сначала) — осознанное
отличие от `created_at ASC, id ASC` у `wallets`/`categories`. Проверено полным QualityGate, включая `make
test-infra` (RESTRICT/CASCADE, `CheckConstraint` на сумму, корректность баланса, изоляция — все на реальной БД).
