# 017. Пополнения и переводы (frontend, этап F2e)

Зависит от: 016, 011. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь пополняет многовалютный кошелёк сразу во всех его валютах и переводит деньги между своими
кошельками.

## Контекст и решения
- Пополнение (`POST /api/transactions/topups`) требует ровно по одной сумме на каждую валюту кошелька — форма
  строит поля динамически по числу валют выбранного кошелька, а не как фиксированная пара полей.
- Перевод (`POST /api/transfers`) — одна валюта без конвертации, обязана входить в набор валют обоих кошельков;
  форма после выбора обоих кошельков предлагает только валюты, общие для них.
- Категория пополнения обязана быть доходной — выбор категории в форме пополнения показывает только категории
  типа «доход».
- Навигация — без отдельного пункта нижней панели (бюджет исчерпан, решение 013): маршрут `/transfers` и точки
  входа в обе формы (пополнение/перевод) — со страницы «Операции» (016).

## Объём
- `routes.tsx` — маршрут `/transfers` под `RequireAuth`; точки входа с экрана «Операции» (016).
- Форма пополнения: выбор кошелька → поля сумм по каждой его валюте → категория (только доходные) → дата.
  Понятная ошибка backend про неполный/избыточный набор валют, если она всё же возникла.
- Форма перевода: исходный кошелёк → целевой кошелёк → валюта (только общие для обоих) → сумма → дата; понятная
  ошибка при отсутствии общей валюты или совпадении кошельков.
- Список/история переводов с фильтром по кошельку.
- Обработка стандартных ошибок API.
- Тесты компонентов и hooks.

## Вне рамок
Конвертация валют внутри перевода (backend её не поддерживает); редактирование пополнения на месте (backend не
даёт менять число ног через `PUT` — только удаление и создание заново, форма редактирования пополнения не
делается, только просмотр и удаление).

## Открытые вопросы
Решено: подсказка/предпросмотр implied-курса — не делаем (не требуется постановкой). Запись пополнения в списке
операций (016) — отображается как обычная карточка, но со списком сумм по КАЖДОЙ ноге (не только первой) и
заблокированной кнопкой «Редактировать» (backend меняет операцию по `PUT` только ровно одной ногой — правка
молча схлопнула бы пополнение).

## Критерии готовности
- Пополнение без всех валют кошелька отклоняется с понятной ошибкой; перевод без общей валюты — тоже.
- Перевод и пополнение видны в истории операций/переводов.
- QualityGate проходит.

## Статус
Выполнено (изменение `frontend-transfers`, архив `2026-09-30-frontend-transfers`). «Добавить» на экране «Операции»
(016) стало выпадающим меню из трёх пунктов: «Доход/расход» (без изменений), «Пополнение» (новая `TopupForm` —
динамические поля сумм по числу валют кошелька, категория только доходная), «Перевод» (переход на `/transfers`,
без формы на месте). `TransactionCard` теперь показывает все ноги операции (не только первую) и блокирует
«Редактировать» для многоногих операций (`disabled`+`Tooltip`) — «Удалить» остаётся доступным всегда. Новая
CRUD-вертикаль `features/transfers/` (по образцу кошельков/категорий, с реальной пагинацией, как у операций):
валюта перевода — пересечение наборов валют исходного и целевого кошельков через уже готовый `CurrencyPicker
.allowedIds` (013/016), без дальнейшего расширения компонента. Маршрут `/transfers` без пункта `navItems`
(подтверждено — файл не тронут). Мутации переводов инвалидируют баланс обоих затронутых кошельков. При личной
проверке обнаружена и задокументирована в памяти (не устранялась в рамках задачи, не связана с её кодом)
предсуществующая редкая нестабильность `make test` (таймер `IconPicker`/`Drawer`, ~1 из 3–5 прогонов при большом
наборе тестов) — известный follow-up, не блокирует. Проверено полным QualityGate (лично, 3 прогона тестов
чистые); backend не затронут.
