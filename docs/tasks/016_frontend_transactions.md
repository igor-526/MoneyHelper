# 016. Операции: доходы и расходы (frontend, этап F2d)

Зависит от: 014, 015, 010. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь ведёт список своих доходов и расходов по кошелькам и категориям, видит баланс кошелька.

## Контекст и решения
- Список — лента операций (не таблица), сортировка `occurred_at DESC` (как отдаёт backend) — новые операции
  первыми.
- Кошелёк и категория у пользователя уже должны существовать (014, 015) — при их отсутствии экран показывает
  пустое состояние с указанием, что нужно сначала завести кошелёк/категорию.
- Валюта операции ограничена набором валют выбранного кошелька (`currency_ids`) — `CurrencyPicker` фильтруется по
  выбранному кошельку, а не показывает весь глобальный справочник.
- Баланс кошелька (`GET /api/wallets/{id}/balances`) показывается на этом экране (например, при выборе кошелька
  фильтром) — карточка с суммой по каждой валюте кошелька.
- Навигация — эта задача добавляет собственный пункт `navItems` («Операции») и маршрут `/transactions` (решение
  013); четвёртый из пяти пунктов нижней панели. Переводы (017) будут доступны отсюда же (ссылка/переключатель на
  этом экране), без отдельного пункта панели.

## Объём
- `navItems`/`routes.tsx` — пункт «Операции», маршрут `/transactions` под `RequireAuth`.
- Список операций: фильтры (период, кошелёк, категория, тип), пагинация.
- Форма создания/редактирования операции: кошелёк → категория → валюта (ограничена набором кошелька) → сумма
  (`MoneyInput`) → дата.
- Удаление операции с подтверждением.
- Карточка баланса кошелька по валютам.
- Обработка стандартных ошибок API (включая 400 — валюта не из набора кошелька, превышение знаков суммы).
- Тесты компонентов и hooks.

## Вне рамок
Пополнения многовалютных кошельков и переводы между кошельками (017) — форма создания здесь создаёт только
обычную операцию с одной валютой, как и backend `POST /api/transactions`.

## Открытые вопросы
Показывать ли в этой ленте пополнения (созданные через 017) — они физически те же операции (просто с несколькими
«ногами»); как визуально отметить такую запись в общем списке (бейдж «пополнение» или просто больше одной суммы в
карточке); нужен ли переключатель «Доход/Расход» для быстрого сужения списка категорий в форме, или достаточно
единого списка категорий с видимым типом каждой.

## Критерии готовности
- Доход и расход по кошельку создаются, редактируются, удаляются, фильтруются.
- Нельзя ввести сумму в валюте, которой нет у кошелька — ошибка понятна пользователю.
- Баланс кошелька виден и соответствует операциям.
- QualityGate проходит.
