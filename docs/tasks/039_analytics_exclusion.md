# Исключение операций из аналитики

Источник: [036_improves.md](036_improves.md).

## Объём
Флаг exclude_from_analytics для расходов и пополнений, по умолчанию false; миграция с сохранением существующих данных. Фильтр include_excluded по умолчанию false для аналитики и истории курса, включая источники курсов.

## Этапы
1. Описать proposal, design, spec и tasks в openspec/changes/analytics-exclusion/.
2. Реализовать контракт и интерфейс, сохраняя изоляцию воркспейсов и обработку ошибок.
3. Проверить граничные случаи unit-тестами; изменения API покрыть smoke-тестами.
4. Последовательно выполнить make format, make lint, make test.
5. Провести ревью и зафиксировать результат.

## Приёмка
Флаг exclude_from_analytics для расходов и пополнений, по умолчанию false; миграция с сохранением существующих данных. Фильтр include_excluded по умолчанию false для аналитики и истории курса, включая источники курсов.
Ошибки запросов проходят через существующий глобальный обработчик. Интерфейс доступен от 320 px в обеих темах.

## Детали реализации
1. Добавить `Transaction.exclude_from_analytics: bool = False`; поле распространяется на расходы и пополнения.
2. Добавить BOOLEAN NOT NULL DEFAULT false в transactions; подготовить обратимую миграцию, сохранив суммы, ноги и даты старых записей.
3. POST/PUT принимают флаг с default false, GET возвращает сохранённое значение. Обычные списки его не фильтруют.
4. GET analytics и analytics/rates принимают `include_excluded=false`. При false исключить помеченные операции до расчётов; в агрегатах не использовать их как источники курса.
5. Средний курс карточки кошелька сохраняет прежнее поведение; период выборки источников курса не меняется.
6. Добавить checkbox «Не участвует в аналитике» в создание и редактирование обоих видов операций.
7. Добавить общий checkbox включения помеченных операций на странице аналитики; все режимы используют одно значение, по умолчанию false.
8. Включить параметр в ключи кэша. После изменения операции инвалидировать как агрегаты, так и историю курса.

## Проверка
- Сохранение true, повторное открытие формы, сброс false через PUT.
- Миграция: единственный head Alembic и генерация SQL без подключения к БД.
- Unit: помеченные расходы исключены; единственное помеченное пополнение не даёт курс; include_excluded=true возвращает и суммы, и курс.
- Smoke: поле в request/response-схемах обоих видов операций, параметр include_excluded с default false в аналитике и истории курса.

## Результат
Реализовано в изменении `analytics-exclusion`. QualityGate пройден: 463 backend-теста и 525 frontend-тестов. Alembic heads и offline SQL проверены; миграция на рабочей БД не запускалась. Ревью — `openspec/changes/analytics-exclusion/review.md`.
