Для каждого изменения созданы proposal, design, spec, tasks и review. Первые два этапа проверены совместно после адаптации регрессионных тестов; этапы 3 и 4 проверены последовательно. Итоговый QualityGate охватывает весь монорепозиторий.

## Принятые решения
- Пустой мультивыбор означает отсутствие результатов, отсутствие ограничения означает все записи. «Выбрать всё» и инверсия работают относительно доступного справочника.
- Поиск соответствует полю comment, не учитывает регистр и трактует `%` и `_` буквально.
- Флаг исключения распространяется на суммы и аналитические источники курса. Карточка среднего курса кошелька сохраняет прежнее поведение.
- Статистика дневных трат продолжает учитывать нулевые дни. Для курса строка «Сумма» суммирует показанные дневные значения.
- Артефакты оставлены в openspec/changes для просмотра; архивирование не выполнялось.

## Проверка и ограничения
Миграция `20261103_0014` проверена через Alembic heads и генерацию offline SQL. На рабочей БД она не применялась. Для развёртывания требуется применить миграции перед запуском нового backend.

UI проверен автоматическими тестами jsdom; нативный календарь на физическом телефоне не проверялся. Тесты с БД не запускались; обязательный QualityGate не требует внешней инфраструктуры.

## Итог
Все четыре этапа завершены. Последовательно прошли `make format`, `make lint`, `make test`: 464 backend-теста и 530 frontend-тестов. В каждом OpenSpec-изменении задачи отмечены выполненными, результат проанализирован в review.md.
