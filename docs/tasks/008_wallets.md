# 008. Кошельки (этап 3)

Зависит от: 005, 006, 007. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь ведёт свои кошельки с одной или несколькими валютами и иконками.

## Контекст и решения
- Примеры: UPay (USDT), Alipay CNY (2 шт.), WeChatPay CNY (2 шт.), NihaoChina CNY, наличные RUB.
- Кошелёк принадлежит пользователю; данные изолированы между пользователями.
- У кошелька одна или несколько валют из глобального справочника; кошелёк с одной валютой допустим.
- Иконка — имя Lucide из iconpack.
- Удаление физическое; защита связанных данных внешними ключами.

## Объём
- Таблицы кошельков и связи кошелька с валютами, миграция.
- CRUD кошельков, привязка и изменение набора валют, иконка.
- Изоляция по владельцу на уровне репозитория и сервиса.
- Unit- и smoke-тесты, тест изоляции пользователей.

## Вне рамок
Операции и балансы (010).

## Открытые вопросы
Решено: таблицы операций (010) ещё нет, поэтому удаление кошелька — физическое и безусловное, `PUT` делает полную
замену набора валют без ограничений; оба вопроса про историю операций — задел на будущее для 010 (зафиксирован в
design.md изменения `wallets`). Ручной порядок отображения (sort/reorder) вне «Объёма» — список сортируется
детерминированно (`created_at ASC, id ASC`).

## Критерии готовности
- Пользователь видит и меняет только свои кошельки.
- Кошелёк с одной и с несколькими валютами создаётся и редактируется.
- QualityGate проходит.

## Статус
Выполнено (изменение `wallets`, архив `2026-09-29-wallets`). Две таблицы (`wallets`, `wallet_currencies`, миграция
`20260929_0004`) с `ON DELETE CASCADE`/`RESTRICT`; `WalletRepository` фильтрует по `wallet_id` И `user_id` в одном
запросе — чужой кошелёк везде даёт 404, не 403. `GET/POST/PUT/DELETE /api/wallets*` реализованы под
`get_current_user`; валидация иконки через `IconName` (007, первое реальное подключение) и валют через новый метод
`CurrencyRepository.missing_ids`. `PUT` — только полная замена (без `PATCH`). Проверено полным QualityGate,
включая `make test-infra` (изоляция пользователей, cascade delete, RESTRICT — все на реальной БД).
