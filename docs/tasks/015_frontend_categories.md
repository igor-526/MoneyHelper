# 015. Категории (frontend, этап F2c)

Зависит от: 013, 009. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь видит список своих категорий доходов и расходов, фильтрует по типу и может создать, отредактировать
и удалить категорию.

## Контекст и решения
- Список — карточки/список, не таблица (mobile-first).
- Категории делятся на доходы и расходы (`type`) — фильтр по типу на экране списка, тип виден в карточке.
- Название уникально в пределах пары «пользователь + тип» (backend отдаёт 409 при дубле) — понятное сообщение при
  создании/переименовании в занятое название.
- Удаление, заблокированное операциями (409), — как и у кошельков (014), понятное сообщение.
- Навигация — без отдельного пункта нижней панели (бюджет 5 пунктов занят «Главная»/«Кошельки»/«Операции»/
  «Аналитика»/«Настройки», решение 013): маршрут `/categories`, вход — ссылка со страницы «Настройки».

## Объём
- `routes.tsx` — маршрут `/categories` под `RequireAuth`; ссылка на него со страницы «Настройки».
- Список категорий с фильтром «доход / расход / все», пустое состояние с CTA при отсутствии категорий.
- Форма создания/редактирования: тип, название, `IconPicker` (013).
- Удаление с подтверждением; обработка 409 (дубль названия при создании/переименовании, категория с операциями
  при удалении) понятными сообщениями.
- Обработка стандартных ошибок API.
- Тесты компонентов и hooks.

## Вне рамок
Иерархия категорий (backend её не поддерживает — плоский список); набор категорий по умолчанию для нового
пользователя (backend не сидирует, вне рамок и здесь).

## Открытые вопросы
Решено: тип в карточке — `antd Tag` с семантическим цветом (`success`/«Доход», `error`/«Расход», именованные
пресеты темы, не хардкод); сортировка — как отдаёт backend (`created_at ASC, id ASC`), без клиентского выбора.

## Критерии готовности
- Категории доходов и расходов создаются, редактируются, удаляются и фильтруются по типу.
- Ошибки (409 на дубль названия и на удаление с операциями) обрабатываются понятно.
- QualityGate проходит.

## Статус
Выполнено (изменение `frontend-categories`, архив `2026-09-29-frontend-categories`). Повторяет архитектуру 014
(список-карточки, единая форма create/update в `Drawer`/`Modal`, `Popconfirm` на удаление, hooks с инвалидацией
кэша) с двумя отличиями: 409 на дубль названия в пределах типа обрабатывается **на уровне поля формы** (`form
.setFields` на `name`, по образцу `RegisterPage`, без toast) — не так, как 409 при удалении с операциями (тот
покрывается общим обработчиком без спецкода, как и у кошельков); навигация — без пункта нижней панели (бюджет
занят), точка входа — ссылка-кнопка со страницы «Настройки» (второй блок, после «Тема оформления»). Фильтр по
типу — `Segmented`, всегда видимый, включая пустой отфильтрованный список. Проверено полным QualityGate; backend
и `navItems.ts` не затронуты.
