# 009. Категории (этап 4)

Зависит от: 005, 007. Дорожная карта: [002_roadmap.md](002_roadmap.md). Правила: [AGENTS.md](../../AGENTS.md).

## Цель
Пользователь ведёт категории доходов и расходов с иконками.

## Контекст и решения
- Категории делятся на доходы и расходы; список плоский, без вложенности.
- Категория принадлежит пользователю; иконка — имя Lucide.
- Удаление физическое; защита связанных данных внешними ключами.

## Объём
- Таблица категорий (тип income/expense, название, иконка), миграция.
- CRUD категорий с фильтром по типу.
- Изоляция по владельцу.
- Unit- и smoke-тесты.

## Вне рамок
Иерархия категорий; операции (010).

## Открытые вопросы
Решено: уникальность названия в пределах типа обеспечивается составным `UniqueConstraint(user_id, type, name)` на
уровне БД (409 при конфликте); запрет/каскад при удалении категории с операциями не реализуется — таблицы операций
(010) ещё нет, удаление физическое и безусловное, задел на будущее для 010 зафиксирован в design.md изменения
`categories`; набор категорий по умолчанию для нового пользователя не реализуется — вне рамок задачи 009,
пользователь создаёт категории сам через CRUD.

## Критерии готовности
- Категории доходов и расходов создаются и фильтруются; чужие категории недоступны.
- QualityGate проходит.

## Статус
Выполнено (изменение `categories`, архив `2026-09-29-categories`). Таблица `categories` (миграция `20260929_0005`)
с `ON DELETE CASCADE` у `user_id` и составным `UniqueConstraint(user_id, type, name)`; `CategoryRepository`
фильтрует по `category_id` И `user_id` в одном запросе — чужая категория везде даёт 404, не 403.
`GET/POST/PUT/DELETE /api/categories*` реализованы под `get_current_user`; тип — первый в проекте закрытый
`StrEnum` (`CategoryType`), защищён `CheckConstraint` в БД; иконка проверяется `IconName` (007). `PUT` — только
полная замена (без `PATCH`); дубль названия в пределах типа даёт 409 (перехват `IntegrityError`, без
предварительного `SELECT`, по образцу `UserRepository`). Проверено полным QualityGate, включая `make test-infra`
(уникальность, `CheckConstraint`, cascade delete, изоляция пользователей — все на реальной БД).
